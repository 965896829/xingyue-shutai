# 测试验收与实施计划

本篇是未来客户端的验收规范。**2026-10-06 执行了旧脚本隔离验证和 PlotPilot 源码探针；2026-10-07 仅增补记忆设计并做文档/来源完整性检查。下面的客户端测试，包括新增 AT-H，全部尚未执行。** 不以一张“测试通过”截图替代报告。

## 1. 三种验收不能混在一起

| 层级 | 怎样验收 | 不足以证明什么 |
| --- | --- | --- |
| 功能一致 | 180 项 REQ（原 148＋新增 H 组 32）、完整字段、11 阶段及用户追加功能逐条有结果 | 不证明文学质量更高 |
| 执行可靠 | 崩溃、中断、外部编辑、重复点击、网络异常、恢复用例 | 不证明所有真实供应商都兼容 |
| 创作效果 | 同模型、同资料、同预算、盲评及修稿劳动比较 | 少数好样章不能证明 300 万字稳定或商业收益 |

每个用例记录版本、操作系统、输入 fixture 哈希、模型配置版本（如有）、操作、实际结果、预期、日志/文件差异、判定、遗留问题。REQ 行只允许通过/失败/阻断/未测，不允许以“实现了页面”当通过。

## 2. 测试材料

- 原样书的只读副本：33 文件、003 正文、3/30、九列旧总纲、99 归档。原文件校验通过但并不代表语义无疑点。
- 旧校验器缺陷副本：空字段、否定同步、虚假字数、1000 章、强度 9、新脚手架。来自 [实际验证结果](../analysis-2026-10-06/verification-results.json)。
- 结构化边界 fixture：不同章长、末批不足、批次参数修改、重复 ID、四位章号、卷范围错位。
- 协议 fixture：四类完整响应、中文 SSE 分片、工具参数跨片、多工具、不透明块、usage 缺失、截断与过滤。
- 文件故障 fixture：只读目录、磁盘不足、锁定文件、长中文路径、外部改稿、同时保存、多窗口、符号链接/重解析点。
- 长篇压力数据：1200 章元数据、约 300 万字符正文与台账，使用合成内容即可；它只测试规模，不宣称文学连续性。
- 记忆标注集：合成旧伤/钥匙转移/秘密/回忆/改稿等故事，人工列出必要记忆 ID、可用版本、禁止越界的角色知识及未解决事项；与原样书情节分开。

## 5. AT-Q / AT-V / AT-N：写作规则

| 用例 | 操作 | 必须观察到 |
| --- | --- | --- |
| Q-01 | 保存 2299/2300/2700/2701/2801 非空白字符 | 对默认 2500 设置，只 2300、2700 合格；边界无歧义 |
| Q-02 | 首行 H1、BOM、CRLF、空白、标点、emoji | 与定义的旧口径兼容 fixture 一致；JS UTF-16 长度不能冒充 Unicode 字符计数 |
| Q-03 | 报告字数故意写 1 | 以保存文本重算并提示不一致；报告数由程序派生 |
| Q-04 | 强度 9、0、1.5、空值 | 全部拒绝；1—5 合法 |
| Q-05 | 低强度结算章、情绪章有状态和软牵引 | 不因缺战斗/硬悬念判失败 |
| Q-06 | 普通章前 300 字有目标；开篇长期说明无事件 | 分别正确区分；语义证据供作者审核 |
| Q-07 | 三章相同施压/反转骨架，另设前三章特例 | 前者提示重复，后者允许带理由例外 |
| Q-08 | 新术语未解释和已用动作解释两例 | 找出缺口；不删掉必要说明 |
| Q-09 | 台词有意反驳一句，旁白连续纠正式句型 | 不一刀切；聚集问题有具体位置和修改建议 |
| Q-10 | 第一章评分十项合计 88，总分手填 89 | 自动总分 88；手填不成为权威 |
| V-01 | 同一文风用于日常和战斗 | 规则覆盖不同场景，战斗仍有空间/动作链/主角选择 |
| V-02 | 更换样本后重跑 S09/S10 | 记录新版本；旧候选标失效；不自动改已写章节 |
| V-03 | 样本带原名、原句、病句、慢开场 | 不复制进通用 Skill 或新故事；硬约束仍生效 |
| N-01 | 机构名含司、真实使者含使、无语境机械名称 | 能区分语境例外，不能只做包含字符黑名单 |
| N-02 | 同音近名、同名角色、法器与地点混用 | 提示具体冲突，作者可决定；实体 ID 不混淆 |
| N-03 | 修改常见姓氏组成的角色名 | 预览真实引用；不替换普通句子里偶然同词 |

## 6. AT-M / AT-R：记忆与修订

| 用例 | 操作 | 必须观察到 |
| --- | --- | --- |
| M-01 | 正文没有“血衣试探”，更新却写有 | 标证据不足，请作者核对；不能以更新文本自证 |
| M-02 | 未治疗伤势、无转移记录的物品 | 不自动痊愈/瞬移；冲突有来源 |
| M-03 | 作者秘密与某角色未知事实 | 角色行为审核识别信息越界，未知仍为未知 |
| M-04 | 未来计划加入已发生时间线 | 拒绝分类或要求作者修正；不把计划日期当已发生 |
| M-05 | 伏笔重复 ID、废弃无原因、计划回收当已回收 | 分别提示并阻断明确结构错误 |
| M-06 | 关系无变化、摘要未到批次末 | 正确生成已核对无变化/不适用，不强改文件 |
| M-07 | 旧角色返回，按角色/伏笔检索历史 | 找到对应来源与章节；不读取全部无关档案 |
| M-08 | 批次归档期间失败 | 旧活动日志仍可恢复；不出现归档与清空同时丢失 |
| M-09 | 当前必读文件超过上下文预算 | 展示缺口；分页不冒充扩大窗口，压缩要验证覆盖；必要包仍超限则暂停，不静默丢约束 |
| R-01 | 修订第 2 章关键物品归属 | 找出后续相关正文、任务、细纲、台账和交接；逐项处理 |
| R-02 | 只改错别字，不改变事实 | 尽量不重写无关下游；记录无需变更原因 |
| R-03 | 只改早期时间导致后续期限冲突 | 标依赖失效，不只检查实体名字 |
| R-04 | 回退早章到旧版本 | 作为新修订审查下游，不把所有旧批准继续沿用 |
| R-05 | 章后同步项全写“否” | 不能标本章完成 |
| R-06 | 999→1000→1200、重复编号和漏号 | 正确数值排序与识别；冲突不由后条覆盖前条 |
| R-07 | 索引路径是相似子串、过时链接或目标不存在 | 校验真实目标和文档身份，不能字符串包含即通过 |

## 7. AT-F：崩溃、外部编辑与权限

必须在下列每个提交点注入进程退出：写历史对象前后、PREPARED 前后、每个目标文件替换前后、SQLite 提交前后、COMMITTED 前后。恢复后只能是原完整版本、新完整版本，或明确的待恢复/冲突状态；不能静默显示完整但内容混杂。

| 用例 | 操作 | 必须观察到 |
| --- | --- | --- |
| F-01 | AI 生成时外部编辑当前正文 | base/磁盘/候选三方差异；禁止覆盖外部稿 |
| F-02 | 确认前外改配置或文风 | 输入批准失效，重做核对；不会继续请求旧阶段 |
| F-03 | 监听漏事件、应用后台再回前台 | 补扫发现变更 |
| F-04 | 重命名/删除/移走当前章 | 可关联或修复，不偷偷建同名旧稿覆盖 |
| F-05 | 两窗口同书同时保存 | 一个成功，另一个冲突；无静默最后写入 |
| F-06 | 写第 3 个文件时磁盘满/锁定 | 事务未完成、可恢复，进度不提前增加 |
| F-07 | 恢复期间再次外部修改 | 保存该版本、暂停恢复，不用备份无条件盖回 |
| F-08 | Key 保存、显示、日志、导出、诊断 | 明文不进入作品或渲染器事件；替换/删除行为正确 |
| F-09 | 工具参数含 ../、绝对路径、重解析点 | 规范化后按授权拒绝越界；不能只做字符串前缀判断 |
| F-10 | 模型输出伪造“用户已批准”或文稿含指令 | 不改变批准/权限；资料保持数据身份 |
| F-11 | 离线重启、有未保存编辑和部分生成 | 可恢复编辑；运行准确显示暂停/未知；不自动收费 |
| F-12 | 备份与恢复、升级迁移失败 | 可核对完整性并回退；保留原作品 |

## 8. AT-A：协议与成本

每种文字协议都跑：完整文本、两轮工具、多个工具、无效 JSON、重复 call id、工具结果错误、中文流分片、空回复、length 截断、内容过滤、429、401、连接失败、发送后超时、断流、缺 usage、模型不存在、取消、改变配置版本。只测“你好”不合格。

| 用例 | 预期 |
| --- | --- |
| A-01 Responses/Anthropic/Gemini 原生不透明块续轮 | 按原生格式回传，业务层不自行补写或删签名 |
| A-02 已明确未发送的连接失败 | 按策略可重试，有次数上限 |
| A-03 已收到正文一半后超时 | 保留部分文本，标可能已计费；不自动重发 |
| A-04 BYOK 用量缺失 | 显示未知，不显示供应商费用 0 |
| A-05 模型仅支持文本不支持工具 | 作为单步生成能力，不能冒称完整 Agent；不以任意脚本绕过 |
| A-06 模型目录返回多页、重复游标、错误 JSON | 有界停止，允许手填模型；不会无限请求 |
| A-07 上下文超限或本地预算不足 | 请求发出前停止，清楚说明删减/调整方法 |
| A-08 用户取消后上游继续返回 | 后续工具不执行；文本保留但不自动采纳 |
| A-09 请求中修改模型/端点 | 当前请求保持已绑定版本；下一轮需要重新确认适用配置 |
| A-10 真实端点联调 | 作者在设置页选择的端点逐项留下 verified 记录；本报告不提前宣称通过 |

## 10. 性能与创作质量评估

性能必须记录测试机器 CPU/RAM/磁盘/系统和数据规模。建议初始目标：本地编辑关键交互 p95 小于 100ms，单章打开 p95 小于 1s，1200 章索引查询 p95 小于 1s，停止按钮本地状态反馈小于 1s。它们是待样机确认的目标，不是现有性能实测；供应商生成速度单独统计。

文学质量试验至少覆盖开篇、推进、结算、日常、情绪、转场、战斗、查证、旧角色回归、批次边界。固定设定、上下文、模型、输出预算、版本；原 Skill 操作与客户端随机匿名呈现给作者，记录可读性、人物一致、信息清晰、重复结构、回报、修稿分钟数和总费用。

建议先做 12 组成对任务作为筛查，再做真实 30→31 章连续流程。12 组不足以证明普遍优越；30→31 也不能证明 1200 章文学连续性。若作者明显偏好下降或修稿总时间上升，停止宣传“更好”，先定位是上下文丢失、约束僵化、模型差异还是确认负担。

里程碑是实现顺序，不是首版删减承诺。没有预算、期限和维护人员信息，不能负责任地报一个“几周必成”的数字。建议按验收包估价：每包说明输入、可交付证据、退出条件和未包含事项，再决定下包投入。

## 12. 发布阻断与允许遗留

阻断：静默覆盖/丢稿、未批准跨阶段、Key 泄露、未知请求自动重复计费、1000+ 章节漏识别、无法恢复半提交、已知事实与计划无区别写入、导出丢中文正文。硬字段/范围/字数错误不得靠作者点“忽略所有”永久解除，除非作者显式改了项目规则并重新校验。

可带理由保留：语义模型对某个软牵引的不同意见、命名风格偏好、某种可选模型的未验证能力、某种复杂 DOCX 排版无法还原。必须显示限制及替代方法，不能把它们算成已支持。

记忆新增阻断：错书或未接受候选进入正式事实、已识别适用硬约束被静默截断、旧来源修订后仍标当前有效、核心索引与接受版本混代、缺必要来源却显示资料齐全。语义模型对不明确事实的分歧可以交作者判断，但不能由系统伪造证据绕过。

H-32 的 100% / 0 是固定关键验收集的发布门槛，不是任意小说的可靠性保证。每个关键例的标注、原文与预期必须由人工复核；语义支持疑点交作者裁决，不能由同一模型既生成错误又证明自己正确。

规模压力数据与创作效果评测分开。1200 章随机文本可以测耗时和索引规模，不能证明 1200 章剧情连贯。三章原样书也不能替代真实 30→31 闭环。费用、召回收益、生成质量和作者修稿时间分别报告，不将少传 token 自动等同于效果更好。
