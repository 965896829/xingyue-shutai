# 产品需求文档（PRD）

2026-10-08 已批准并实现的增补：独立对话内核、任务卡、角色模块、Tavily 搜索及草稿隔离，详见 [18：智能体对话与执行分离](18_智能体对话与执行分离.md)。原正式阶段的 Skill 装配与确认流程保持兼容。

状态：0.10 需求基线（2026-10-07 增补记忆设计，随后获用户整体实施授权）。功能追溯以第 04 篇为准，字段以第 05 篇为准，记忆细则见第 12 篇。文序 0.1.0 的实现与未验收范围见[第 13 篇](13_实施记录与验收状态.md)及[第 15 篇](15_逐项实施与验收状态.md)，不以本需求文档代替验收结果。

## 1. 产品定义与成功标准

为个人作者提供一个 Windows 桌面写作工作台：作者通过聊天布置任务，系统按 Skill 管理规划、正文、人物与连续性资料；生成前授权，生成后查看结果与文件差异；确认后形成正式版本；发现外部编辑、中断或旧事实变化时，能够继续、修复或回退。

首版最终验收必须覆盖原 Skill 全部功能。开发可分里程碑，但不能把“里程碑 1 完成”包装成“全部 Skill 已完成”。用户追加能力：按书调整参数、终端/脚本/依赖安装、封面生成与可编辑叠字、TXT/DOCX 导入导出、本地历史版本与指定目录备份。用户明确不需要平台直发、首版云同步；配音、视频没有纳入当前文字写作范围。

成功标准分三层：功能覆盖必须逐项通过；可靠性必须通过中断、外部编辑与恢复测试；文学效果由作者在同条件比较中评估。第三层不能用前两层的通过来替代。

## 2. 使用对象和业务边界

作者拥有本机作品、自己的 API Key，可以离线阅读、编辑、检查和导出。AI 生成和外部检索需要对应网络服务。首版不以登录你的网站为前提，不需要安装开发环境才能写书。可有多个作品，各自拥有配置、工作流版本、聊天与事实记录。

免费安装包不等于所有功能已经承诺永久免费。收费模块、许可证、联网激活是否存在尚未确定；不得先行开发自动扣费、余额或强制账号。作品的可读文件不因授权状态变化而被加密锁死，此为保护作者数据的设计建议。

## 3. 核心业务对象

| 对象 | 作者看到的含义 | 关键规则 |
| --- | --- | --- |
| 作品 | 一部小说及其创作档案 | 独立 ID；目录重命名不改变身份 |
| 阶段 | 设定、配置、世界、人物、规划、正文、更新等任务 | 开始前明确目标、输入和将改的文件 |
| 章节 | 正文及对应任务、细纲、更新 | 数字 ID 支持 1000 以上；有草稿、已接受、已同步状态 |
| 批次 | 默认连续 30 章的规划与记忆周期 | 可配置；不得把旧批次归档读成当前日志 |
| 候选 | AI 或外部变更提出、尚未接受的内容 | 不覆盖正式事实；可比较、修改、放弃 |
| 正式版本 | 作者已接受的文件版本 | 后续读取必须引用该版本或明确待确认变化 |
| 事实 | 从正文、作者要求或规划中提取的记录 | 已发生与计划分开；保留来源章节/版本 |
| 运行 | 一次授权后执行的过程 | 保存调用、工具、费用、暂停点和失败原因 |
| 批准 | 作者对指定输入和结果的决定 | 内容或输入变化后不能继续沿用旧批准 |

## 4. 工作台的信息组织

采用类似 Codex 的任务工作方式，但界面用小说语言解释状态，不要求作者理解 JSON、数据库或 token 才能写书。

| 区域 | 必需内容 | 关键交互 |
| --- | --- | --- |
| 左侧作品与任务 | 作品列表、阶段树、批次、章节、搜索、最近任务 | 切换作品明确隔离；显示待确认/需修复标记 |
| 中央聊天与执行 | 作者指令、澄清、阶段计划、实际工具步骤、当前状态 | 停止、补充要求、重试、查看读取资料；不伪造思考过程 |
| 右侧编辑与差异 | Markdown 编辑/预览、候选与正式比较、文件标签页 | 按文件或段落查看变更；手工修改后重新校验 |
| 结果确认区 | 产物清单、问题、费用、下一阶段名称 | “确认结果并开始下一阶段”“只确认并暂停”“继续修改”“放弃候选” |
| 资料与连续性面板 | 人物、关系、时间、伏笔、物品/伤势、术语、知情；本次召回资料及未解决事项 | 每条可跳到原文件及证据；显示为何使用、是否过期、具体缺口；冲突不能只有红点 |
| 运行与设置 | 模型、预算、权限、备份、版本、诊断 | 展示真实状态；不默认展开开发术语 |
| 封面模块 | 书名、简介、风格需求、尺寸、生成候选、下载位置 | 与正文状态独立；费用和采用按钮独立 |
| 终端面板 | 命令、目录、输出、退出码、取消与副作用说明 | 作者能看见正在运行的实际命令 |

只显示真实发生的“已读取 4 个文件、正在校验第 3 章”等事件。模型没有返回内部推理，不妨碍展示执行步骤；不要把随机进度百分比包装成可观测状态。

## 5. 新建、打开与导入

新建输入：作品名或临时名、保存目录、原始设定、题材/读者、已有硬约束。正文默认总字数 300 万、目标单章 2500、范围 2300—2700、批次 30；用户已确认可按书调整。改成其他章长时，作者同时填写可接受上下限；不自动猜测浮动范围。预计章数向上取整。参数值和默认来源明确记录，禁止修改一项后让其他文件悄悄失配。

同名目录存在时给出“打开已有作品、以新名字创建、选择其他位置”。不得合并两部书。创建骨架不会将第 1 章标为已完成。文风规则文件始终创建，未提供样本时标未启用。

导入当前 Skill 档案：扫描文件→只读预览→识别工作流版本、章节、计划与正文→列出缺字段、冲突、旧归档和重复身份→用户确认补充管理信息→建立索引。先保留源字节及快照；不通过重新格式化所有文件实现导入。部分格式无法解析仍可编辑原文件，依赖该内容的自动阶段暂停并指出位置。

导入样书时应识别 003 和 3/30，不把旧任务归档计作活跃任务；九列表格不会被强行解释成完整十三列。角色的未来计划不会记作已发生。

## 6. 阶段流程与门槛

每阶段固定提供：本次目标、当前输入版本、所用模型、将产生或修改的文件、未解决问题、预计费用口径、开始按钮。授权只覆盖展示的阶段与范围。阶段内允许必要读取、工具和修复；新一章正文仍要再次确认。

| 阶段 | 前置输入 | 产物与内容 | 结果接受前检查 |
| --- | --- | --- | --- |
| S01 设定拆解 | 作者原始设定与硬约束 | 题材、卖点、神级点、困境、不公平规则、破局、反差、首章事件、长线动力、升级路线、风险修正 | 抽象概念有读者可懂表达；重大未知向作者提问 |
| S02 项目配置与文风 | S01 接受、作者参数 | 项目配置；未启用或启用的文风规则 | 参数合法、硬约束明确、样本来源和启用状态可见 |
| S03 世界规则与卖点 | 配置与设定 | 底层规则、金手指、限制、代价、信息差、反制、升级、防重复 | 每条能用于具体冲突；不能只堆术语 |
| S04 人物及连续性初始化 | 世界与主线方向 | 角色卡、关系、活动行为、摘要、历史目录和五台账 | 空台账合法但不冒充已发生；新名字检查；关键角色角色功能齐备 |
| S05 分卷大纲 | 已接受设定/配置/世界/人物 | 预计总章数、容量表、主线、阶段目标、反派/成长路线、卷开局高潮钩子 | 容量连续且算术一致；卷与批次关系可见 |
| S06 章节总纲 | 分卷与当前正式事实 | 当前批次逐章路线，首次至少覆盖首批 | 章节顺序权威；类型、强度、承接、状态、回报、揭示、牵引齐备 |
| S07 批次节奏 | 当前范围总纲 | 3—5 章波段、压力/推进/释放/余波、信息与回报 | 连续覆盖；与总纲冲突必须先解决；允许有记录的结构例外 |
| S08 批量细纲 | 总纲与节奏已接受 | 当前批全部章节细纲、揭示总量和禁止项 | 不能先写第 1 章再补其余；范围无漏号/重复，类型强度与总纲对应 |
| S09 单章设计 | 当前批规划、已接受前文、必读资料 | 本章任务清单与场景细纲 | 所有必需字段有效；上章承接、知情、伤势、物品、文风和禁揭示明确 |
| S10 正文 | 本章设计已接受；正文专门授权 | 正文章节候选、保存回读计数、质量报告 | 长度、硬约束、关键连续性、句式扫描与信息落地；作者可编辑和拒绝 |
| S11 章后更新 | 已接受正文版本 | 章后报告、变化角色/关系/行为、受影响五台账、索引与进度；边界时摘要/归档 | 每项更新有依据或无变化原因；正式正文与记忆同步后才可启动下一章 |

S09 将任务和单章细纲合并为一个对作者的阶段，这是 workflow 的定义；内部依次生成，不能直接跳到正文。S04 多文件可作为一个可审阅结果包，不需要每张卡片弹一次确认。

## 7. 一章完整的作者操作

1. 作者说“续写第 4 章”。系统确认正式最新章、活动批次、未闭环修订、外部变更；缺资料先解释阻断位置。
2. 展示 S09 计划，列出必读文件与拟使用模型。作者同意后读取并生成任务和场景细纲。
3. 展示本章目标、场景、承接和揭示预算及两文件差异。按钮明确写“确认设计并生成第 4 章正文”。
4. 接受设计与正文授权作为一个原子业务决定记录。正文生成中可停止；停止留下部分候选，不增加已完成章数。
5. 展示完整正文、真实字数、质量问题。按钮为“确认正文并开始章后更新”。若作者修改正文，旧校验与批准失效，重新检查。
6. S11 只依据已接受正文生成记忆候选。正文已经保存，但状态显示“待完成章后同步”，不是“本章完成”。
7. 作者审阅事实差异后，可点“确认更新并开始第 5 章设计”或“只确认并暂停”。提交整个更新包成功后，本章才计为完整完成。

如果当前结果被拒绝，不消耗下一阶段授权；如果结果已接受但下一阶段启动失败，接受决定保留，恢复时不得重新接受或重复提交文件。

## 8. 批次边界

默认第 30 章的 S11 包含：结束批次的事实合并、活跃角色摘要、详细行为归档、下一批必要承接。下一批顺序固定为扩展总纲→匹配节奏→完整批量细纲→单章设计→正文。依据实际接受的正文、未回收伏笔及偏离旧计划的记录。

历史行为不按每章全量重读。老角色回归、旧线索和事实冲突时，能按角色、编号和章节回查。默认 30，用户允许调整。已确认：全书末批不足时按实际范围，例如 40 章最后一批为 31—40；写到第 15 章改为每批 20，原 1—30 不变，下一批为 31—50。

## 9. 文风、命名和章节质量

文风：提炼叙述距离、句式、词感、镜头、人物、对话、解释、情绪、爽点和章末方式；覆盖日常对话、修炼、战斗、审判、查证、关系、群像、转场。样本只提供表达约束；原人物名、剧情与句子不成为新书素材，病句和矛盾不能照搬。启用/停用/更换样本须显示对未写及已写章节的影响，已写正文不自动重写。

命名：对象包含人物、势力、机构、职位、功法、法器、地点。先题材，再阵营语系，再字面和读音，最后去重。人名通常易读的二三字，但不是强制所有题材同一种风格。机构“司/使”是避免机械默认，保留阴司、历史官制和真实使者等语境例外。改名以实体与引用范围作差异，不用全文字符串替换误伤普通词语。

章节：六类主功能可组合，自定义细分标签可保留；强度 1—5；至少一个状态变化和一个阅读回报。开书/开卷/指定高潮前 300 字进入强事件，其余章节前 300 字进入有效叙事。结算、日常、情绪、转场不被强制改成打脸。硬悬念和软牵引都合法。

检查要区分：词语命中≠错误，模型意见≠事实，分数≠客观质量。纠正式句型与“此言一出”等套话显示命中位置、上下文与重复聚集；允许有意对话例外；建议改动作和叙事结构，不是机械替换同义词。新术语必须解释基本含义与即时后果，不能把合理解释全部判成“AI 总结”。

评分十项各 0—10，程序求和；信息落地、句式扫描、字数合规等另列结果。证据不足必须显示“不确定”，不能默认通过。只有作者接受后才形成审美判断上的通过；硬错误按第 08 篇规则阻断。

## 10. 三层记忆、按需召回与修订

三层是同一套作品资料的不同使用范围，不是三份互相复制的事实库。详细契约见[分层记忆与按需召回](12_分层记忆与按需召回设计.md)，追溯 REQ-H01—H32。

| 层 | 作者得到的能力 | 必须满足 |
| --- | --- | --- |
| 瞬时记忆 | 记住本次任务目标、当前步骤、已读资料、工具结果、候选和待解决问题 | 检查点落盘；关闭重开核对来源再恢复；不重复未知收费请求或已完成写入 |
| 短期记忆 | 围绕当前章/场景、上章正文、近期变化和活动批次组织资料 | 不改变原 Skill 当前资料必读要求；窗口滚动不删除未解决事项 |
| 长期记忆 | 保留已接受设定、正文、事实、历史、摘要与原文证据 | 每章更新确认后保存；按实体、事件、伏笔、时间和关联关系取回，能查证来源 |

按需召回先取得当前适用的硬约束与必读资料，再补查历史；不能只挑语义相似度最高的几条。甲第 12 章受伤、第 120 章再次出场，若没有接受过恢复依据，其有效伤势仍必须进入第 120 章资料。未知、未找到、确认没有、冲突和过期应显示成不同状态。

本次资料清单展示来源版本、召回原因、实际装入范围和重要缺口。自动扫描不等于模型读取全文。必需信息超出模型容量时暂停并说明处理选择，不能静默截断后生成；原 Skill 当前必读文件改用压缩投影须先验收覆盖。近期摘要窗口和检索探索范围可调，但不能关闭必要约束核对。

人物当前状态只改实际变化者；关系极性与信任度有固定类型。情绪变化有原因和行为证据。五台账分别处理发生时间、伏笔状态、物品/伤势、术语、角色所知。模型生成的“推测”不能进入已发生时间线，作者掌握的秘密不能直接成为角色知识。

计划、作者设定、已发生事件、角色误解和模型推断分别保存；作者接受一条误解不意味着误解变成世界真相。回忆情节的发生时间、读者首次看到的章节和文件修改时间必须区分。后期揭示不能倒灌进早期角色知识。

S11 提取的是候选记忆。作者在现有章后确认区审阅整个更新包，接受后才同步正式台账、短期视图、索引和进度；不增加逐条事实弹窗。批次末归档与摘要保留原文和未解决事项，摘要不能为自身提供事实依据。

修订入口支持“更爽、节奏太慢、人物崩了、压到 2500 字”、局部选区修改、改名、变更设定和外部编辑。先生成影响范围：旧事实、新事实、起点、被引用章节和文件、无需修改及理由。作者授权后修改候选并逐项审核；不是无差别重写后续所有章节。

正式正文改变后，旧记忆与下游规划标为可能失效；只有重新核对过的对象才能去除标记。没有受影响的文件应保持字节不变。回退早章也算一次事实变更，必须重查下游，不能只替换那个 Markdown。

该失效规则同时覆盖摘要、检索片段、可选向量、短期缓存和待执行任务。索引重建只恢复可派生数据，不绕过作者确认改写故事，也不能伪造批准历史。记忆增强不默认上传作品到额外服务；首个基线不要求配置向量模型。

## 11. 外部编辑与文件控制

文件监听及时提示新增、修改、重命名、删除；应用回到前台和运行前再次扫描核对，避免漏事件。界面区分应用自身写入和外部修改。

编辑冲突以三个版本展示：任务开始时、当前磁盘、AI 候选。禁止无提示“最后写入者覆盖”。普通正文外改可保留为待审核新版本；系统不能偷偷改回去。关键配置外改立即使相关待批准任务失效。删除/移动文件需重新关联，不能按同名文件误认身份。

备份覆盖作品与运行所需元数据；用户已确认自动保存本地历史版本，并能备份到自己指定的目录，首版不做云同步。恢复先预览并保存当前状态，不能回退覆盖作者后来外部修订。SQLite 索引丢失可从作品重建，但历史批准、运行和恢复记录不是都能从正文推断，备份须包含这部分。

## 12. API、费用、中断与续跑

作者可配置多个端点、协议、真实模型 ID、显示名和能力。获取模型目录只是连通性检查；文本、流式、工具参数、工具结果续轮、用量和取消分别记录测试结果。默认不通过收费生成来伪装“免费连接测试”；完整能力测试显示将发生的小额调用后再开始。

每阶段可选模型，默认沿用作品配置。运行中改模型只影响后续明确的新请求，不能把某厂商的原生签名块直接送另一厂商。缺 Key、无模型、上下文不足、预算不足、限流、网络断开、内容过滤、工具参数无效、响应截断分别给出可执行处理。

费用展示真实上游用量或“未知/估算”，BYOK 只代表本客户端不收平台模型费用，不代表供应商免费。取消尽快停止本地执行和后续工具，已发送请求可能继续计费。重启续跑从持久化检查点重新核对输入，不能把一半正文当完成或对未知请求无条件自动重发。

## 13. 终端、脚本与依赖能力（用户追加）

提供终端命令、脚本执行、受控联网及依赖安装能力。它们不是原 Skill 的必需写作动作，也不能用“支持终端”替代结构化写作工具。

执行前能看见目录、命令、参数、涉及路径、联网目的、是否安装软件及可否撤销；运行时输出流、退出码与停止按钮；进程退出后实际验证文件变化。用户已确认：项目内普通读写随阶段授权，安装、项目外访问、大量删除及不明脚本先展示具体动作再确认，策略可在设置中调整。

运行记录必须区分“请求停止、进程已终止、子进程仍在、状态未知”。文件快照无法撤销系统环境修改、远程写入和第三方安装副作用，不得把它们显示成已完整回滚。下载脚本和作品中的文字均不能自行提升权限。依赖优先安装到项目隔离环境，全局安装不能隐含发生。

## 14. 封面模块（用户追加）

输入：书名、副标题/作者署名（可选）、题材、核心意象、人物描述、色调、比例/尺寸、禁用元素、参考图（可选）、图像模型与预算。首版具体图像服务未定，协议可独立适配。

流程：生成方案和将发送的材料→用户确认→产生封面候选→预览/再次生成/局部修改（若模型支持）→接受后保存图片和生成记录。封面文件不混入章节计数；采用封面不改变正文事实。用户已确认客户端叠加可编辑书名和作者名：可改文字、字体、字号、颜色和位置，保留无字底图、排版数据及合成图片；重新生成底图不应丢失已编辑文字。

输出包含原图、采用版本、参数与用量记录，不保存 Key。失败保留旧封面；没有确认不替换已采用图；未支持的编辑/透明底等能力不得显示为可用。首版不承诺图片适配所有平台封面规则，也不自动上传发布。

## 15. 非功能需求

| 主题 | 必须达到的行为 |
| --- | --- |
| Windows | 首版 Windows 10/11 x64（Intel/AMD）；含本机 Windows 10 build 19045；ARM 与其他系统后续再做；安装后不要求手动配置 Python/Node |
| 中文编辑 | 输入法组合输入不丢字；中文路径、书名、长文滚动和撤销可用 |

## 16. 范围不确定时的处理

产品界面不能把“未定”当成默认同意。影响小说方向的问题在阶段开始前问作者；实现细节由技术设计负责；供应商能力以实际检测为准；收费、商用授权和恢复目标等待产品决定。所有变化进入决策记录并列出受影响需求，不覆盖旧决定以制造“从来如此”的假象。
