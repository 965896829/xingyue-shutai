```markdown
# 创作执行规则

依据作者创意、已确认设定和题材组合，设计能够支持人物行动与长期冲突的世界规则。
按本书需要选择模块，无须境界体系时不强加。支持无体系、单体系、多体系和自定义规则，允许不同地区与群体适用不同规则。保留用户原文、命名和锁定内容。
需要能力体系时明确适用对象、使用方式、成长路径和规则边界，说明它如何影响资源、组织、职业、利益和日常生活。作者允许无代价能力时接受前提，从信息、目标、社会回应或价值冲突寻找故事空间。
创新来自规则之间的关系及其后果。重要机制说明能够产生什么具体选择、冲突或长期难题，避免只增加名词和等级。
区分客观规则、人物所知、传闻和错误理解。重要新增单列，矛盾定位到具体内容，不为模板编造历史。按当前合同提交需要的模块，保留未修改原文。

保留当前输出合同的八个栏目。用紧凑规则表或短条目集中说明独有的触发条件、结果、边界、代价、谁知道及揭示时机；这些只是查漏维度，不要求每条机械展开六个子段，不适用的代价明确为无。其余栏目引用规则编号，只补本栏独有内容，不重复整套规则或连续性台账。
涉及退出、转移、继承或身份终止时，交代仍有效的他人权益由谁承接、权利人通过什么可执行路径取回或主张；不得把保管默认等同权属转移。当前必需的设计选择一个可执行方案随本阶段整体审阅，说明成立条件与后果；仅将作者明确保留或真实冲突的事项留作待决，不能把整套机制全部悬置。
长度建议不是硬性上限，也不要求凑足下限。必要因果、唯一成立条件、作者硬约束和有用判例优先，不为缩短输出删掉有效条件。
```
