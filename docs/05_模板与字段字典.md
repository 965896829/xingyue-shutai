# 完整模板与字段字典

本篇保留用户提供的模板原文作为兼容基线，不把它当成已经实现的 schema。原模板来自 `templates.md`，人物字段补充来自 `memory-system.md`；新建客户端增加的字段另列。所有字段都应能在 Markdown 中查看和编辑，结构化表单只是辅助入口。

## 数据类型与必填语义

| 字段组 | 建议类型及约束 | 不允许的处理 |
| --- | --- | --- |
| 章节/批次/卷范围 | 正整数、起止闭区间；数值身份与 001 显示分开 | 固定三位解析；字符串排序；重复身份覆盖 |
| 字数/目标/容量 | 非负或正整数按字段定义；目标章长必须正；下限≤目标≤上限 | 把中文字符数、非空白字符数和 token 当同一指标 |
| 类型/强度 | 六类主类型可组合，额外子标签保留；强度整数 1—5 | 限制所有章节只能强冲突；强度 9 因两处相等而通过 |
| 关系极性/信任 | positive/neutral/negative/ambiguous；整数 0—100 | 用未知自动填 neutral 或 0 |
| 伏笔状态 | 已埋/推进中/已回收/已废弃；状态变更附原因与来源 | 把计划回收等同已回收；删除旧证据 |
| 同步结果 | 已更新/已核对无变化/不适用/待处理/失败；关联事务与目标版本 | AI 输出一个“是”就当作提交成功 |
| 评分 | 十个数值分项 0—10，程序求和 0—100；可为未评分 | 把缺失填零或默认通过；让模型自算总分 |
| 样本状态 | 未启用/已启用，来源类型与版本 | 没有样本文件就声称缺少整个项目 |
| 长文本 | UTF-8 Markdown；保留原始段落、表格、未知字段与转义 | 解析不了就删掉、吞并或重写 |
| 叙事事实 | 值+事实类别+来源版本+证据位置+有效章节范围 | 将推测、误解、作者计划归入已发生事实 |

必填不等于“任何阶段都非空”。初始化的时间线可以为空，角色的未知秘密可以明确未知；进入正文生成前的核心事件、入口、状态变化、回报等必须有可执行内容。未发生/无变化/未知/不适用要区分；不适用须有理由，不能作为批量填充绕过。

所有章节设计中的承接与预算，以已接受版本作为依赖。不同文件重复表达的字段应有主来源：配置管理字数/视角，章节总纲管理章节顺序与类型强度，正式正文管理实际发生事实；后续文档不能自行改写这些来源。

## 字段之间的自动核对

章节总纲的章号/类型/强度 → 节奏覆盖 → 批量细纲 → 单章任务/场景；差异必须形成有来源的修改，不能让模型各写一份。正式正文的实际字符数 → 质量报告和章后更新；完成事务 → 同步项与进度。模板中“已同步”是展示结果，不是模型可直接写入的事实开关。

从旧九列表格导入时，保留列与原始文字，缺少的四类语义不能自动补为确定事实。新增字段不应造成整份文件被重排。对于手工编辑到无法解析的片段，保留并提示修复，阻断相应自动生成。

## 字段实现验收

每个模板字段必须具有：显示标签、内部字段 ID、类型、阶段必填条件、合法未知/不适用值、来源优先级、编辑和保存规则、校验错误位置、导入别名。字段清单不能只实现旧 validator 的 TASK_FIELDS/UPDATE_FIELDS 子集。

自由创作的字段内容由模型和作者完成，程序只能验证结构及明确规则；人物动机、情绪因果、爽点成立、世界观可读性仍需语义审阅。系统不得因它们难以自动判定而把它们从需求中删除。

## 分层记忆增补契约（2026-10-07）

上面的原模板和 272 条原文提取记录保持不变。以下是客户端管理信息，不冒称原 Skill 已经定义。

| 对象 | 新增字段范围 | 保存与编辑原则 |
| --- | --- | --- |
| 事实与证据 | 身份、内容、性质、审核、业务状态、依据、时间、认知、替代关系、生成/接受记录 | 正式可读信息附在主要管理 Markdown 的条目附近；完整定义见第 12 篇第 5 节 |
| 摘要 | 来源版本集合、覆盖范围、事实/未解决项编号、重要遗漏、原文入口 | 作为派生导航；摘要不成为自身证据，源变更使其过期 |
| 任务资料清单 | 输入作品版本、读取/装入状态、片段与事实 ID、使用/未采用原因、覆盖、冲突、预算 | 在运行记录中持久保存；区分扫描、工具返回和实际送入模型 |
| 瞬时检查点 | 阶段、目标、步骤、工具结果引用、候选、待问项、模型与批准范围、调用状态 | 工作现场可恢复；不存伪造内部推理，不丢协议续轮必需信息 |
| 短期视图 | 作品版本、章/场景、批次、实体集合、窗口配置、来源集合 | 可重建；缓存失效不删除正式资料 |
| 检索与依赖 | projectId、接受版本、索引代次、文档/事实/摘要依赖、查询范围及完整性状态 | 精确检索和可选语义检索使用同一隔离与版本约束 |

每种事实只有一个主要管理文档；章后报告引用更新编号和版本，不另建可独立改动的事实副本。旧档案缺少新字段时保留原文，标来源待核对，依赖时核实；不得自动补为已验证。三层记忆不是在原模板之外维护三套同名角色卡。

完整设计及示例：[分层记忆与按需召回](12_分层记忆与按需召回设计.md)。字段、流程和检索的组合验收见 AT-H，而不止验证字段存在。
