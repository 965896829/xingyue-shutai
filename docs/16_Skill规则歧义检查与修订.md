## 保留、需要另行决定的创作规则

以下是明确存在的旧要求，不是正反例标错。修改它们会改变创作策略，本轮没有代替作者作决定。

1. **首批 30 章要求有“第一场公开打脸”。** 它限制故事类型；是否改成按作品选择，需要作者决定。主规则仍允许作者明确要求覆盖默认。
2. **默认脑洞爽文方向、分卷建议和金手指结构。** 它们会影响创作结果，但属于既有产品定位，不能直接视为语病或错误规则。

另记录工程边界：原 Python 校验脚本仍按固定 30 章及三位章节编号处理，原脚手架也固定初始批次。它们在原源码审计中已有记录；当前客户端的可变批次与四位章号使用 TypeScript 实现。规则澄清不能被描述为已经修好所有旧脚本，本轮不扩展到脚本重构。

## 已有作品与任务怎样生效

- 新任务在运行时重新读取安装目录的规则文件，因此本轮只同步规则即可生效，不需要退出客户端或重输 API Key。
- 旧任务记录中的提示词与已生成候选不会自动改写。规则哈希发生变化后，直接“继续修改 / 恢复”会要求重新组装。
- 要保留旧候选继续审阅，可由作者点击“重建上下文 / 用所选模型继续”，让新任务按新规则重新核对；该操作会发起新的 API 调用。该按钮沿用旧任务要求，并不会自动采用输入框中尚未提交的新要求。
- 要用全新的要求重做，可先在任务中“放弃候选”，随后填写要求并确认开始当前阶段。放弃不会删除正式文稿。
- 已接受正文和命名不因通用规则更新自动重写，需要作者另行授权修订。
