# 0.4.35：错误分类与有限恢复

本次沿用既有运行器、SQLite、模型适配器、候选审阅和事务采纳机制。保留 S01—S11，不改变作品目录，不回写旧作品。新增运行元数据均为可选字段，旧模型配置继续可读。

## 用户可见变化

| 场景 | 当前处理 |
| --- | --- |
| 评分使用星号、加号、粗体字段、英文冒号或“8 分” | 在生成候选时规范为可检查的字段；重复、越界、缺失或含糊分数仍报出具体问题 |
| 工具 JSON 外包了完整 Markdown 代码围栏或 BOM | 确定性移除包装，不修补截断 JSON，不猜测业务字段 |
| 某个候选文件不合格 | 提供待修文件与问题，只允许修改受影响内容；已通过部分保留 |
| 方向或作品方案审核不通过 | 根据已验证的 JSON Pointer 确定修复范围，其他位置保持原值；根级问题需要整份核对 |
| 六个书名中只有部分不通过 | 修复未通过项，保留通过项；手填名称仍由作者决定 |
| 正文审核要求重写 | 当前章交回正文生成器，随后重新独立审核，不允许只改审核结论放行 |
| 临时连接故障 | 在有限次数、总调用次数和费用约束内恢复，记录每次请求与等待 |
| 需要人工继续 | 开书、命名和阶段任务使用“恢复任务”入口，内部判断本地复查、局部修复或重建上下文 |

一般文风建议不再要求填写豁免理由；连续性、作者约束和其他实质风险仍需核对。

## 设置与网络边界

桌面：**模型与连接设置 → 单个模型参数与测试 → 费用、超时与连接恢复**。
网页管理端的模型编辑页复用相同设置组件。

- 默认最多恢复 **2 次**，可选择关闭或 1—3 次。
- 默认只重试确认未发送的连接失败和临时限流。401、403 等拒绝、已识别的余额不足不会自动重试。
- 502、504、断流等可能已经执行的请求默认保留现场；作者可从恢复入口确认重新请求。
- 模型设置提供“允许对结果未知的临时网络错误重新请求”选项，明确提示可能重复计费。即使开启，已有部分可见文本或无法保证费用上限时仍停止。
- 指数退避有抖动，等待可取消。服务端要求等待超过 30 秒时停止本轮自动恢复，保留记录。
- 每次物理请求单独登记，重试计入任务调用上限；未知费用不会因后续成功而变成已知费用。
- 重启只恢复持久化状态，不自动重放网络请求或结果不明的工具副作用。

网络恢复不能保证上游服务持续可用，也不会绕过真实权限、费用、版本冲突或作者确认。

## 实现入口

| 能力 | 位置 |
| --- | --- |
| 分类、旧记录兼容与恢复展示 | `src/shared/errors.ts`、`src/shared/recovery.ts`、`src/core/failures.ts` |
| 确定性格式规范 | `src/core/output-normalization.ts` |
| 文件与结构化候选的局部保护 | `src/core/runtime/candidate-repair.ts` |
| 请求恢复与持久化账本 | `src/core/runtime/network-recovery.ts`、`src/core/runtime/model-gateway.ts` |
| 显式恢复准备与统一命令 | `src/core/runtime/run-recovery.ts`、`run.recover` |
| 界面入口和设置 | `RunRecoveryButton`、`NetworkRecoverySettings` |

原 `run.resume`、`run.handoff` 等接口保留，兼容已有调用方。新恢复入口不会清零任务累计轮数、工具次数和费用；作者明确恢复后可开启新一轮有限修复。原始模型回执、候选与修复范围保存在现有运行记录和对象库中。

格式规范发生在候选校验、审核指纹和采纳之前。采纳阶段仍验证当前依据和候选指纹，不会在作者确认后偷偷修改待提交内容。

可在运行日志查看 `format-normalized`、`local-repair-scope`、`prose-repair`、`network-retry-scheduled`、`network-retry-started` 和 `recovery-requested`。
