## 修复

- 整份文档附带冗余的 `final:true` 时，按完整提交处理；不再因为这个字段要求重新生成相同全文。`final:false`、错误版本、路径和内容结构仍阻断。
- 已发送请求的网络故障恢复保留完整配对的工具调用、校验回执和已有候选；不再把此前校验意见清空。正文或工具参数已经开始返回后，不自动重发整轮。恢复次数和阶段轮数不增加。
- 对已采纳、相邻的 S01—S08，持久化前次真实请求前缀，把新阶段及变化资料追加在末尾。完全相同的作者设定和完整资料不重复发送；正文、独立审查、受限视角、资料版本变化和上下文容量不足时使用当前完整资料重建。原生工具调用与推理回执保留。
- S05—S08 的串行文档提交设置从第一次请求起保持一致，避免第一次分段保存后更改工具参数破坏缓存前缀。
- 断流诊断记录响应 ID、首个事件、最后有效事件、事件数及空闲时间，区分握手失败和已发送后的中断。计时不包含正文或凭证。

参考 [DeepSeek Harness 的 runtime-context 源码](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/src/runtime-context.ts) 的追加式上下文架构，结合本客户端的持久化记录和文档版本约束实现；没有替换创作流程。缓存命中取决于服务端，必须以返回的缓存 token 为准，不能由本地前缀相同推定命中。
