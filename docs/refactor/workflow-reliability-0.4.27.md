## 已确认问题与处理

| 问题 | 原来的实际影响 | 修复后的行为 |
| --- | --- | --- |
| 执行参数与创作内容共用正式版本号 | 将调用上限从 12 调到 30 后，原候选不能采纳 | 逐次验证快照链；仅轮数、工具次数、费用上限或备份目录改变时，原候选继续有效 |
| S02 配置候选含旧执行参数 | 采纳旧配置可能把新设置覆盖回去 | 提交时仅合并最新执行参数，保留原候选及批准指纹 |
| 开书页、书名页直接比较旧版本号 | 禁用下一步、隐藏已审核书名 | 宿主返回经过验证的兼容状态；界面、资源读取和历史分页采用同一结果 |
| 最后一轮提交齐全仍等待结束说明 | 产物已完成，界面却提示调用上限 | 普通阶段、正文审稿和章后更新在预算边界做本地收尾检查；满足条件即进入审阅 |
| 已保存的完整候选仍停在旧错误状态 | 重启或提高上限后还要手动重查 | 打开作品、保存执行参数、继续任务时检查可恢复候选，恢复审阅并记录事件 |
| 修复任务卡对整个 Run 计算指纹 | 后台用量入账、状态保存时间变化也会导致卡片失效 | 新卡只绑定候选、任务内容、真实错误、权限和待答事项等执行相关内容；旧卡保留旧指纹协议 |
| 方案交接更换基础版本，命名关联仍指向旧任务 | 换模型后方案绑定失败或已选书名不可用 | 保留原始方案输入绑定，接续同一已确认方案的命名关联；规则真正改变时重新审核 |
| 记忆同步只比较版本号 | 提高预算后丢失逐文件同步进度，或已完成的审核失效 | 保留已核对范围、进度及原审核证据，只对经证明的执行参数差异兼容 |
| 回答问题后模型配置变更 | 恢复仍使用旧配置，或重建时丢失答案 | 保存作者答案，再携带答案和候选建立后续任务；旧权限在新上下文中不直接执行 |
| needs_repair 通过重查后直接提交 complete | 内容已合法却被状态转换规则拒绝 | 先保存通过本地检查的审阅状态，再走原有原子提交 |
| 后台叙事评估使用绝对快照号 | 只改预算也会丢掉有效曲线结果 | 允许经过验证的执行参数变化；正文、评估版本或创作要求改变仍拒收迟到结果 |

## 内部恢复的范围

本地恢复只进行确定性核验，不新增模型请求、不代替作者采纳、不推进阶段、不清零累计轮数或费用。成功恢复登记 `local-recovery` 事件，保留触发来源和先前错误，便于后台日志追踪。

以下情况仍要求完成原有步骤：

- 标签、想法、禁区、文风、世界规则、人物事实或正式文稿真正改变。
- 原文在客户端外修改，磁盘内容尚未被作者确认。
- 独立审核发现实质冲突，记忆缺少依据，或必需产物未生成。
- 存在未回答问题、未批准动作、失败或未执行完的工具调用。
- 请求结果未知、断流后费用未确认，或模型输出被截断、中止。

这些情况的候选和请求记录继续保留。有限次数的自动补齐与修订仍受原任务预算控制；不会无限重试，也不会自动重发结果未知的收费请求。

正式事务的快照、文件基线、批准指纹及重复提交校验继续保留严格检查。运行器之外的当前事实查询、向量索引和历史回看仍按各自的数据范围隔离，不把历史事实直接当作当前事实。
