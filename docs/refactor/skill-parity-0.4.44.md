# 0.4.44：缓存、来源复用与增量台账

保持 S01—S11 顺序、原 Skill 模板、作者设定、独立正文审阅、记忆语义审查及后续计划核对。减少已知字段和机器回执的重复生成。

- Responses 请求按项目、接入配置、模型和推理强度生成稳定缓存标识。固定控制规则、原始作者输入及排序后的同版本来源位于阶段任务前；原生 assistant/tool 历史逐项保留。原始资料仍为 user 数据，不升级为 developer 指令。
- 官方 API 的已知模型使用显式共享前缀加自动续轮缓存。兼容端点使用自动缓存及稳定会话标识，不假定支持官方新参数。2026-10-23 的本机 Sub2/Codex OAuth 探针实际拒绝 prompt_cache_breakpoint，故该端点不发送断点或缓存 TTL 参数，也不自动降档重发。
- S08 可以引用已采纳、哈希匹配的章节总纲，生成新场面及必要覆盖字段。宿主还原逐章十二字段 Markdown 后进入同一验证流程。未生成的新场面、缺失字段、越界/重复章节不能由引用补齐。
- propose_changes 支持候选范围内的增量：唯一旧文锚点、唯一行锚点及末尾追加。所有变更绑定同一来源版本，拒绝歧义、重叠和过期依据。保留完整文件提交用于新文及大幅修订；最终产物均为完整文件。
- 指定正文的事实证据可用 source:prose；独立审查可用 evidenceRefs 选择该条记忆已有引文。宿主补齐路径和版本并验证原文，语义结论、逐条覆盖和问题理由不省略。独立审查不能由机械引文存在检查替代。
- 用量保存缓存读取、缓存写入、推理输出子集；缺失数据保持未知，聚合时不把未报告当零。

原始模型输入、实际发送 body、输出、工具历史及用量均记录到独立复测目录。修改、探针、测试、构建时间与冻结后的创作运行时间分开。缓存命中不是承诺；以实际用量和完整运行结果判断收益。
