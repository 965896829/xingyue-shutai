# 兼容与迁移矩阵

构建0.4.1；IPC protocolVersion=1；项目 schemaVersion=1或2；SQLite user_version=4；自有 checkpointVersion=1。版本职责分别判断。

| 合成样本 | 行为/证据 |
|---|---|
| 数据库1/2/3、项目1 | 增量事务建表，VACUUM INTO 备份含 WAL；assistant/studio 旧升级测试 |
| 项目2（标签契约） | 打开、回收、恢复、备份支持同一身份校验；T-001/tags 全流程 |
| 空项目、旧候选、未采纳正文、已采纳正文 | 保留旧记录与内容，不伪造聊天或模型结果；旧基线回归 |
| prepared 旧正式提交 | 可验证原changeset才恢复；T-055/056 两次 recover 仍只提交一次 |
| 旧待发/未知请求 | 标记可能发送、保留未知费用，不重新联网 |
| DB提交后 outbox 待物化/冲突 | 只补本地文件；四个独立进程 kill 边界及外部竞争回归 |
| 未知项目/数据库/checkpoint | 拒绝不安全写入；T-057/064 |
| 完整备份、WAL有提交 | 恢复到新目录，必需对象和 hash 校验；core/studio/compatibility |
| 备份缺对象/损坏对象/错误 manifest | 恢复前拒绝；原项目不覆盖，缺对象项目不能激活 |
| 损坏 settings JSON | 原始字节保留，另存 unreadable 副本，内存兜底 |
| 密钥无法解密 | 提示重新配置，保留旧加密值；实机换账号解密未演练 |

迁移不降版本。0.4.0 不允许读写已升级到数据库4的项目。代码回退须使用升级前备份恢复到新目录。只恢复程序不等于恢复数据。

GC 默认只报告容量和候选对象，没有删除入口；所有对象始终保留，等价于本轮全局保留，尚未启用删除时的细粒度 pin/回收协议。因此不声称已验证未来 GC 删除并发和中断。
