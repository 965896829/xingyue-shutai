## 用户入口

聊天输入框、阶段任务输入框、新建作品及开书页的模型名称旁均有强度标记。点击后打开紧凑面板：上方显示当前档位，中间可切换模型，下方为带刻度的滑杆，右上角可恢复默认。支持鼠标拖动、方向键、Home / End 和 Escape；按模型分别记住选择。

模型与连接设置、网页后台的模型编辑页也可以配置强度。桌面和网页共用数据与控件，变更会同步；深浅主题沿用所在界面的配色。新建作品的模型入口移到主表单，无需展开高级选项。

## 档位与实际参数

“默认”不发送强度参数，由模型服务决定。“低、中、高、极高、Max”等档位按精确模型 ID 和协议匹配，不把未知中转别名视为已验证型号。GPT-6 Astra 与 GPT-6.1 Sol 提供低、中、高、极高、Max；其他已核实 GPT 型号使用各自支持的集合。未接入的模型保持默认，并明确说明，不展示无效滑杆。

依据：[GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)、[GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[推理参数说明](https://developers.openai.com/api/docs/guides/reasoning)。具体型号来源记录在 `src/shared/reasoning.ts`，核实日期为 2026-10-19。Codex 应用内的额外档位不能直接推断为公开 API 参数，因此没有添加未经确认的 `ultra`。

- Responses 请求发送 `reasoning: { effort }`。
- Chat Completions 请求发送 `reasoning_effort`。已确认不兼容工具调用的型号与组合，在请求前提示使用 Responses。
- 显式开启推理时不发送与其不兼容的 temperature；不会用 temperature、输出 token 上限或提示词伪装推理强度。
- 原生 web_search、流式输出和原有工具循环保留。
- 上游拒绝所选档位时保留错误，不自动降档或重发请求。

## 偏好、任务与兼容性

Profile 增加可选的 `reasoningEffort` 和 `reasoningRevision`。快速设置使用独立命令 `profiles.reasoning`，校验模型配置版本及偏好修订号；保存到原配置文件，密钥仍由原加密存储管理。仅改变强度偏好不增加执行配置版本，旧页面不能覆盖另一处刚保存的偏好。

每个新任务保存各分工模型的强度快照 `reasoningEfforts`；聊天保存本轮模型的快照。运行器、审核、正文、章后更新、命名及最终请求网关均使用任务快照。每次实际请求的强度也写入既有请求对象和配置指纹。

因此，改变滑杆影响该模型的新消息和新任务；已经运行、暂停或等待采纳的任务仍使用创建时强度。普通恢复和应用重启不改变其设置。显式使用所选模型重新建立任务时，采用新的偏好。任务详情、开书运行详情和聊天调用记录显示实际绑定档位。

旧配置不需要强制迁移；缺少字段按默认处理。旧任务缺少快照时继续不发送强度参数，避免升级后突然提高消耗。新增记录位于原有配置、任务和聊天数据中，沿用原备份恢复流程，未新建第二套执行或记忆系统。
