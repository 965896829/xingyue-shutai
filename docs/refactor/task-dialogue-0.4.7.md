# 任务内对话 0.4.7

2026-10-11，作者希望在创作任务原输入框中询问当前报错，能够继续追问，不必把每次输入都当成重新生成的指令。截图中的 S02 缺少项目配置、文风样本等产物，已有模型回复又提及内部授权记录；客户端需要把真实任务状态一并交给解释对话，避免让作者猜测内部编号。

## 行为

- 在现有任务输入框问“为什么报错”“还缺什么”“下一步怎么办”，回复出现在当前任务正文下面，可连续追问。Ctrl + Enter 同样发送。
- 每次提问附带当前作品、阶段、任务状态、正式阶段完成记录、阻断项、必需产物、候选情况、已有任务回复及界面报错；近期对话请求自身失败也能继续询问原因。
- 普通解释不重新执行任务、不接受候选、不推进阶段。支持只回答文字的模型；查看候选的工具仅能读取绑定任务的未接受内容。
- 明确请求修改时，模型可以给出修复方案。点击“按这个方案修复”后继续原任务，不另建一个重复阶段；任务内容或来源变化后，旧方案失效。未知费用的重试仍需明确确认。
- 对话按任务保存，重新打开作品可继续；不会混入“创作讨论”的主题列表。已有布局、样式、图标和 Skill 文件不变，仅增加原任务流中的消息、说明文字及修复方案。
- 对话可以解释工作流状态并调用现有修复能力，不能直接修改客户端源代码；真实服务商返回的解释质量仍取决于所选模型。

## 实现

增加 `run.discuss` 契约和任务绑定对话，沿用现有会话存储、模型请求、流式事件和执行调度。上下文使用客户端实际记录，要求模型区分程序状态与旧回复的推测，用中文解释，不向作者索要内部编号或授权封套。修复卡绑定原任务及其内容指纹，执行前继续校验作品、模型、资料和任务状态。

主要源码：`src/core/task-discussion.ts`、`src/core/conversation-runner.ts`、`src/core/service.ts`、`src/core/conversations.ts`、`src/ui/TaskDiscussion.tsx`、`src/ui/App.tsx`、`src/ui/ChatWorkspace.tsx`，以及共享类型与生成契约。没有新增源码注释，依赖未改变。
