# 0.4.17：统一作品方案、独立命名与变更联动

2026-10-16。保留 S01—S11、四协议执行器、SQLite 正式快照、候选审阅和事务提交。

## 作者流程

新建只填保存位置与想法，平台标签可选。创意、标签或两者一起提供都进入同一策划流程：三个简短方向 → 选择与调整 → 完整作品方案及独立审核 → 作者确认方案 → 独立生成或手填核对书名 → 统一采纳 S01。选择方向、确认方案、生成书名及选择书名均不会提前推进阶段。

作品方案覆盖阅读承诺、融合因果、主角行动、阶段目标、长期方向、优势边界、持续剧情机制、阶段变化、开篇证明和内容边界。标签分工属于具体作品方案，不修改平台标签注册表。未覆盖题材可只按创意创建；保留现有 482 项范围。

书名按不同卖点给候选，显示阅读承诺、已确认方案依据、兑现阶段、审核结论与风险。允许手填核对、局部重做、停止、恢复及模型交接。未通过语义审核的候选不能选择；文字去重、引用、长度与字符由程序校验。不会显示虚构的点击率、市场概率或平台查重通过结论。15 字符只对应可选的番茄多书名实验场景，本地名称另有规则。

## 数据、确认与恢复

- 新流程的唯一正式方案为 `project.creation`，复用已有 BookSpec、知识快照与 CreationContract；最终契约包含结构化 plan、稳定条目编号、指纹、生效章节及作者批准依据。
- `project.tags` 仅用于读取旧记录。旧书主动接入并采纳时迁入单一正式记录，不维护两份可独立修改的契约；旧快照保持原样可读。
- 策划报告保留历史候选。作者的方案确认绑定完整候选、输入、知识与基础版本，不推进正式阶段。命名使用独立持久化任务，绑定方案指纹与来源确认；改变想法、禁区、标签或候选后旧确认和命名不能沿用。
- 书名生成与独立审核共用该命名任务预算，格式修复最多两次、语义修订最多一次；局部重做和交接不清空预算。命名沿用现有请求意图、用量、未知请求和执行检查点记录。
- 最终统一提交方案、设定拆解、书名与配置，并在同一事务中完成所选命名子任务。重复采纳不重复提交或推进阶段。
- 作品目录和项目 ID 保持稳定。书名变更同时更新配置、索引、进度与桌面最近作品；完整备份包含正式方案、确认、命名候选和历史，不包含全局密钥。
- 保留原契约展示路径以兼容旧目录。契约与书名 Markdown 是结构化记录的投影，外部编辑不能直接冒充正式记录，可从正式记录恢复展示文件。

数据库兼容版本提升至 7，项目结构新增版本 3。打开旧数据库时沿用现有完整备份后升级机制；旧作品不会因此被自动生成方案或退回 S01。旧版本客户端应使用升级前备份，不能继续写入新记录。旧的创建接口保留原行为用于兼容，客户端新建界面固定使用统一流程。

## 后续变化

正式方案及硬约束进入阶段、讨论和恢复上下文。方案条目可通过 `planRefs` 关联有正文证据的兑现记录；计划与已发生事件分别存储，不能用新方案为生效范围之前的正文追认兑现。

旧书主动接入、后续修订保持当前阶段、章节和已完成正文。新方案按下一个未写章节生效。变化记录列出条目与约束，复用现有影响队列核对世界规则、人物约定、未来大纲细纲与相关书名简介材料；没有充分依赖证据时仍列为待核对。同步按世界规则、人物约定、大纲到细纲的顺序传递候选，独立审核后统一采纳。历史正文不会自动改写，既成事实不能被未来约定覆盖。

方案变化后当前书名可能需要重新核对；可以检查原书名，无须一定改名。完成书名核对后再同步未来资料。单纯改名只更新命名与项目元数据，不产生剧情修订队列。
