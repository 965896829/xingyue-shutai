# 作者原始要求的传递与优先级

0.4.40 的第三次独立样本在 514.510533 秒时停止。S01 将作者指定的第一卷高潮重释为后续卷事件，S02 又将这条建议写入“用户硬约束”，与原 Skill 的第一卷安排不一致。4 次请求已返回，第 5 次在本地停止时仍在进行，远端结果未知；所有已接收输出、输入及冻结源码均保留，不将未收到的结果记为成功，也不重复续发。

修复将普通设计的采纳和修改作者原始要求分开：

- 宿主说明原始输入在无作者明确修订时优先于生成规划和摘要；阶段采纳不能把相反建议升级为作者要求。
- S01 先用卷长和发展层次满足具体事件承诺；S02 从作者输入提取硬约束，不盲目转抄上游建议；S05 先锁定事件卷属和字数窗口，再分配容量。
- 正文、审稿及记忆阶段补传完整 `authorPremise`，并在常驻输入预算中计入其大小。已有角色知情与未来揭示边界继续有效，作者全知不等于人物已知。

针对测试覆盖原始输入的实际审稿载荷、超长原文预算阻断、原始约束优先级、完整工作流及记忆安全。另以第三次实跑的 S01/S02 真实输入分别请求模型：S02 特意保留含错误建议的上游文件，以检验纠正能力。重放属于修复验证，不计入下一次从头实跑。
