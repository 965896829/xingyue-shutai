# 0.4.77 文稿、人物和故事资料可视化

## 原因与证据

本次以“折叠都市：我靠抢修给整栋楼续命”的只读导出副本回放。正式项目未打开写入、未迁移、未运行模型。

- 原项目 S10 已生成正文，但尚未采纳；任务中的正文为 2,653 字符，正式正文文件仍是占位。原文稿面板没有在重新打开时选择这个已完成草稿。
- 正式事实表和实体表均为空；角色卡 Markdown 已有许川、马国平、罗敏、丁海四个人物。原人物面板只读结构化事实，忽略已有角色卡和台账。
- 原章内曲线仅从少量标题和动作字段匹配强度，六个场面的其他风险、结果和状态字段被漏读。
- 行为记忆是按章节、人物分节的列表，物品伤势含说明段落；不能只按表格读取。

## 本次行为

文稿面板重新打开或从目录打开当前正文时，优先读取版本兼容的任务草稿，并明确标为“待采纳草稿”。点击别的档案仍正常打开。编辑内容缓存、正式采纳和恢复流程保持原有入口。

人物页从已保存角色卡、连续性台账、有效正式事实及本章任务草稿生成只读视图，默认展示目标、情绪和当前状态。支持人物切换、别名、稳定身份、行为记忆、关系、物品、知情和后续目标；变化字段可展开原记录。关闭“显示本章草稿变化”即可查看正式档案。

新增“故事”页：人物有向关系图、阅读章节与故事时间并列的时间线、伏笔、目标与承诺、物品、伤势说明、知情边界和世界规则。关系图限定所选人物的直接关系，支持更换中心人物和点击来源。缺少信任度、时间、伤势或情绪数据时不补填默认值。

详情页展示实际可读人物和资料数量、正式记忆数量、过期资料和检索索引状态，不生成综合健康评分。

叙事面板支持情节强度及压力、回报、情绪、揭示、关系五个维度；章内默认折线，可选平滑，节点可回看依据。细纲预估、草稿判断、已采纳判断有独立标识。全章维度对照复用已有评估或原有生成返回的可选 `narrative.chapterValues`；场面维度复用可选 `points[].values`。不为缺少附带数据追加请求，不由场面分数推造全章分数。

0.4.76 的左侧当前阶段、章节高亮一并保留。

## 约束

- 不将 Markdown 展示解析结果注册为正式事实，不把作者计划当作正文事件，不替作者采纳正文。
- 不把过期、已放弃、跨项目、跨章节或基线不兼容的草稿叠加为当前状态；完整替换稿中删除的字段不会从旧版自动补回。
- 每项可点击查看准确路径、版本和原文。草稿证据只从当前项目已有任务中读取，校验哈希、引文及 Unicode 范围，不接受任意对象哈希。
- 不改变 S01—S11 顺序、轮数、模型配置、Skill 文件结构或原有复核规则；可视化元数据可省略，格式异常也不触发修复轮次。
- 章内本地规则预估是粗略规划提示，不是正文文学评分；旧作品没有保存的精细维度仍保持缺项。
- 本次未新增依赖，未安装或覆盖已安装客户端。

## 涉及实现

`manuscript-view.ts` 提供只读展示与契约；`draft-source.ts` 补齐任务草稿来源追溯；`manuscript-target.ts` 选择可打开的正文草稿。界面由 `ManuscriptInspector.tsx`、`useManuscriptView.ts` 和 `App.tsx` 接入。`narrative-dimensions.ts`、`NarrativePlayback.tsx`、`NarrativeComparison.tsx` 及原曲线模块负责有来源的节奏展示。所有来源和可视化更新均复用本地数据，不进行独立模型推理。
