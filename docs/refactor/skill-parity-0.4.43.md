# 0.4.43：减少创作流程中的重复请求与上下文

0.4.42 死亡权独立实跑实际执行 4099.499 秒，其中模型请求 4053.539 秒，本地处理约 45.960 秒。44 次请求里有 15 次只读取本地材料，耗时 260.724 秒；包括网络恢复后的两次重读。原 Codex 记录为 gpt-6-astra / ultra，客户端为 gpt-6.1-sol / high（经本机 Sub2API），两者生成的规划长度也不同，4.46 倍不能全部归因于客户端执行器。

本版本保持客户端模型、推理级别、正文 2300—2700 字、30 章细纲、原模板字段、8000 字符分段上限及独立质量检查要求。

- 目标文件的完整基础版本在本地预载，跟随资料包记录哈希；模型可直接使用已有 baseHash。外部改动仍阻断，超预算的可选目标仍可按需回查，不能覆盖未读的旧内容。
- 为明确的现代规则悬疑、生存题材增加精确命名模块别名，不从否定或任意子串推定世界观。审稿与事实提取沿用既有名称，只保留名称一致性约束；不再重复装入新命名示例和工具。
- 分卷范围支持原模板字段及句末标点；节奏表支持无“章”字的 001—003 单元。保留全局约束、当前卷/批次涉及内容及准确 Unicode 来源区间，匹配不可靠时保留全文。
- S09 预载当前人物台账及完整当前批次；正文阶段只常驻本章相关计划。首次写作时不能用尚不存在的结构化正文事实代替人物资料。
- S04/S11 依完整内容长度分组，取消每组 1—3 文件限制。S06/S08 取消每轮固定 10/5 章限制，在原 8000 字符上限内按自然段组提交；不减少场面、字段或总章数。
- 文学审稿不再提供事实写入工具；记忆提取不重复携带质量报告候选。
- 普通章后的事实语义与未来计划检查在容量允许时共享一次输入，正文、事实和计划只装入一份。两个检查分别覆盖全部编号/文件，并复用严格引文、哈希和指纹验证。任何事实未获支持时不签发计划一致回执。小预算、超过 32 条或复杂同步仍使用分批核对。
- 只读审查请求不携带无关的输出版本、写入授权及重复资料清单；宿主版本、原文变化、预算、工具权限、批准及事务检查保持执行。

离线复核使用 0.4.42 保存的真实输出，未请求模型：当前卷输入从 7521 降至 1749 字符，首章节奏从 3250 降至 755；23 条事实及 4 份计划的共享审查输入/系统字符从 127687 降至约 71004（实际运行还有少量身份字段），减少约 44.4%。这只是输入大小比较，不冒充实际耗时提升。

完整测试、安装包校验、冻结文件清单和从头实跑记录在 `output/skill-parity-optimized-20261022/`。实跑采用新的 run-06，修复/测试/构建/项目初始化与生成耗时分别记录；最终结果以该目录完整报告为准。原 0.4.42 档案和原 Skill 八文件、十四模板块不修改。
