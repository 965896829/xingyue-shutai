# 0.4.38：原 Skill 输出结构与独立复测

完整设定入口继续按 S01—S11 执行。原 Skill 八份基础文件及十四份模板保持原文；客户端运行时要求把内容写进对应模板字段，禁止自动附加重复的保护清单、来源表、交付声明和复核说明。批量细纲仍完整覆盖当前批次，正文独立审稿、记忆证据核验均保留。

## 输出结构

- 自动生成的模板外二级小节会得到具体定位，要求将独有信息并回原字段；不会静默删除剧情或改动作者手工文稿。
- 章节表首列、节奏范围、分卷容量表及批次章标题本地转换为原 Skill 脚本接受的表示法。数值、因果内容及单元主题保留，不发模型请求处理等价写法。
- 正式采纳时，在同一事务中物化章后报告的同步字段；尚未结束的批次只更新进度，不伪造已完成摘要。
- 修改执行设置继续保留作者备注，缺少的旧参数别名不再形成另一套公开附表。
- 原模板的单章字数、范围与创作字段直接参与解析和采纳，不能依赖隐藏机器配置才能生效；正文长度边界也纳入容量漂移检查。文稿预览隐藏已标记的内部事实记录，原始证据继续保存在源文件和数据库中。
- 正常文稿导出采用同一作者可见内容规则，去掉已标记机器配置、审核证据和事实记录；小说正文逐字保留，完整备份与源文件不受影响。

## 请求与连续性

- 提供输出路径的正式 baseHash，完整来源已经在输入中时不要求再次读取。
- 分段回执只有在实际消息历史能完整重建并验证相同哈希时才省略尾文；恢复或缺链时仍保留尾文。
- 记忆提取开始时提供九份当前记忆全文各一次，并纳入来源变更检查。
- 正文审稿提交完整有效报告后直接进入记忆步骤；提取器以最后一次 `propose_memory(complete:true)` 明确完成，文件与事实指纹绑定，后续修改即失效。随后仍执行独立证据审核，不需额外模型结束说明。
- 后续计划由独立只读审阅逐份引用计划及正文核对。只有同版本、完整证据确认一致的计划免于重复同步；缺失、过期、冲突或不确定的结果仍保持待核对。新增事实本身不再等同于全部后续计划失效。
- 请求、工具、修复次数与费用上限继续生效；没有取消质量核验或将未知请求费用改为零。

基准已获作者全流程授权，按预先记录的策略自动推进通过检查的隔离候选，并另做最终内容审阅。代码修订、手工改稿、预算调整及断点交接不能混入干净复测；未完成的样本保留为诊断记录。构建与测试时间单列，不加入运行耗时。
