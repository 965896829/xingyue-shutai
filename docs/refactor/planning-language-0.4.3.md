# 0.4.3 策划中文说明修复

2026-10-11。修复“所选方向的契约候选”正文出现 `mustKeep`、`mustAvoid`、`A_D1_RULE` 等内部标记的问题，保留既有 UI 布局、操作入口和作者审批流程，没有新增代码注释。

## 原因与修改

策划工具需要英文结构化字段与编号关联方向、假设和约束。此前生成提示还直接用字段名描述作者约定，产物只检查结构与引用有效性，未检查作者可见正文是否把内部标记抄进去；界面随后原样渲染这些字符串。

| 文件 | 变化 |
|---|---|
| `src/shared/planning-language.ts` | 统一中文输出要求与显示转换；根据实际方向标题、假设正文和标签名称解释已知编号；空作者输入显示“未填写” |
| `src/core/planning-language.ts` | 检查新报告、契约和审核的作者可见文字，结构化字段、定位与关联编号继续保留 |
| `src/core/tag-planning.ts` | 接入提示与校验；泄漏标记时使用原有最多两次格式修复，仍受既有总轮次、费用与取消限制 |
| `src/ui/TagWorkspace.tsx` | 为策划说明、候选和约束变化等现有文字表达式增加显示转换，界面结构、静态文字与事件处理不变 |

例如，`mustKeep=[]` 显示为“必须保留：未填写”，`mustAvoid=[]` 显示为“不能出现：未填写”；已有 `A_D1_RULE` 会根据该任务的假设正文显示具体规则，不让作者猜编号。空清单不等于作者同意无限制。

旧候选的转换仅发生在显示层，不写回数据库，也不改变报告、候选、文件差异或审批指纹。旧书接入的已接受设定文稿仍原样返回；局部重做不会要求改写其他已冻结方向。英文专名、必要缩写、链接和文件路径不做全字母删除。
