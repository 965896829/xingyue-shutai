## 范围与结论

本次检查覆盖开书三案、完整作品方案、命名、S02—S11、候选修改、记忆同步、恢复和可选节奏评估。基于 0.4.69 当前源码修改；不更换模型、不提高请求轮数上限、不删减 Skill 产物字段，不调用真实模型复测。

## 减少了什么

以下是请求或审查范围对比，不是真实生成耗时测量。

| 场景 | 0.4.69 | 0.4.70 |
| --- | --- | --- |
| 六个书名中五个合格、一个需修改 | 生成→检查→自动修订→检查，共 4 次，不含检索 | 生成→检查，共 2 次；五个可选，问题项不可采纳 |
| 自动修订后完整方案完全没变 | 再发一次审核 | 0 次重复审核；原问题保留，不伪装通过 |
| 全部书名不合格，自动修订完全没变 | 再发一次审核 | 0 次重复审核；原不合格判定保留 |
| 三条事实中只修正一条 | 第二次核对三条，并可能重查所有后续计划 | 第二次只核对一条；原文、计划未变时复用计划核对 |
| 已收到有效结论，内存断点丢失但内部回执还在 | 整批精确缓存，任一项变化即失效 | 可逐条恢复真实结论，已有正面和负面结论都能复用 |
| 完整方案上下文 | 整份三案和重抽历史 | 所选方向及全部全局诊断/假设；三案原文件不变 |
| 书名审核上下文 | 当前批次、旧候选整批、历史和旧审查反馈 | 当前批次、方案、市场参考及作者要求；省略重复旧批次/历史/反馈 |

书名有合格项并不意味着其余书名被宣布合格。前端和后端均维持不合格候选不可采纳；用户可以选择其他候选或提出修改。

## 质量与失效边界

增量结论绑定当前任务、章节、基准版本、完整事实内容、全部相关来源路径及内容哈希、调整范围、控制规则、作者约定、作者原始创意、标签约束、审核模型版本及推理设置。上述依赖改变时，相关缓存失效。每次读取仍核对条目编号、证据引用和准确原文；缺少、损坏、漏项或引文无效都不能当成通过。

第一次合并核对须完整解析记忆与后续计划两部分，才保存可复用结论。事实不合格时，计划结果只保存在内部，不认证后续计划；事实修正并通过后，才允许复用正文及计划未变的真实计划结果。事实再次修改且未检查时，也不能用旧计划回执跳过检查。

后续计划的新指纹只依赖实际正文和计划，避免把待核对提取结果当作证据。旧版包含 facts 的指纹仍可按精确旧输入识别。正面、负面和“不明确”结论都按原样保存，不做本地语义判断、不构造假审核回执。

本次未改变三案报告、十类作品方案条目、六候选书名、Skill 阶段文档模板及正文/质量报告/章后更新的输出结构。减少请求不等于保证每次生成文字相同；真实生成质量与端到端时间仍需独立模型样本验证。
