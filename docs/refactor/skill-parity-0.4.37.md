# 0.4.37：原 Skill 格式兼容与长任务收尾

本次修复由死亡权设定与旧客户端记录的对照触发。原 Skill 的八份基础文件保持不变；调整的是客户端的格式识别、宿主执行与专项提示。已有未提交的项目修改保留，没有回退到历史版本。

## 格式检查

- 章节表支持 `1`、`001`、`第001章` 等等价章号；覆盖、重复、列数、章节类型与强度仍按同一解析结果严格检查。
- 分卷容量支持精确的中文万字表示，例如 `45万字` 和 `22.5 万字`；不接受小数字数或不匹配的容量。
- 评分支持带分母、单位和解释的常见写法，不删除解释，也不放过重复维度和越界分数。
- 模板字段后面的子标题、列表及有效表格可构成字段内容；空标题或仅有表头的表格仍为空。S08 所有被计入覆盖范围的合法章标题都必须具备逐章十二字段，不能以标题层级绕过检查。
- 正文字数和空稿检查使用同一个正文提取函数。首行一级标题或独立的“第001章 章名”不计入正文，普通叙事首段和对白保留。真实首章原稿为 2,424 个非空白正文字符；旧计数 2,435 包含了 11 个章名字符，历史日志保留旧值并注明口径差异。

## 减少重复请求

S01—S09 的普通阶段在整批工具调用成功、全部目标产物齐备且来源、版本、权限与内容校验通过后，直接进入待审阅，省去只用于校验或宣布完成的额外模型调用。生成完成不等于采纳；正式保存和推进仍走原审阅事务。

正文阶段的独立文学审核、必要重写、记忆提取与逐条证据核验继续执行。关闭实时预览时，不再额外运行两次自动预览评分；手动评估入口保持有效。新建作品可选择“已有完整设定”，直接执行原设定流程，并保留作者书名、完整输入和篇幅参数；原有从创意策划的入口继续保留。

文学审核给出有正文引文和哈希证据的阻断问题时，即使评分报告写“无需整章重写”，也应转到正文修订，不能重复要求修改本来正确的评分报告。只有偏好警告不会触发重写；报告本身格式、引文或版本错误仍先修报告。作者编辑正文候选后，旧审稿、记忆审核和旧稿局部修复状态失效，重新审核新正文；累计模型轮数、工具数及费用用量不重置。

S04 的九份人物与连续性文件按自然组分轮保存，角色卡通常独立提交，其余每轮一至三份短文件。已保存且有效的候选不重复生成，恢复时读取候选再补未完成文件；仍需九份齐全和原十九项角色字段完整才能进入待审。此调整利用既有的多文件候选累积机制，减少一次长响应中断时丢失全部生成的风险，没有放宽最终检查。真实复测遇到的 HTTP 上游 EOF 及未知费用保留在记录中，不能把分组保存视为已经修复上游网络。

S06 章节总纲与 S08 批次细纲通常每次响应保存最多五个完整章节，场面复杂时可减少本段章数。收到真实保存回执后接续，不在同一响应里连续提交依赖同一旧哈希的多段内容；最后一段仍须完整覆盖实际批次才声明完成。此限制仅改变单次传输和保存粒度，十三列表格、逐章十二字段与可执行场面要求不变。S06 真实请求遭遇上游数据间隔超时后，以明确记录的恢复指令先验证这一保存方式；S08 开始前将其固化进两阶段专项提示。

`read_document` 明示候选读取的回退顺序：未完成草稿、已保存候选、正式文档。回执标识实际来源并给出正式 `baseHash`；候选不存在而返回正式版本时，无需再读取相同文件以获得提交哈希。旧正式回执的 `hash` 用法继续兼容。候选内容哈希与正式基础哈希仍严格区分，磁盘外部改动、权限、快照和提交版本检查保持有效。此修复由真实 S04 两轮同内容复读触发，不能据工具说明改动保证模型从此绝不重复读取。

## S08 轮数上限恢复

S05—S08 的分段草稿在预算耗尽或恢复时，可以尝试本地完整性检查后收尾。只处理内容完整、末尾闭合、哈希和来源一致、全部字段与批次覆盖通过的草稿。失败保留已有草稿；日常生成仍等待明确的最终提交，不因中间片段暂时看似完整就提前停止。

此路径不提高 12 轮上限，不重置累计工具数或用量，不自动采纳。未知费用保持未知。S10/S11 的记忆流水线不能借此省略模型的显式结束和独立事实审核。

完整复测的 S08 在原 12 轮预算内用 7 轮完成。后续 S10 因修复前的审稿分流错误已消耗 11 轮，继续审核和记忆更新需要为该隔离测试显式补充轮数预算；这一调整通过现有项目配置接口执行并单独留痕，不作为 S08 自动恢复的性能证据，也不改变客户端新项目的默认预算。

旧 S08 的真实隔离副本已验证：6 段、25,571 字符原样合成待审阅候选，0 次模型调用，12 轮和 22 次工具调用保持不变，严格检查无问题。验证耗时 3.255 秒包含打开副本、检查和关闭；不能把它当作重新生成三十章的耗时。原作品没有被本次验证写入。
