# 回退与恢复操作

## 功能回退

Pi 始终关闭，新任务为 legacy。不得修改记录中的 executor/checkpoint 冒充兼容，也不要删除未知请求后重跑。关闭新框架不影响原候选和正式文件。

watcher 有60秒低频扫描兜底；资源事件出现缺口回到 app.snapshot。GC 删除未启用。没有提供改变 UI 的新增开关。

## 普通异常

1. 请求结果未知时，先查看已收到内容、供应商记录与费用。明确选择重新发送才产生新 Attempt；原未知费用保留。
2. 执行内核断开时等待有限恢复；不会自动推理。连续失败后退出并重新启动，保留项目和诊断。
3. outbox待同步时可用原“重试同步”操作；发生外部改稿先比较保留内容，不删除 .novelclient/preserved。
4. 未保存编辑由本机草稿缓存保留。正常退出会停止活动请求、持久化并关闭数据库；最长15秒后强制结束，下一次仍需核对远端结果。

## 代码与数据回退

- 保留当前项目和全部 .novelclient。不要手工降低 PRAGMA user_version，也不要删除新增表。
- 从升级前 .novelclient.before-v4-* 的完整备份或正常导出备份，经恢复入口复制到新目录；先核对文件 hash/历史/待提交事务，再使用兼容版本。
- 不用当前0.4.0直接写入数据库4。旧安装包只能与旧兼容副本配合。
- 本轮没有覆盖真实安装。交付安装包的 appId、GUID、userData 名称与旧版一致，但覆盖安装、卸载、跨账号密钥迁移仍需独立Windows环境验证。
