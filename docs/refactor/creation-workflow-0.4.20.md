# 0.4.20 开书、提示词与恢复更新

## 交付范围

基于 `main` 的 `1378e7710759b7c3df397d899c24ae042a0e50d8`（0.4.19）更新现有客户端。本次接入已有三步开书、四协议模型执行器、SQLite 正式快照、Markdown 文件、独立审核和作者采纳机制。

本次交付源码与回归测试。0.4.20 Windows 安装包、覆盖安装和真实模型文学效果未在本轮验证。

## 作者能直接使用的变化

### 1. 可以有明确范围地反复构思

在“作品方案与书名”的第一步，除了原有“按要求重做这个方向”，增加：

- **换一批三案**：沿用当前创作想法、标签、必须保留项和禁区，重新生成三案。
- **保留这一案，换另两案**：完整保留当前选择的方向，重新设计另外两案。
- **这次希望怎样构思**：可补充偏好，例如提高生存压力、加强能力代价、减少系统感。

保留一案时，客户端同时保护该方向的完整内容、关键假设、代价及关联诊断。新两案可以调整自己的假设，不能通过删除全局假设来取消保留案的限制。旧报告进入历史，旧界面的报告版本不能重复选择或重做。

模型会收到同一作品、同一输入版本的近期方向摘要，默认最多 9 条方向记录。历史用于比较差异，未选内容不会成为正式设定。新方案仍须通过结构检查与独立审核；轮数、费用和工具预算继续累计，超过设置时保留结果并暂停。

### 2. 先确认方案，再比较六个书名

新命名任务默认恰好六个候选，每个候选说明命名角度、读者承诺、方案依据及兑现阶段。反复生成会携带同一方案与同一来源版本的近期命名历史，默认最多 18 个名称及审核反馈，并拒绝规范化后完全重复的名称。

作者手填名称只核对该名称；局部重做只替换指定项，其他候选完整保留。审核只修正承诺或引用时可以保留原名称。旧任务没有新增数量字段时，继续读取原来的 1–12 个候选合同；本次不会把旧候选补成六个。

“番茄命名参考”展示带核对日期、网址和解释的五个官方页面样本。生成与审核的真实请求均带这些资料，覆盖短名称、题材与机制、处境与行动、异常与反差等命名方式。它们是编辑归纳的有限参考，不是点击率、排名或实时热门词统计。作者明确的长名、短名偏好优先，名称承诺必须有当前方案支持。

六个候选是客户端默认值。15 字符限制仍只适用于“番茄多书名实验”命名场景；普通书名使用本地配置，未进行番茄全站重名核验。

### 3. 标签提示说明核实到哪一步

保留现有标签 ID 和本地快照，页面从注册表读取数量，生产校验不再假定词条总数永远是 482。

新增带版本、适用范围、核对日期和来源的标签规则资料。阅读标签四组数量分别核对；内容标签数量、实时可用词条和完整组合限制单独标记为尚未核实。数量符合不会被汇总成“整个组合已获平台确认”，未知项不阻止创意策划。

只输入创意的开书方式继续可用，显示“未应用平台标签规则”。本地不存在的 ID、分组错误、重复选择或超出本地范围仍由程序拒绝。

### 4. 冲突作品可以先打开、比较

如果已经批准的提交在落盘前中断，之后文件又被外部编辑，客户端会显示待处理的提交，同时允许打开作品、阅读正式版本及比较：

- 当前磁盘文件；
- 上次已接受的正式内容；
- 当时批准、尚未提交的原始候选。

用户可以恢复原文件后点击“重新检查并恢复提交”；也可以点击“保留候选，放弃此次提交”。后一操作保留候选、原提交日志及外部文件，撤销尚未使用的批准。若方案版本或批准依据已经变化，页面提示放弃旧提交后重新审阅，不能直接复用旧批准。

已记录的冲突不会在下次打开时自动重放，未处理前暂停新的正式提交。文件或日志损坏仍会报错，不会因存在外部冲突而跳过完整性检查。

## 提示词与实际执行的衔接

原策划提示词文件虽在资源校验范围内，主要请求仍使用长段内联文本。本次改为实际加载独立的策划、审校、方案展开、命名和书名审校提示词。

26 个已有专项模块统一为“角色、任务、规则、输出”，保留各自原有产物、核心依赖和阶段边界。模块文本总字符数由 27,701 减少到 21,592，约减少 22.1%；这只统计 26 个模块文件，不代表请求 token 或费用同比下降。

正文、审稿、记忆提取分别使用独立输出模式。正文调用只返回正文，审稿调用只交审稿结构，记忆调用只提取当前版本的候选增量。模型不会同时收到“写正文”和“提交阶段文件/质量评分”的相互冲突要求。

资源哈希继续覆盖实际使用的提示词与样本。作者主动重做会保存上一轮提示词指纹并建立新轮记录；普通中断恢复仍校验版本。历史资料放在用户任务数据中，选择不同冻结方向不会无故改变同一阶段的系统提示词。

## 请求行为修复

Chat 和 Responses 的明确拒绝内容进入已有 `filtered` 处理，保留拒绝文字、原生消息与已知用量，不再误判为空回复并重复触发格式修复。

聊天停止后，若模型迟到返回完整响应，记录已收到内容和已知费用，但停止执行随附工具、任务卡或后续轮次。已知响应不会被改记成未知费用。
