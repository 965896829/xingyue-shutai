# 0.4.74：正文流式显示与叙事进度同步

## 原因与修改

0.4.73 的 S10 作者流已经发送 `prose-delta`，但工作台没有把这个增量直接用于正文显示。它把该事件当作状态变化，等待约 350 毫秒后读取状态；作者草稿写入数据库又有约 800 毫秒的间隔。因此界面容易隔一段时间才增加一大段文字。每次增加还重新解析并替换整篇 Markdown。任务讨论也可能把正文事件当成刷新对话的理由。

旧叙事节奏面板只显示 `assessments`。新作品默认关闭额外的预览评分请求后，这张表可能一直为空，面板只剩“暂无评估”。

本轮修改：

- S10 增量补充字符偏移与资源范围；前端直接消费增量。生成、落盘、恢复及 skill 内容契约不变。
- 正文、任务回答、创作讨论共用按画面帧合并的显示通道。收到一批文字后用约 100 毫秒呈现；暂停、完成和隐藏页面时及时收敛到已保存或已收到的文本。操作系统减少动态效果设置受到尊重。
- 右侧正文编辑器也订阅同一份流，追加时只替换变化区间，保留前文与选区；结束时一次同步完整候选，不停在开头短草稿。
- 只有当前文字块与节奏位置随帧更新。完整段落保留 DOM；变动尾段重新解析，保留 Markdown、代码、链接、净化处理和横向表格阅读。
- 删除被替代的 `useLiveText.ts`，去掉工作台顶层逐增量更新，以及任务讨论对正文事件的无效读取。
- 正文生成阶段自动展开叙事进度：已显示字数、目标篇幅、既有细纲的场面顺序及计划强度。正文和节奏面板订阅同一个已显示文本前缀。
- 优先复用生成时绑定的完整细纲；不足时按既有文档哈希读取本地文件。不会调用模型补评分。原有五维评估数据仍可显示。
- 向下阅读时跟随输出；向上翻阅或选择文字时尊重用户位置。项目切换、重复事件、旧工作进程、重试正文和延迟快照都有隔离或版本控制。

## 进度的含义

场面位置按已显示篇幅与目标字数估算，界面明确注明“场面位置按已显示篇幅估算；内容与强度来自本章细纲”。这是已有规划与生成进度的联动，不是实时语义评分，也不能证明该场面已经按计划写成。计划强度只取自细纲，不转换成压力、回报、情绪等五维分数。

没有场面结构的旧细纲显示正文进度，不虚构场面或分数。停止时冻结，重新生成时切换新的正文流，正文完成后保留结果供阅读。
