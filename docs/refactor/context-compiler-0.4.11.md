# 0.4.11 上下文编排实施与验收

2026-10-12。保持客户端界面布局和样式，不增加作者操作步骤，无新增源码注释。此前安装的 0.4.9 直接升级到 0.4.11，本包包含 0.4.10 的记忆一致性修复。客户端 `resources/skill/runtime/agent.md` 继续作为创作模型总控，本次内容未改变。

## 实际变化

| 项目 | 已实现行为 | 边界 |
| --- | --- | --- |
| 独立编排器 | `context-compiler.ts` 统一服务普通阶段、正文、修订、讨论和自由试写，替代分散的常驻资料拼接 | 标签策划、记忆修复、审稿等专用子调用仍按各自契约组装检查对象；完整请求统一经过预算校验 |
| 范围与版本 | 先确定作品、世界、时间线、章号与正式快照，再筛有效来源、检索、排序去重、分配预算 | 当前工作分支只有 main，不宣称多分支合并 |
| 作者硬规则 | 能力禁令、世界规则独立装入；相关伤势、未完成承诺及伏笔固定保留 | 文本本身的歧义和遗漏仍需作者及模型核对，不能证明提取语义永远正确 |
| 知情和揭示 | 人物事实与作者约束分开；尚未允许揭示的事实进入单独边界块，标明不能写成人物已知 | 保留作者必要的隐秘设定作为禁止泄露依据；最终写作遵循情况仍依赖模型 |
| 本章材料 | 抽取当前章节和分卷范围，保留全局说明与前章结尾 | 计划格式无法可靠识别时保留全文，超预算则提示缩小任务，避免静默删约束 |
| 证据与影响 | 记录来源版本、Unicode 范围和省略原因；硬规则与隐秘事实的来源也纳入依赖检查及修订影响分析 | 字面相符和哈希一致不等于事实语义必然成立 |
| 中文检索 | 精确人物名、别名和实体关系，配合中文分词及二字片段；从有效来源筛选后排序 | 本轮是中文词法匹配，未新增 SQLite 中文倒排索引，不依赖 trigram 找两字人名 |
| 输入预算 | 已知映射使用本地 tokenizer；未确认模型明确采用 UTF-8 字节保守上界；扣除输出、协议、安全和工具结果预留 | 本地计数不是供应商完整序列化的精确计费 token 数；未知模型可能提前触发容量限制 |
| 入口一致性 | 资料预览也扣除当前任务规则；多轮每次发送前检查完整请求和资料版本 | 后续工具返回或历史增长仍可能超限，此时停止请求并保留任务 |

硬约束与必读资料不参与预算删除。可选片段和可选事实被裁减时记录原因；硬约束仍装不下时不发请求。模型有效输入上限可以通过配置收紧，但不会根据一次测试或服务商宣传自动提高。

## 真实端点结果

使用本机已配置的 Responses / gpt-6.1-sol，发送合成小说资料；没有发送真实作品。三个输入规模同时改变资料包出现位置，属于小样本连通性和规则核对，不能分别推断位置效应和容量上限。

| 组别 | 资料位置 | 供应商回执输入 tokens | 结果 |
| --- | --- | ---: | --- |
| 1 | 开头 | 3,512 | 姓名、能力、伤势、人物知情、揭示时机、承诺期限共 6 项通过 |
| 2 | 中部 | 10,426 | 同上 6 项通过 |
| 3 | 结尾 | 未知 | HTTP 502，停止且未自动重发；本地输入为 93,176 字节保守上界 |

报告保留 `complete: false`，未产生已验证有效容量结论，也未改变作者的容量配置。第三组可能是网关、模型或服务端故障；仅凭 502 无法认定上下文过长。前两组只证明这两次输入中的六项事实判断，不能证明整本小说无记忆错误或文学质量合格。

`npm run eval:context` 默认仅做离线资料包测试。实际调用必须加 `--live --profile-file <测试配置>` 并以 `WENXU_EVAL_API_KEY` 提供测试密钥，失败即停止。测试报告记录具体模型、计数方式、供应商使用量、答案及检查结果，不自动修改生产容量。
