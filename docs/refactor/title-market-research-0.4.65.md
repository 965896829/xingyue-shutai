# 0.4.65：命名前检索番茄同题材书名

## 原因与行为

旧版独立命名只读取固定的五个离线样本，没有在生成书名前联网。0.4.65 在新建自动命名任务时，先做一次有上限的资料检索，再沿用原有的六候选生成、独立审核和作者选择流程。

- 优先使用当前 Responses 模型连接的原生 `web_search`；使用第三方搜索的连接复用已有 Tavily 配置，不新增依赖。
- 只向搜索阶段提供公开题材词；优先取已选标签，无标签的创意开书则从已确认题材及方案提取公开类别，不把角色、情节正文和私人备注放进检索词。
- 原生研究至多一次模型请求、两次搜索工具调用，受现有轮数、工具数和预算限制。没有新增市场报告提交或市场报告审核步骤。
- 仅保留番茄官方 `/page/数字编号` 作品页，排除关键词聚合页、伪域名、无题名链接和重复页面。显示检索时间及来源，最多八本。
- 同一批的审核、格式修正、语义修订、单项重做及恢复复用已存资料；作者另生成一组时才重新检索。作者手填名称的核对不额外搜索。
- 未取得实时资料时明确显示离线状态，不声称已检索成功，也不因为缺少参考样本阻断命名。上游请求结果不确定时继续保留原来的人工恢复边界，不自动重发。
- 新任务提示词要求参考题面表达、长短名差异及具体人物和处境，避免抽象概念堆砌和六个同模板名称。保留作者偏好与作品事实，不照搬其他书名、设定或标志性短语。

原生工具参数依据 [OpenAI Web search 文档](https://developers.openai.com/api/docs/guides/tools-web-search)：启用外部检索、限制域名并接收工具来源和引用。Sub2 的实际支持情况通过下述真实请求验证，未仅依赖接口文档推断。

## 流式接收修复

首轮开发验证发现中转发送了完整的流式条目，但最后的 `response.completed` 没有携带输出列表。旧接收器只读取最后一帧，误判为空结果，导致重复生成。

现在在终止消息省略或清空 `output` 时，复用已经收到 `response.output_item.done` 的完整条目。仍有未结束的消息或工具参数时保留为结果不确定，不把碎片作为工具调用执行；正常终止消息保持权威，不重复拼接已有结果。HTTP 与 WebSocket 共用此兼容逻辑。

## 真实验证

在现有项目的独立副本上，使用原 Sub2 连接的 `gpt-6.1-sol/high`，不采纳名称，不写入原作品或模型配置。此处只验证独立命名流程，不是 S01—S11 全流程复测。

| 步骤 | 耗时 | 结果 |
| --- | ---: | --- |
| 番茄书名检索 | 25.453 秒 | 一次模型请求，内部两次搜索，保留四个官方书页 |
| 六候选生成 | 74.452 秒 | 六个完整候选 |
| 原有独立审核 | 22.672 秒 | 五项通过，一项需要补充方案引用 |
| 原有局部修订 | 27.808 秒 | 补充 `p_opening`，六个名称不变 |
| 原有复审 | 25.076 秒 | 六项均通过 |
| 独立任务总耗时 | 176.959 秒 | 约 2 分 57 秒；等待作者选择 |

本次格式修正为零，语义修订一次。需要修订的候选是“旧井通往三十年前”：原引用支撑了三十年间隔及干预循环，但未引用明确提到旧井的开篇条目。此处没有再次搜索，也没有新增审核轮类型。

全量回归 662 项全部通过，构建与安装包检查通过；158 个 Skill 文件与源码逐字节一致，没有随安装包重复携带 `node_modules` 源码树。回归测试本身耗时 886.229 秒，不计入上述命名任务时间。

得到的候选：旧井通往三十年前、修器学徒查旧案、禁剑还在库里、去三十年前找我爹、师父从未收过我、有人留着改史的证据。名称吸引力仍需作者判断，本次不能证明主观的“AI 味”已彻底消失。

四个引用来自番茄官方详情页。独立抽查的[《无限资源，宗门全员天骄》](https://fanqienovel.com/page/7394393396455935000)与[《全宗门凑不出一个老实人》](https://fanqienovel.com/page/7598749470846618648)均能核对书名及玄幻脑洞分类。样本的穿越、系统等具体设定不作为当前作品的事实依据。检索时间不是作品发布时间，也不能据此称为最新热榜或完成全站查重。

开发中发现空输出问题的失败样本耗时 243.741 秒，保存于 `output/title-market-research-20261025/live`，单独列账。修复后的完整样本位于 `live-fixed`，修复、测试、打包和界面验收时间均未计入 176.959 秒。模型输入缓存命中率实际为 40.9145%，未将新增的命名研究任务宣称为 95% 缓存性能验收；未提供价格，费用记为未知。

## 兼容与验收记录

新增研究状态字段均可选，旧命名任务不强制重新搜索或失效；显式生成新任务时才启用新规则。候选结构、独立审核结构、阶段上限与正式采纳流程保持原样。本次没有新增依赖或修改 Skill 资源文件。

验证材料保存在 `output/title-market-research-20261025`：

- `verification-summary.json`：实际请求、耗时、缓存、来源、完整测试结果及安装包校验值。
- `live-fixed/1-input.json` 至 `5-output.json`：五次模型调用的输入与输出；不包含鉴权请求头。
- `live-fixed/result.json`：六候选、审核、检索状态和运行结果。
- `full-tests.log`、`build.log`、`deliverables.log`：回归、打包及资源一致性检查。
- `title-ui.png`：使用全局 Playwright 验收隔离副本的界面。实际六候选、四条来源及检索日期显示正常；另行模拟搜索失败时，无额外阻断提示。

安装包：`release/星月书台 Setup 0.4.65.exe`。已安装并打开的客户端继续保持 0.4.64，本次未自动关闭或覆盖。
