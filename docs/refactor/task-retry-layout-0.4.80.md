# 0.4.80：第一章重新生成与对话两侧布局

## 确认的原因

只读检查原客户端的当前作品发现：S10 第一章任务暂停在记忆核对阶段，累计请求轮数已经达到 12。作者提出重新生成后，任务方案仍绑定该任务；确认入口沿用累计上限检查，因此启动被拒绝。界面把错误放在长对话顶部，按钮旁没有反馈，表现为点击没有反应。

左侧短线导航和右侧滚动条原本都在居中的窄列中；写作容器还有水平内边距，所以无法靠近写作区域两侧。

## 修复行为

- 作者确认对已达上限的 S10 未采纳正文进行修改时，建立新的章节候选，从正文阶段执行。旧稿、旧任务及调用记录保留；单次轮数和工具上限配置保持原值，累计费用预算沿用原任务链。
- 普通断线恢复、继续任务不重置累计计数；未知结果仍需明确选择是否重新请求。其他阶段、已采纳任务及特殊修复任务不走此重建入口。
- 新候选和任务方案的执行状态在同一数据库事务内保存；重复确认返回原执行结果。前端增加本地重复点击防护、就地启动状态、就地错误提示和错误焦点定位。
- 相应按钮改为“重新生成这一章”；其他普通修改按钮为“开始修改”。
- 对话滚动容器铺满写作区域，导航靠左、滚动条靠右；正文和输入框保持居中阅读宽度。窄窗口和打开文稿面板时适配写作区域边界。

本次不修改 skill 指令、阶段定义、正文输出结构或模型配置。

## 验证与交付

- 74 项相关回归测试通过，覆盖重新生成、普通恢复、未知结果、累计费用预算、Pi 执行入口、任务对话与幂等性；未运行整个测试集。
- 浏览器离线夹具验证宽窗口、窄窗口和打开文稿面板的布局；注入启动失败后，错误显示在按钮旁。后续双击只进入一次模拟模型调用。
- TypeScript 检查、生产构建及 NSIS 打包成功。首次构建发现测试断言的可选消息类型错误，修复后重建成功，首轮日志单独保留。
- 安装包内 UI、主进程和 worker 与本次构建逐字节对比；skill 目录清单及各文件散列与源码一致。详见 [打包校验记录](../../output/task-retry-layout-0.4.80-20261028/package-verification.json)。
- 本次没有真实模型调用，没有覆盖安装，没有修改原有作品和模型配置。离线测试确认重新生成入口与请求次数，不代表完成了真实模型整章质量验收。
