# 0.4.68：围绕内容查看与修改的流程简化

用户只需要判断本阶段生成的内容是否合意。内部校验、审稿和必要的局部修订继续由客户端执行；正常建议不再转换为人工审核手续。

## 确认的问题

- 部分 warning 要求作者填写“保留理由”，即使没有阻断错误也不能保存。
- 已确认方案、已选书名之后，还需要到页面底部再次保存。
- 阶段对话明确要求修改后，会生成待确认卡，并再请求模型输出一次结束说明。
- 自填书名、修改要求隐藏在折叠区，进度中的“检查书名”容易被理解为要用户操作。
- 已有作品调整方案后，书名待核对状态会禁止继续写作、同步后续计划。
- 完成的 S10 流水线收到作者修改意见后，未正确回到正文阶段；切换模型时也可能只复核旧稿。

## 本次修改

1. 删除 warning 的强制理由门槛。非阻断建议仍可查看，保存时继续执行原来的错误校验、版本校验和独立审核检查。旧 API 的可选理由字段仍接受。
2. 新书选定书名后，一次点击完成名称选择与方案保存；按原复选框决定是否继续生成。已有书名的作品直接保存满意的方案，不再强制进入命名步骤。
3. 方案结果增加直接修改输入框。复用已选方向、报告和原方案，仅重新生成方案及执行独立检查；清除旧选择绑定并保留修改历史和累计预算。
4. 阶段结果增加“按意见修改”。它直接修改当前候选，无须额外讨论请求。普通阶段对话在作者明确提出修改时可直接执行当前未采纳候选的修订，省掉重复确认卡及其结束回执；单纯提问仍只回答。
5. 自动执行仅限本轮绑定的当前候选，继续检查版本、依据、模型、预算和请求状态。使用独立幂等回执，消息重复提交、任务重复确认不会再次执行。普通自由聊天、旧任务卡保持兼容。
6. S10 收到修改意见时回到正文阶段，保留原稿供修改，撤销旧审稿与记忆回执，随后重新审稿、提取及核对记忆；切换模型重建上下文时也应用修改。总轮数、工具数、费用不清零。
7. 命名页先展示结果；“自己取名或修改要求”直接定位到输入框。“自动检查书名／方案”明确由客户端执行。已保存结果不再继续显示“请采纳”，内部契约不默认展开。正文与修订内容可在阶段页直接阅读。
8. 方案变化后的书名状态改为提醒：继续保存其待核对标记，作者可随时调整，但不单凭书名状态禁止创作或同步。实际内容冲突仍按原规则处理。

## 保留的边界

保留 S01—S11 顺序、Skill 内容结构、生成和独立审稿职责、记忆证据校验、正式稿采纳、文件版本保护、兼容与恢复。网络请求结果未知、重复计费风险、实际执行权限或预算不足仍会明确提示，不静默重发，也不扩大预算。

新字段均为可选，旧作品、旧对话和旧任务卡继续按兼容路径读取。开发与测试期间未修改安装中的客户端、真实作品目录或模型配置；随后按用户“覆盖”指令完成下述安装更新。未进行真实模型复测。
