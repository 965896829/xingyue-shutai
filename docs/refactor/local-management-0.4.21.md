> 这是 0.4.21 的历史记录。0.4.22 已移除 iframe 和此处旧导航，当前页面及功能映射见 [原后台复刻记录](admin-replica-0.4.22.md)。

## 范围与使用入口

按作者确定的范围，首版在本机浏览器管理这台客户端，作品和创作任务也接入。保留以后连接多台客户端的适配接口。

1. 启动 0.4.21 客户端。
2. 点击侧栏「网页管理后台」，或菜单「星月书台 → 打开网页管理后台」。默认浏览器打开并完成一次授权。
3. 在网页侧栏进入需要的功能。首次没有作品时，从「作品与文档」新建或打开本机作品目录。
4. 浏览器里的目录选择框浏览的是客户端电脑上的文件。输入完整目录后点击「前往」，再点击「选择」；导出时填写文件名。
5. 关闭网页不会取消创作任务。停止任务请使用任务页的停止按钮。退出客户端会关闭管理服务。

菜单支持复制新的管理链接、断开全部网页会话和停止管理服务。链接两分钟内有效且仅可使用一次；网页会话最多八小时，失效后从客户端重新打开。链接中的授权信息进入 URL fragment，页面兑换后立即移除。

## 工程接入

视觉和功能组织参考本机 `D:/aiwangzhan/novel-platform/apps/admin` 的深色侧栏、卡片、顶部工具栏和浅绿操作色。在当前 Vite/React 工程中实现；没有复制原平台的账号、套餐、账单、后台凭据或数据库。

调用链：

```text
浏览器管理外壳 + 复用工作台
    → 带会话和版本上下文的 HTTP 命令 / SSE 事件
    → Electron 主进程统一 dispatch
    → 现有业务进程 Service / 调度器 / 模型适配器
    → 原作品 SQLite、快照、候选、提交和 Markdown 同步
```

桌面 IPC 与网页命令都进入同一校验和分派入口。网页不创建另一套业务 Service，也不直接写作品数据库。工作台、模型设置、智能体设置复用现有 React 组件，避免两套流程日后不一致。

新增 `admin.html` 和 `workspace.html` 构建入口。网页外壳保持同源工作台常驻，切换日志和设置不销毁未提交输入。开发模式代理 Vite 模块并使用其 loopback HMR；安装版读取 `app.asar` 内的静态资源，无需另外安装 Node、Next 或 Python 服务。

`ManagedClient` 把目标适配与 HTTP 传输分开。接口使用 `/api/clients/:clientId/...`，`/api/clients` 目前只返回本机这台。将来多台管理仍需另行实现远端认证、设备连接和部署；本次没有开启局域网/公网服务。

## 一致性与连接保护

- 服务仅监听 `127.0.0.1`，默认端口 39741；端口被占用时选择空闲端口，由客户端生成实际链接。
- 一次性随机授权、HttpOnly/SameSite Cookie、CSRF 校验、Origin/Host 校验及跨站限制；页面不保存 API Key 或会话密钥到 localStorage。
- API Key 继续由客户端现有 Windows 密钥保护保存，网页读取配置只看到是否已配置密钥。
- 每次作品请求绑定作品会话和内核代数，旧视图不能向已切换作品提交。写操作没有自动重试。
- 供应商组保存校验模型版本与启用状态，另一端改动后拒绝覆盖旧配置，需重新载入。
- 文稿编辑和缓存同时绑定作品编号与目录，恢复副本沿用编号时也不会串用草稿；跨端切换时收起旧编辑器，保留原草稿缓存。
- 普通目录不再在打开失败时被创建为空项目数据库，并且失败前保持当前作品。
- 浏览器路径选择按会话单独授权；服务不提供随意执行 shell 的接口。静态路由不暴露源映射、数据库或任意本机文件。
- 连接断开只停止页面等待；已提交任务的实际状态仍以客户端为准。重新连接先读持久化状态，不重新调用模型。

管理操作日志单独保存到应用数据目录 `management/audit.sqlite`，记录来源、命令、结果、耗时、操作编号和错误码，不记录请求正文、Key 或配对链接。约保留最近两万条；任务事件仍在作品数据库，随完整作品备份保存。全局管理日志和 API 配置不包含在单本作品备份中。
