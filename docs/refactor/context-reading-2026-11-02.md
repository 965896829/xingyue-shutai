# 上下文完整回读与发送前核验

基线：`0.4.96` / `523c0a52148010110ac64d1a1e124dfc47689bc1`。

## 已接入的生产路径

- 新对话通过 `search_history` 定位历史消息，支持中文分词、已知人物别名和结果分页；`read_history_message` 按原消息版本分页读取全文。原消息继续保存在原数据库中，摘要不替代原文，也不改变讨论、候选或正式事实的性质。
- 分页位置以 Unicode 码点计数，返回总长度、起止位置、完成标志和下一页游标。游标绑定聊天、消息和内容哈希；重启后可以继续，原文变化时拒绝混读。已读原文也是后续请求和工具执行的版本依赖。
- 新清单由上下文编译器建立。阶段必读文件继续使用现有阶段选择；S09/S10 另外从本章相关实体的有效事实中补齐状态、信念、伤势、物品和未完承诺，独立于普通检索排名。仍遵守世界、时间线、历史有效位置、证据和人物知情范围。
- 裁剪只处理可选资料。必读资料不完整、版本改变或必读内容超过模型容量时停止；不会悄悄使用其他章节替代。可选经历被裁掉后，同时移除对应的悬空引用。
- 统一模型网关在序列化和缓存转换后，核验 Chat、Responses、Anthropic、Gemini 实际请求中的原文、范围、事实、作者要求、配置、已确认章名及修订保护内容。核验失败时不发送远端请求，不新增收费请求记录。
- 请求证据绑定最终请求指纹，并保存在本地。独立审核、严格逐场生成等已有专用合同继续使用各自的范围校验，不强塞整章写作材料。
- “本次召回资料”增加默认折叠的必读清单；打开面板只读取本地资料。

## 兼容性

- `ContextManifest.readPlan`、`ConversationTurn.historyReadVersion/historyReads` 都是可选字段。无新标记的旧请求可继续沿用旧规则；旧历史工具保留原参数合同及数组回执。
- 仅调整轮数或费用上限后，继续原任务时刷新工作中的资料包。原始请求账本、模型回执、候选、任务编号和累计预算不变。
- 已更新生成的 IPC 合同，保证必读清单和历史依赖能通过接口到达界面，而不会被输出解析器丢弃。
- 未迁移或改写作者作品、正文、既有任务及提示词资源。本轮构建产物尚未打包安装。

## 成本与边界

- 必读清单和核验元数据只在宿主使用，不追加到专业提示词；正常创作流程不增加模型调用。此前可能遗漏的关键状态会增加必要输入，不能把补齐资料宣传成必然降低 token。
- 历史定位和读取本身均为本地操作。模型决定翻页时仍占用原对话的轮数、工具数和输入预算；不会无限读完后绕过预算继续请求。
- 搜索使用本地关键词、分词和已知别名，不宣称实现任意语义问题的百分之百召回。已有语义检索配置未改动。
- 核验能证明宿主登记的必要内容进入了实际请求，不能证明模型已经理解每项资料，也不能证明未结构化、未检索到的事实不存在。
- 未执行本轮付费模型质量评估或真人阅读对比。番茄风格提示词的改写另作提案，本轮不替换运行资源，不宣称已获得商业成绩改善。
