- 当前 `TitleMarketResearch.sources` 只有书名、链接和可选摘录，没有可核实的独立卷名字段。不能把书名当卷名，也不能凭官方链接声称已经阅读目录。

## 2. 公开资料与适用边界

本次打开了以下番茄官方作品页。访问日期代表本次检查日期，不代表作品发布时间、榜单名次或热度：

- [重生末世：从打造最强基地开始](https://fanqienovel.com/page/7323881715288509502)：目录包含“绿源”“最强基地”。其普通人求生、设施经营与基地扩展可作局部表达参考；丧尸、重生等设定不适用于本书。
- [全民求生：开局一个小破屋](https://fanqienovel.com/page/7575881968810740761)：目录包含“全民求生，存活之路”。可证明求生类目录中存在直接交代阶段处境的表达，但一个样本不能代表平台标准，也不自动成为优先仿效项。
- [黑鲸鱼](https://fanqienovel.com/page/7541304024566336537)：目录包含“双面人”“继承者”等。其言情读者方向与本书不同，只用于说明卷名形式有差异，不应进入本书的正向风格依据。

检索也会返回“第一卷”“默认”等无实质卷名条目，以及同人、近似书名、关键词聚合页和质量不足的作品。系统必须筛选，不能把检索到等同于适合借鉴，也不能把平台所有卷名归纳成统一爆款公式。

## 3. 用户流程

用户选择生成分卷大纲后：

1. 从已接受创作方向确定本次检索题材。
2. 自动读取番茄同题材作品与目录，保存可核对卷名和时间。
3. 在原 S05 生成请求中，用同一份资料完成分卷设计与整组卷名。
4. 显示原有分卷容量表和逐卷大纲。用户读内容、满意继续，或在聊天框提出修改。

不新增“审核卷名”“确认参考资料”“通过命名检查”等步骤。联网进度用一句状态提示；来源和时间放在可折叠的“参考资料”中，默认不占据正文。

## 4. 题材定位

- 显式的本次作者要求优先；其次使用最近已接受方案中的读者定位、题材与机制；配置分类作为补充。未采纳候选不能悄悄覆盖既定方向。
- 针对当前书，检索取向应为“都市脑洞 / 大逃杀 / 求生”，可以用“社区、基建、资源争夺”辅助筛选；不能仅因为旧分类是玄幻就查修仙。
- 复用已有结构化字段并记录来源版本，避免另加一次“判断题材”的模型请求。需要从自然语言补充时，在已有的方案生成结果或有界联网请求内完成，而非另起分类任务。
- 搜索请求只发送公开题材词；原文、完整大纲、角色资料保留在本地生成上下文中。
- 题材冲突作为内部检索修正信息保存，不要求用户寻找设置页，也不借此修改用户的全局模型配置或作品事实。
- 定位逻辑由书名与卷名共享，修复书名误搜题材的问题；两种命名仍使用各自的表达规则。

## 5. 真实卷名证据

复用现有搜索连接、请求计量、未知结果保护和持久化机制，扩展命名参考资料能力，不另建一套互不相通的联网系统。

每条卷名样本至少包含：

```ts
type VolumeNameSample = {
  bookTitle: string;
  bookUrl: string;           // 经核验的番茄官方作品页
  volumeName: string;        // 目录实际出现的名称
  directoryEvidence: string;// 最小必要的目录原文
  verifiedAt: string;
  evidenceKind: 'catalogue';
  match: 'same_audience' | 'partial' | 'excluded';
  matchReason: string;
};
```

- 优先检索并读取实际目录；只拿到书页标题/简介，不算取得卷名。
- 对 `/page/数字` 官方作品页作来源核验。关键词页最多用于发现官方作品页，不作为最终卷名证据；同人和近似名作品按实际题材区分。
- 按目录结构区分卷标题和章标题，不能把正文中“第一卷”字样、作者说明、读者评论误识别为目录。
- 排除只有卷序、默认/正文/作品相关等占位标题。搜索中看到其他差的名称可保存为排除证据，不作为正向范本。
- 保存来源内容哈希/引用、题材定位、检索时间和匹配理由。网页内容只作资料，不能成为操作指令或小说事实。
- 目标是取得少量不同作品的有效目录样本；以一个有界检索批次结束，不为了凑固定数量不断查询。公开可获取的匹配卷名不足时，记录“样本不足”，不能伪造。

## 6. 命名方法

S05 的原生成请求内同时完成以下编辑判断，不要求模型输出思考过程或草案池：

1. 先确定每卷真正持续的矛盾、标志性事件/地点、人物选择和阶段回报。
2. 根据同题材样本选择自然的命名方式：事件、地域、争夺目标、身份、悬念等均可，不强制统一为四字名、长宣传句或疑问句。
3. 卷名应帮助读者辨认这一段故事并产生期待；“有水之后”“留下来的记录”这类泛化表述需结合本卷内容判断，不能只因字数少就保留。
4. 只借表达方式，不引入他书能力、系统、设定、人物或关键名称；不能为了吸引眼球承诺本卷没有的胜利，也不能提前把隐藏真相写进标题。
5. 一次比较整组卷名：各卷有区别、有递进，不全部使用同一种句式；大纲中的实际剧情要支撑题面。
6. 用户明确保留的卷名优先。判断不依赖禁词表、词频或“AI概率”打分。

## 7. 请求与上下文控制

- 每个新的 S05 生成批次只做一次有界实时取材，全卷共用；不逐卷搜索。
- 同批修订、查看、恢复复用已保存证据。用户仅要求改名时，不因修辞变化重新检索；作者明确要求刷新或改变题材时才更新。
- 书名资料可以共享连接、定位和已取得的当前目录证据；只有书名列表或题材不匹配的旧研究不能直接复用为卷名参考。
- 原生联网可能增加一轮模型请求；外部搜索连接可由宿主取材。真实成本按实际路径记录，不能宣称“联网零耗时”或把一次批次等同于一次 HTTP 请求。
- 搜索与页面读取总量统一计入工具预算，生成与必要工具留有额度。不因样本不足自动抬高轮数上限。
- 不增加独立卷名模型审核或“AI味修复”循环。在原生成请求内比较、改好再提交。
- 只给生成上下文加入少量有效卷名、匹配说明和必要来源，完整网页留作审计；动态资料放在稳定规则之后，不改变共享缓存前缀。
- 已经发出的未知结果请求继续沿用现有恢复保护，不自动重发。明确搜索失败/禁用则提示未完成实时参考；可保留已有候选或使用标明状态的离线建议，不伪称实时样本合格。
- 单列检索、分卷生成和总耗时；不能以缓存命中率代替耗时或质量验收。

## 8. 结构、兼容与局部修改

- 保持 `05_长篇大纲/分卷大纲.md` 路径、容量表列和各卷字段不变。
- 卷名改动须同步容量表和对应 `## 第X卷：卷名` 标题。只改名称时保持章节范围、容量、事件、人物和伏笔不变，并在本地确认其他字段未漂移。
- 参考资料是生成依据，不插入容量表、不作为故事事实，不污染正文和记忆库。
- 已安装版本不会自动改写旧候选。用户继续旧任务时按旧版本恢复；明确重做卷名或新生成 S05 才启用新规则。
- 客户端运行资源和 Codex skill 的分卷命名规则同步，更新资源锁与兼容指纹。不能只在客户端外加另一套输出模板。

建议实现入口：

- 复用聊天参考资料展示；不增加需要用户点“通过”的审查界面。

验收用例：

1. 本书旧配置为玄幻、确认方向为都市求生时，实际查询和有效样本应符合已确认方向。
2. 实际目录才能产生卷名证据；默认卷、章名、同人错配、聚合页、提示注入均正确处理。
3. 一次生成多卷只有一个取材批次；修订与恢复不重复请求、不突破上限。
4. 改卷名只更新表格和分卷标题；容量与剧情内容逐项不变。
5. 网页不可用、只有旧缓存、请求结果未知时，界面状态与记录如实反映。
6. 正常路径无新增模型审核、无审核按钮；保持 S01—S11 顺序和 skill 输出结构。
7. 真实效果和延迟需经用户授权的独立模型运行才能验收；本设计不宣称已经改善实际生成质量。
