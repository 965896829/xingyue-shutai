# 0.4.79：正文质量工程与成熟 Agent 架构对照

核对日期：2026-10-28。基线：本轮修改前的 0.4.78 源码快照；真实用户项目和模型配置未参与试验。本轮不调用真实模型、不安装客户端。

## 结论与边界

换执行框架不能直接获得真人文风。Pi 已在 0.4.78 接管新任务的执行循环，客户端仍应负责作品状态、Skill 契约、上下文、工具授权、预算和恢复。本轮在这个分工上补齐正文证据交接和可重复评测，没有叠加另一套总控。

“完全消除 AI 味”“达到商业成稿标准”不能通过词频或单元测试证明。工程层能验证资料是否完整、引文是否真实、请求是否重复、恢复是否安全；人物是否鲜活、语言是否自然、读者是否愿意追读，仍需要真实正文的阅读评审。不能用本轮离线通过率冒充模型文学能力、实际缓存命中率或商业收益保证。

## 确认的问题与修复

### 1. S10 人物表达字段会在交接中消失

原代码从 S10 起排除大多数 `04_` 记忆文档，依靠结构化事实与摘要承接。这可以降低输入体积，但“说话风格”“做事风格”等卡片字段并不必然变成事实，首章尤其没有正文事实可代替它们。

新增 `character-voice.ts`：复用已有角色卡解析器，根据任务、当前计划涉及的姓名/别名/编号选取说话风格、做事风格和同义标签。保留逐字原文、码点范围、文件哈希与快照；不装入完整人物库、秘密字段、后期结局或事实块。代码围栏中的示例不会成为人物设定。

这是作者视角的表达资料，不是“人物已经知道”的证据。人物限定视角继续使用原有知情隔离，不通过此路径读入整份角色卡。同文件中无关坏事实仍保留在记忆管理中，不能因为读了两行口吻就变成全章阻断；相关事实、全局规则和身份冲突的原检查保留。

同一份 101 张角色卡的离线前后对照：原人物库 15,259 字节；旧 S10 输入未包含角色口吻，新输入只增加当前角色的 115 字节原文（连同来源元数据，整个上下文从 17,310 增至 17,868 字节）。硬事实、必读事实编号和隐藏信息边界一致。这个实验说明补回了资料，不代表实际模型速度或人物塑造已经通过验收。

### 2. 原本地正文检查主要发现硬性损坏

已有检查覆盖字数、占位、乱码、连续重复字和大面积重复段落。表达规则已经包含文风启发式，但缺少自动提供给审稿的跨章文本证据。

新增 `prose-editorial.ts`：定位本章长段重复、近期已确认正文的整段复用、连续多章相同收尾、密集相同叙述起句及疑似助手开场。证据保存原文、位置和版本；不输出 AI 概率或新增硬错误。

限制也明确：它检测的是少量表面线索，不理解整部小说，不能识别所有套路，更不能单独判断某段照应是否应删。对话口头禅、必要规则解释、回忆与有意复沓必须由现有审稿结合语境判断；单个常用词不构成问题。

### 3. 证据并入原审稿，不加“去 AI 味”调用

`prose-editorial-context.ts` 只在本地比较最近已完成、已确认的章节。未确认外部修改、待同步前文和人物视角不可见正文不进入比较。模型只收到有必要的有限引文，不再收到整批历史正文。

已有 S10 审稿仍只产生原质量报告，五个依据维度不变：开头有效性、主角主动性、人物一致性、信息落地、章末牵引。最多附入 8 条线索，序列化上限 3,600 字符，再按实际模型输入及费用预算缩减。不会为放入可选线索挤掉正文、作者要求或计划。没有线索时不增加该提示字段。

本地完整结果保存在运行事件 `editorial-evidence`，包括输入版本、比较范围、附入/省略数量，新增模型请求数固定为 0。线索不直接改变任务状态，不增加按钮，不产生新阶段；只有原有审稿发现确有实质问题时，才按原修订限额处理。

### 4. 从“规则很多”改为“行为可验证”

新增 `npm run eval:prose`。18 组原创合成样本覆盖悬疑、都市、生活、玄幻、历史、科幻、情感与职场，验证具体线索及例外。输出完整输入、原文引文、判定、耗时和测试集哈希。该脚本没有模型客户端，也没有在线运行开关。

额外回归覆盖：Unicode 定位、未确认稿隔离、人物视角隔离、容量不足回退、角色表达交接、坏证据隔离，以及 S10 写作—审稿—记忆调用次数保持不变。打包验证通过本机合成 HTTP 服务调用实际打包后的 Worker，不连接用户模型。

## 流程和兼容性

- S01—S11 阶段、Skill 模板、目录、正文格式和五项审稿结构均保持原样；Skill 文件按字节比对。
- 保留 Pi 总控、原工具网关、请求去重、预算和未知请求禁止自动重发策略。
- 保留已有项目、模型配置、候选、恢复和 Legacy 任务兼容，不对用户项目执行迁移脚本。
- 新增来源依赖是可选字段，旧任务没有此字段仍能读取；已开始的审稿不插入新提示，不增加已发请求。
- 本轮没有增加生产依赖，也没有修改用户的联网命名配置。平台书名/卷名参考仍由原有联网命名流程负责。

## 下一次真实正文验收应回答什么

默认合成项目实际启用的表达规则为正文 192 条、审稿 204 条，对应提示分别为 51,902 与 55,264 个 UTF-8 字节；905 是规则库总数，不是每轮全部执行数。这些规则可能带来输入成本和注意力竞争，但“它们导致文风变差”目前仍是待验证假设。本轮保持规则与例外不变；若要进一步精简，需要同模型、同章纲的分组盲评，不能用提示更短就推断质量不降。

离线工程验证与真实写作验收分开记录。后者须固定模型、题材、作者偏好和计划版本，在项目副本对同一组章纲分别生成，再隐藏版本名阅读比较。至少包括开篇、过渡/日常、冲突、情感和结算章节；不能只拿一章强情节判断整本书。

评审记录具体原句及原因：角色是否有不同的目标与说话习惯，行动能否导致后果，解释是否适量，承诺是否兑现，静场是否有效，结尾是否贴合本章。另记录硬事实错误、返工次数、模型总请求、实际墙钟时间和服务端缓存读数。未知缓存数据记为未知，不能填成 0 或 100%。

本轮按用户此前要求不跑真实模型，因此不宣称正文已通过商用质量盲评，也不宣称真实生成提速或缓存达到某个百分比。安装包与完整测试证据在 `output/agent-engineering-0.4.79-20261028/` 中单列。
