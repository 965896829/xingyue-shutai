# 0.4.63：阶段交接、记忆隔离与精确修复

本次在现有执行器上改进三个环节，保留 S01—S11 职责、作者采纳边界、正式版本及事务提交方式。已有工作树改动保留，测试只使用隔离作品。

## 上下文交接

规划阶段原有 80% 容量保护继续生效。新增效率交接只在新阶段首次请求、上一阶段已采纳、工具历史闭合且当前完整资料可无损重建时启用。移出的可读旧执行文本至少 32 KiB，且占旧文本至少 25%，才建立检查点；短历史、当前任务工具链、不透明推理长度单独膨胀均不触发效率交接。

这些门槛是限制陈旧文本积累的保守工程策略，不是测得的最优延迟阈值。记录两种请求视图的文本字节数、差值、来源绑定与选择原因，不把字节数冒充服务端 token 数或缓存命中量。当前来源、作者原始要求与补充、草稿和审核输入保持原样；旧完整记录继续保留。检查点持久化后在重启和续轮时稳定复用，不新增摘要模型调用。

效率交接接入现有 Responses 缓存会话路径；其他模型协议继续使用原有上下文编排。重建前缀可能降低一次请求的缓存命中，需结合实际耗时和用量评估，不能将移出的字节数直接换算成提速。

## 记忆问题的影响范围

重建索引时继续保存旧版 `memoryIssues`，另保存版本化的派生诊断，包含问题类别、来源文件与原事实的实体、时间线及章节范围。当前任务按已加载资料、实体编号及章节范围隔离不相关的证据错误，失效事实不会进入检索结果；原问题继续在记忆管理中可见。当前生效但缺少实体编号的旧事实不能仅凭姓名未出现而跳过核对。

当前人物、全局规则、当前实际装入的文档仍须核对。重复身份、无法解析的事实文件、无法确定范围或过期的诊断保持阻断。任务启动、采纳后进入下一阶段与实际上下文编译共用同一范围判断；显式请求记忆同步仍处理完整待办。前文修订的待核对状态不在本次放宽范围内。

## 局部修复

普通检查结果增加可选事实编号。独立审核保留经过验证的原始条目编号，避免同名人物的多条事实只能靠文字描述区分。新版修复范围分别列出允许修改的文件与事实，并冻结其他内容。未知位置的问题不再授权修改全部候选；新增旁路文件、大小写/相对路径别名和改写其他事实均受检查。

仅在明确尚未完成的记忆提取中允许补充新事实。没有可定位目标时保留候选与诊断，不循环发起整批重写。旧审核记录无目标字段时保留兼容处理；旧修复检查点沿用原来的候选保护，下一次验证修复时生成新版完整范围，不把旧版未记录的字段误当成禁止继续。旧作品的正式文档不做迁移。IPC 输出契约同步生成，新增字段均为可选。
