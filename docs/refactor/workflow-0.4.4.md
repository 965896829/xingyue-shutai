# 0.4.4 阶段流程简化

2026-10-11。作者反馈客户端确认过多，希望恢复原Skill“展示阶段结果，确认是否继续”的体验。本轮在既有页面内合并操作，保留配色、样式、图标、侧栏和文稿面板，没有新增代码注释。

## 问题与结果

原Skill要求按阶段推进，信息足够时不要为小问题打断，只有会改变作品方向的缺口才询问。客户端将输入保存、方向选择、逐条设定意见、契约整理、跳页采纳和下一阶段启动分散给作者；普通阶段虽然能启动下一项，界面仍可能选中旧任务。

| 之前 | 现在 |
|---|---|
| 修改输入后先点保存，再点开始 | 点击“开始策划”时保存并校验输入；单独保存仍可展开使用 |
| 每条关键假设都必须输入文字 | 展示所选方向的设定，一次明确确认；只填写要修改的部分 |
| 必须先点击某方向才能看到确认区 | 推荐方向预选显示，可切换；未点击确认不会保存为作者选择 |
| 审阅契约后跳到任务页采纳，随后另启下一阶段 | 当前页展示完整设定拆解，点击“确认并继续”保存并启动下一阶段 |
| 下一阶段已启动，页面仍可能显示上一项 | 确认后选中新任务并显示当前阶段 |
| 恢复、重建、复查按钮与正常确认并列 | 普通审阅时折叠辅助操作；异常任务展开恢复入口 |

新书策划仍保留一次方向确认，以及一次设定结果确认，因为生成后的实际文稿需要作者看过再保存。后续正常阶段只有“确认并继续”与“保存，暂不继续”两个主要选择，不自动连续采纳所有阶段。旧书接入与修订只保存当前约定，不推进已有阶段。

## 实现边界

- `TagWorkspace.tsx` 合并保存与开始，在当前页展示设定，使用已有Markdown样式；旧数据中文显示逻辑继续保留。输入有未保存改动时不能确认旧结果，可直接按新输入重新策划。
- `App.tsx` 统一接受回执处理，选择服务端返回的新任务；从聊天任务卡启动标签策划时直接进入对应页面。辅助操作仍可访问，已有阶段任务未完成时不能从输入栏重复启动。
- `tags.selectDirection` 新增可选的明确集中确认标志，仍核对报告指纹、审核回执和所选方向。仅填充适用设定中没有修改意见的条目，不覆盖作者修改，也不默认确认其他方向。旧调用缺少关键意见时仍拒绝。
- `run.accept` 沿用正式提交路径和下一阶段能力，下一项启动回执与原操作保持一致。启动失败时明确返回“本阶段已保存”，避免让作者误认为采纳失败而重复操作。
- 生成提示不再要求对已经明确的要求与配置重复询问；普通创作细节形成候选统一审阅，重要缺口集中提问。规则不授权自动改变核心设定或跳过作者接受。

没有改变数据库、项目或IPC版本，没有新增依赖，没有改动原Skill资源和 `agent.md` 加载链。审批指纹、独立审核、预算、未知请求重试、外部修改冲突与有警告时的保留理由继续有效。
