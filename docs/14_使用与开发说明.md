更新于 2026-10-08。Windows 桌面开发验证版。当前交付与未验收事项见[实施记录](13_实施记录与验收状态.md)，原需求没有因为分期实现而取消。

当前规则修订为 `2026-10-08-r2`，采用作者的全题材命名 v2.0，通用约束常驻、相关题材与标签按需读取，阶段顺序保持不变。命名 v2.0 在 0.1.10 已完成安装核对，0.2.0 继续保留这套完整规则。新任务自动读取新版；旧任务提示规则变更时，选择“重建上下文 / 用所选模型继续”，不要把旧候选当作已经按新规则改好。该操作会调用 API。详见[命名系统升级与兼容检查](17_命名系统v2升级与兼容检查.md)。

## 1. 安装与第一次写作

运行 `release/文序 Setup 0.2.0.exe`，选择安装位置。也可以保留整个 `release/win-unpacked` 目录，运行其中的 `文序.exe`。这两种方式均不要求安装 Node.js。安装包尚未签名，本机验证环境为 Windows 10 x64；Windows 11 仍待环境验收。

界面参考 DeepSeek Harness 官方桌面预览，使用灰蓝侧栏、居中聊天区和圆角输入框。右上角的“夜间 / 日间”按钮切换深灰或浅色外观，操作按钮使用蓝色强调。首次启动默认为夜间，以后记住本机选择。编辑器、差异、模型设置、记忆与封面页面同步切换，已输入的任务与编辑草稿不会被清空，也不会调用模型。封面画面和导出文字颜色仍由封面设置控制。

左上角按钮可收起侧栏，收起后将鼠标放到图标上可查看功能名称。“创作流程”展开或收起 11 个阶段。文稿面板默认收起，点击左侧文件、候选文件或右上角“文稿面板”打开；原有编辑、差异、预览和历史入口均保留。阶段确认和正文授权方式保持不变。

开发者修改外观时，统一配色入口是 `src/ui/themes.css`，布局和组件样式是 `src/ui/styles.css`。本机偏好由渲染器的 `wenxu-color-mode` 保存，与作品和 API Key 分开。

0.1.5 将原来的系统白色标题栏和菜单栏整合为一条随主题变色的顶部栏。窗口按钮使用 Electron 的原生覆盖层；拖动顶部空白处可移动窗口。点击“文序 / 编辑 / 视图”使用原菜单，也可按 F10 聚焦菜单后用方向键选择，Alt+W / E / V 直接打开。打开表单弹窗时菜单仍可使用。窗口外观缓存另存应用数据目录的 `appearance.json`，用于启动时恢复配色，不包含密钥或作品。

0.1.6 将输入框的操作收拢为底部一行：左侧书本按钮查看召回资料，旁边选择当前阶段或“修订资料”；右侧选择模型，点击圆形 ↑ 确认开始，运行时改为 ■ 停止。把鼠标放在图标上可查看说明；输入框下方明确显示开始授权提示。回车只换行，不自动生成。较长的模型名称会截短显示，悬停可查看完整名称，列表仍保留供应商区分。

1. 新建作品，填写书名、原始设定和保存位置。预览创建目录，不调用 AI。正式目录含原 Skill 的 24 个初始 Markdown，另保存作者原始输入。
2. 打开模型设置，选择 Chat Completions、Responses、Anthropic Messages 或 Gemini 协议。填写根地址和 Key，移开输入焦点后自动获取模型列表；勾选需要的多个模型，再保存配置。搜索只过滤列表，“全选当前结果 / 取消当前结果”只作用于搜索结果。列表不可用时可手动添加模型 ID。Key 由 Windows 加密保存在应用设置中，不保存在作品内。
3. 分别测试文字与工具续轮。模型能回答问题，不代表它支持客户端需要的工具循环。测试按钮会调用你配置的服务，按该服务计费；已单独验证本机 Sub2API / gpt-6.1-sol，其余端点应分别测试。
4. 默认进入“创作讨论”，选择模型、输入想法并发送；不会因为闲聊启动阶段。需要执行时先审阅任务卡，点击确认后再生成。显式阶段入口在“创作工具”或“历史任务与阶段执行”。可按规划、正文、审阅、记忆阶段设置不同配置。
5. 点击候选文件查看差异。阻断问题必须修复；非阻断警告需要填写保留理由。可“只接受并暂停”，也可“确认结果并开始下一阶段”。后者同时授权下一次模型调用。
6. S10 正文接受后显示待章后同步；S11 记忆与台账接受后，章节才完整完成。不能把正文文件存在当作已完成章节。

参数初值为 300 万字、每章 2500 字、合格范围 2300—2700、每批 30 章。更改章长时请同时填写上下限。未规划批次可调整；已经批准的批次范围保持，新的批次大小从下一批生效。末批可以不足整批。

同一供应商的模型共用根地址、协议、Key、代理和请求头。在“正在配置的模型”中切换后，容量、输出上限、流式、工具能力、价格、超时和图像参数只对该模型生效；测试按钮也只测试当前选中的模型。每次写作仍选择一个模型，不会同时调用所有勾选模型。

0.1.8 起，新模型默认“跟随官方上限”。已核实的模型自动填写最大上下文、最大输入（官方单独声明时）和最大输出，并显示来源和核实日期。gpt-6.1-sol 对应 1,050,000 / 922,000 / 128,000 tokens。这些是容量上限，不是每次必须生成的字数；输出可能包括推理消耗。中转若另有限制，可以关闭跟随后手动填写，刷新模型列表不会覆盖手动数值。价格仍按实际服务填写。

已有的已匹配旧模型启动后自动升级，原密钥和选择保留；升级前设置备份位于 settings.json.before-official-limits。容量变动会清除旧测试结果并增加配置版本，因此中断任务可能需要重新组装。未知新模型不会套用通用值冒充官方上限：跟随模式显示空白并提示未核实，需要刷新或手动配置；旧未知模型保留原有手动值。图像配置不显示文字 token 上限。

OpenAI 使用已核实的文档注册表（src/shared/official-model-limits.json，随程序更新）；直连官方 Gemini、Anthropic、DeepSeek 接口时，支持从模型列表获取容量字段。来源日期可查看，不保证任意中转别名自动识别。Gemini 的输入、输出上限分别管理，显示的预算总和不是厂商声明的共享窗口。

取消勾选后保存，会将模型从写作选择列表隐藏，但保留它的参数和历史引用；重新勾选恢复原配置编号。依赖该模型的旧任务需要重新启用它，或另选模型重建任务。至少选择一个模型才能保存；删除整个供应商另有确认操作。刷新列表、搜索和重开客户端不会清空已保存的多选结果。旧版单模型连接升级后保持原模型与密钥，不自动替用户启用全部模型。

## 2. 编辑、版本和冲突

0.1.9 增加两类交互：对话左侧的横线导航按实际存在的任务、回复、候选、检查、日志和确认内容显示，当前阅读位置高亮，点击只滚动聊天区域，不表示模型生成百分比。空白任务不显示横线；切换历史任务时重新建立导航。

供应商条目、作品条目和“放弃候选”采用作者提供代码改造的垃圾桶动画：点击展开橙色确认和取消按钮，Esc 或移开焦点也可取消；处理期间不可重复提交，成功后才显示完成。删除供应商会移除其全部模型配置及保存的密钥，供应商不进入作品回收站。放弃候选不删除正式文件，也不清除任务审计记录。

作品删除会关闭该作品并将整个目录移入同一磁盘的 `.文序回收站/编号/作品`，从删除时起保留七个完整的 24 小时。侧栏“回收站”可查看到期时间并恢复到原位置；原位置有同名目录时不覆盖，可以选择同一磁盘的其他父目录。回收期内保留正文、候选、历史、连续性和编辑草稿；当前未提交的任务输入会清空。到期永久清理回收目录，随后清理对应编辑草稿缓存；若另一个已登记的备份副本共用旧项目 ID，则保留其共用草稿。单独保存的备份、导出文件不会删除。

客户端运行时每分钟检查到期项目，关闭后没有后台进程，下次启动时清理。回收日志存于应用数据目录的 `recycle-bin.json`；移动、恢复、清理均先记录状态，遇到磁盘不可用、目录被占用、路径或身份校验失败时保留记录并提示重试。清理开始后可能已删除部分文件，因此该状态不能恢复为完整作品。请勿直接打开或修改回收目录；从客户端恢复后再编辑。跨磁盘迁移请先恢复，再使用备份和备份恢复功能。

编辑器中的修改先保存在本机草稿缓存；“保存候选”创建待审版本，接受后才写入正式稿。候选接受之后，继续修改请从左侧重新打开正式文件。

可以在其他编辑器修改 Markdown。客户端自动检查外部改动；接受任务时再次核对输入文件和输出基础版本。发生冲突时查看基础、磁盘、候选三种内容，先接受或修订外部变化，再重建依赖旧资料的任务。不要用复制旧稿覆盖新稿来消除提示。

历史版本保存于作品的 `.novelclient` 中。版本恢复也先生成候选。该目录同时保存数据库、提交日志、检查点和写锁，请勿随意删除。修改早期正文后，相关档案和后文会列入待核对；逐项检查、修订或记录无需修改理由，才闭合影响记录。

工作区一次打开一本书，多本作品各自保存数据库与正式事实。导入旧 Skill 档案时创建独立副本，先预览再指定续写章与阶段，原档案保持原样。旧台账没有结构化来源时显示待核对，不能假称已转换为可靠事实。

## 3. 三层记忆怎样使用

| 层级 | 当前实现 | 作者可以检查什么 |
| --- | --- | --- |
| 瞬时 | 运行目标、原生协议消息、工具回执、候选、问题、授权、暂停点写入 SQLite | 任务记录、过程、错误、候选 |
| 短期 | 当前阶段必读文档、上章正文、当前批次资料、近期章节更新；近期窗口可调 | 上下文清单、完整或摘录、来源版本、未采用原因 |
| 长期 | 正式 Markdown 中的设定与有来源事实，SQLite 可重建投影 | 人物、关系、物品、伤势、伏笔、知情、历史事件及原文摘录 |

长期记忆检索使用实体 ID、中文名与别名、关系一跳、FTS5 和短词补查。**当前没有向量数据库或 Embedding 请求**；向量是需求允许的可选增强，不是可靠记忆的前提。必要限制先装入，再补充相关历史；不会仅因旧伤超过最近三章就删除它。

正式事实记录事实性质、故事时间、揭示章、接受版本、知情范围、来源路径、哈希和摘录。模型仍可能误解原文，程序检查“有这句话”不能证明“这句话支持该结论”。作者要审核事实含义。计划、人物误解和推断不是客观事件。

当前使用保守的完整请求 UTF-8 字节预算估算，必要资料装不下会暂停。不会偷偷截去关键设定。可删减不必要任务要求、选择更大上下文模型或停止后重新组装上下文。尚未实现经过完整覆盖评测的自动有损压缩，也不承诺任意长度作品都可持续生成。

## 4. 接入、费用和停止

- 端点填 API 根地址，不要同时追加完整请求路径。中转名称不等于协议兼容证明。配置修改后能力测试结果失效，应重新测试。
- 用户可填写输入和输出单价、币种、阶段预算。缺少计量或请求结果未知时显示未知，不假报为零；开启硬预算时不能继续盲目累计。
- 停止会取消本地等待，但服务商可能已经处理并计费。超时、流式中断、未知结束原因不会自动重发收费请求。
- 恢复先核对模型配置、Skill、输入版本和工具回执。切换模型使用重新组装的新任务，保留旧任务用于回查。
- 运行诊断省略密钥、工具结果与终端脚本内容；作品标题等基本信息仍在报告中，分享前可自行查看。

## 5. 终端、联网和封面

终端脚本、联网操作通过任务中的具体权限请求执行。作品设置可选择询问或禁用，默认询问。界面列出实际命令或 URL；安装依赖也走这个通道。

终端进程具有当前 Windows 用户权限，工作目录限制不是操作系统沙箱。已经执行的安装或外部修改不能靠撤销候选恢复。模型提出的文件候选则仍须接受才进入正式稿。

封面使用独立 Images 配置，当前适配 OpenAI Images 兼容接口；不是所有文字协议都自动支持生图。背景生成后，书名、作者、字体、颜色、大小和位置在本地调整。保存得到 PNG 与可重新编辑的 JSON 图层配置。图像调用结果未知也不会自动重发。图像服务真实端点未在开发中调用。

## 6. 导入导出、备份和恢复

MD/TXT/DOCX 导入先预览。TXT 支持 UTF-8 和 GB18030；DOCX 支持正文、标题、基础列表和表格，批注、修订、图片、域与复杂排版显示警告。导出只取选定文件的正式版本，按章节自然数字顺序排列，目标文件已存在时拒绝覆盖。

指定自动备份目录后，接受正式变更会尝试完整备份。备份包含 Markdown、数据库和历史对象，附内容校验清单，不含应用全局 Key。备份失败单独报告，不把已经提交的正文说成未保存。恢复到新目录，校验清单异常时停止，不覆盖原作品。

| 情况 | 处理 |
| --- | --- |
| AI 请求中断 | 查看未知费用提示，核对记录后选择恢复或重建任务 |
| 外部文件变化 | 比较并接受外部修改，再核对受影响的任务与事实 |
| 提交期间程序崩溃 | 重新打开作品，提交日志恢复；遇到第三个外改版本保留并报冲突 |
| 缺少初始文件 | 使用档案检查与修复，预览缺失项，修复候选不覆盖已有稿件 |
| 早期正文改写 | 先修正文，修订事实与摘要，逐项关闭影响记录 |
| 数据库无法打开 | 从入口恢复完整备份到新目录；不要删除数据库后声称任务记录可重建 |

## 7. 开发与验证

```powershell
npm ci
npm run dev
npm run check
npm test
npm run test:scale
npm audit --omit=dev
npm run dist
```

开发使用 Node.js 24。`npm run dev` 启动 Vite 和 Electron；生产界面走本地文件。主进程仅暴露受限 IPC，业务运行在 utilityProcess，界面无 Node 权限。依赖版本固定在 `package-lock.json`。

`WENXU_DATA_DIR` 可以指定隔离的应用设置目录，便于测试。`scripts/mock-model.mjs` 是仅本机监听的测试服务，不是正式 API。容量测试生成的作品位于系统临时目录，统计见 `.test-output/scale-report.json`。全套测试覆盖范围和没有覆盖的项目见[逐项状态](15_逐项实施与验收状态.md)。

代码当前保存在本地，没有发布 GitHub、上传小说或配置商业后台。开闭源与收费仍未决定。
