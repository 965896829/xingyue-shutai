# 文序 0.2.0：智能体对话与执行分离

日期：2026-10-08。依据：作者本轮明确要求实施的“文序智能体：自由对话、专业创作与 Skill 执行分离”方案。本文记录实际实现与验证，不替代原 180 项长期需求的逐项验收。

## 1. 作者如何使用

1. 打开或新建作品，默认进入 **创作讨论**。输入一句想法、一个人物问题或“接下来应该做什么”，点击 ↑ 或按 Ctrl + Enter 发送。Enter 换行；空白消息无法发送，也不能启动默认阶段。
2. 同一部书可以创建不同主题聊天，并重命名、归档、恢复。切换主题时保留未发送输入；重新打开可以回看完整消息和任务卡。正式作品资料共享，其他聊天的未采纳方案不会自动混入。
3. 对话按需读取本书资料、正式记忆与规则。展开回答下方 **资料与来源** 查看文件、版本或网页；展开 **调用、规则与上下文记录** 查看实际工具、费用与输入预算。不应仅凭模型说“查过”判断已经核实。
4. 整章试写、正式阶段生成和修订会先出现任务卡，显示目标、类型、范围、产物、模型与依据。点击 **确认并开始任务** 才实际执行。聊天里的“开始”只会提出任务，不能代替点击批准。
5. 也可展开输入框上方 **创作工具与引用其他聊天**，显式提出当前阶段、自由试写或正式修订任务。跨主题引用须选择具体聊天；读取其内容并不代表采纳为事实。
6. 试写先显示在聊天里。点击 **保存到自由草稿** 并命名后，保存至 `00_作者输入/自由草稿/`。可编辑、保存版本、回看历史，并重新读取外部修改。未保存的草稿编辑缓存仍保留在本机。
7. 在自由草稿中点击 **建立正式修订任务卡**，填写要转入的文件、范围和保留内容。确认后由原执行器提出正式候选，再通过差异、检查、接受和修订影响核对流程。保存草稿本身不会推进阶段、成为正式事实或使其他正式候选失效。
8. **历史任务与阶段执行** 保留旧任务和原阶段操作。任务卡可直接跳到对应任务；原“确认结果并开始下一阶段”“只接受并暂停”继续有效。每章正文仍需授权。当批规划不完整时原执行器继续阻断正文生成。
9. 候选区增加 **重新检查候选**：只在本机运行校验，不调用模型、不接受文件。原来处于“请求结果未知”的任务仍保持未知；不能借重新检查绕过恢复与费用核对。

同一本书同时只有一个模型任务。尚有候选等待审阅时可继续讨论；新的正式阶段仍受既有待处理任务和阶段依赖限制。停止与失败保留消息、已读来源和工具记录；重发须显式确认，未知请求不会自动重试。试写重试重新建立任务卡。

## 2. 角色与提示词

设置入口：左下角 **智能体与联网设置**。

| 层级 | 实现 | 使用方式 |
| --- | --- | --- |
| 简短常驻指令 | `src/core/conversation-runner.ts` | 讨论与执行边界、来源、事实/建议区分、当前作品概况、适用约定与工具权限 |
| 专业角色 | `src/core/assistant-settings.ts` | 网文编辑、番茄创作、起点创作三套细则；摘要常驻，深入处理时按需读取 |
| 完整 Skill | `resources/skill/` 原九个文件 | 对话按主题/标题/行号读取；正式任务保持原 `AgentRunner` 的完整装配 |
| 命名 v2.0 | 原 `naming-system.md` | 起名时读取完整通用核心与相应题材，再按需取 G/T 模块；没有将整套命名规则塞进每次闲聊 |

使用一个所选模型，不并行调用三个角色模型，也不为每条消息增加独立分类请求。专业角色是判断方法，不声称模型真实取得平台头衔，不能保证签约、收益或文学质量。

三类角色规则可以分别编辑、保存、恢复默认和回退版本。默认文本随程序分发；作者覆盖和版本历史独立保存到应用数据目录 `assistant-settings.json`。升级不覆盖已保存编辑。每轮记录使用的规则版本。修改文本不能改变程序的批准、文件提交和终端权限。

## 3. 数据与执行边界

| 记录 | 存储及职责 |
| --- | --- |
| Conversation | `conversations`：标题、归档状态、联网开关、可回查历史摘要 |
| ConversationMessage | `conversation_messages`：完整原消息、流式状态、所属聊天、来源 |
| ConversationTurn | `conversation_turns`：模型版本、工具与协议消息、费用、规则及预算记录 |
| ActionProposal | `action_proposals`：待确认任务、确认版本、依据和实际执行编号 |
| DraftArtifact | `draft_artifacts`：草稿路径、原聊天/消息、内容哈希和版本；正文为中文 Markdown |

作品 SQLite 从 v1 升至 v2。升级先用 `VACUUM INTO` 创建 `state.sqlite.before-v2-*.bak`，包含 WAL 中已提交内容；建表与版本更新使用事务。已有任务、候选、事实、提交记录和历史不改造成虚假聊天。旧书首次升级创建空的“创作讨论”。

对话工具仅有 `read_book`、`search_memory`、`search_history`、`read_rule`、`read_naming_rules`、`public_search`、`extract_pages`、`propose_action`。不存在“批准自己”或正式文件写入工具。

任务卡确认绑定作品版本、阶段/章节、依据文件哈希、模型配置版本和规则版本。变化后必须刷新并重新确认。已执行卡保存实际执行编号；重复点击返回同一个编号，不再调用模型。自由试写的卡状态与聊天准备记录在同一数据库事务保存；阶段卡与原运行记录也在同一事务保存。

自由草稿从正式目录扫描、正式全文索引和提交服务中隔离；没有新建事实索引。保存采用不可变内容对象、独立版本与可恢复记录。外部改稿后，旧基础哈希不能覆盖新文件。草稿转为正式任务时重新绑定草稿哈希和当前正式资料。

### 上下文与较长聊天

普通讨论默认只携带作品概况、当前进度、文风与作者约定、适用全局持续约束和最近 20 条消息。正文、人物、大纲与其他规则按问题读取，不为了聊天强行填满阶段必读模板。

较早消息保留在 SQLite，生成带原消息 ID 的摘录摘要。作者明确表达的决定标记为“聊天记录，未同步正式资料”；助手文字标为“备选意见，未采纳”；其余保留为讨论或未决问题。摘要只列最近一组旧消息的索引摘录，提示其余消息可检索，不冒充无损覆盖全部历史。原文回查工具受聊天边界限制。

每轮组装实际协议请求并记录容量。当前使用 UTF-8 字节数作为保守上界估算，并非伪称厂商精确 tokenizer 计数；使用量以端点回执为准。关键约定不够装时停止并解释，不静默裁掉继续生成。设了费用上限而价格或费用未知时暂停；搜索额度单独以服务商回执记录，不虚构货币价格。

`KnowledgeProvider` 只预留查询接口。本轮未建设知识库、Embedding、向量数据库或云同步。

## 4. 联网服务

在“智能体与联网设置 → 联网搜索”填写 Tavily 或兼容服务根地址、Key、限额及超时，保存后测试。Key 由 Windows `safeStorage` 加密；界面只显示已设置状态，作品、普通日志和模型提示中不保存明文密钥。修改服务地址需要重新填写对应 Key。

默认每次最多 5 条搜索结果，每轮最多 3 次搜索、3 个网页提取，设置页可以调整。全局开关允许按需联网，每个聊天可以再关闭。连接测试会发起一次公开搜索请求，可能消耗额度；即使关闭日常自动联网，也可显式测试已保存配置。

采用官方 [Tavily Search 接口](https://docs.tavily.com/documentation/api-reference/endpoint/search) 和 [Tavily Extract 接口](https://docs.tavily.com/documentation/api-reference/endpoint/extract) 的请求契约。查询不携带整章原稿；提取限已找到的公开网页，保留 URL 和获取时间。网页只作为外部材料，不获得工具或流程权限。

缺 Key、关闭、失败、限流、达到次数上限和空结果会进入可见记录，并显示未核实提示。不是每个结果都可靠；模型仍需判断来源、时间与适用范围。真实 Tavily 服务未提供 Key，本轮验证的是兼容契约、受控服务和错误路径，不声称已经验证真实 Tavily 账号额度或搜索质量。

## 5. 字段校验修复

`parseMarkdownFields` 按字段块处理同一行、续行和更深层的列表；下一同级字段、标题或代码围栏不会被误并入。纯空白、占位符、未选择状态仍阻断；同一文件同一位置的空字段只报告一次。

截图中的“爽点升级路线”“风险与修正”以嵌套列表填写时不再误报。此修复只判断字段结构，不证明列出的方案有文学效果或已获作者认可。
