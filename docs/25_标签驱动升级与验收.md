# 0.4.0 标签驱动升级与验收

日期：2026-10-10。版本定位：本地开发验证版。保留现有 11 阶段、四协议模型适配、独立业务进程、SQLite 快照及文件提交机制。未调用真实收费模型，文学质量与真实结构化输出仍需联调验收。

## 作者使用方式

新建作品默认选择标签。主分类必选一项，其他七组按界面上限选择；创作想法可空，必须保留和禁区可逐行补充。未覆盖题材选择“原有方式 / 未覆盖题材”。

在“标签与策划”保存输入、检查知识覆盖、选择模型，再点击“确认并开始标签策划”。系统生成三个方向并独立审核；作者可以重做其中一个方向，另外两个保持原样。选择方向并处理其关键假设后，生成该方向专用契约及完整设定拆解，再次独立审核。

作者最后在任务页审阅契约、项目配置映射和设定拆解三个文件差异，点击“采纳契约与设定”。此时一次提交并进入 S02，不自动启动下一阶段。选择方向、模型审核和恢复请求都不能代替这次采纳。

旧书在相同入口主动保存标签、启动接入。报告与审核读取现有正式资料。批准前保持原状态，批准后保持当前阶段与章节，原设定和正文不改写；受影响材料进入原有修订核对流程。未接入旧书继续使用原流程。

## 数据、指纹和恢复

| 对象 | 权威保存位置 | 版本约束 |
| --- | --- | --- |
| BookSpec 草案 | SQLite `tagDraft` | 作品 ID、输入修订号、标签库版本、完整作者输入和参数指纹 |
| 策划报告及审核 | 原运行记录 `Run.planning` | 固定 BookSpec、知识快照、基础正式版本及快照、阶段提示与工具 Schema 指纹 |
| 已采纳契约 | `ProjectState.tags`，随正式快照保存 | 契约修订号、输入指纹、知识版本、采纳人及候选哈希；每项约束由宿主标记作者已确认 |
| 实际兑现证据 | 原有结构化事实 `Fact.tagRefs` | 关联契约修订号、输入指纹、选项和约束 ID；事件仍必须引用正文片段及哈希 |
| 可读契约 | `02_项目配置/标签创作契约.md` | 由结构化记录生成；外部修改不会成为新的正式契约 |

改变想法、禁区或标签都会使旧策划失效。报告诊断项、假设、方向、逐标签计划、契约作用范围及审核 JSON Pointer 均有运行时校验。三个方向各自拥有兑现计划；只有选中方向的契约会正式采纳，未选方向保留在历史任务中。

关键假设必须有作者处理意见；需要确认的诊断必须关联关键假设。语义审核最多一次自动修订，格式错误最多两次修复。生成、审核、局部重做、恢复和模型交接共享原任务轮数、工具次数与费用预算。预算不足保留候选，费用未知不会自动当作零。审核是独立请求，可使用项目的审核模型配置；没有单独配置时使用当前模型重新审核。

取消后的迟到模型返回不能成为可采纳候选；未知请求重试沿用现有明确确认。重启保留阶段与候选，批准仍检查完整输入绑定、基础版本、依赖文件和候选哈希，重复采纳不重复提交。备份和恢复包含数据库、标签草案、报告、已采纳契约及证据。标签项目使用项目结构版本 2，未接入旧书仍为版本 1；旧客户端不能直接打开版本 2 项目。

契约展示文件只读，修订通过标签策划进行。文件在外部被删除或修改后，标签页提供“从正式记录恢复契约展示文件”；恢复前再次核对磁盘哈希。

## 11 阶段与上下文

S01 使用独立标签子流程；S02—S11 保持原产物及正文审核流水线。已批准标签、作者约束、结构化范围、确认意见及兑现计划进入系统必需上下文；契约 Markdown 也进入必读依赖，不随可选聊天历史截断。人物视角同样保留作者约束，但不得把这些约束当作角色已知事实。

S02 对齐当前参数，S03 落实能力和世界规则，S04 落实角色关系与知情范围，S05—S08 分配大纲承诺，S09 选择本章相关承诺，S10 按契约写作与审核，S11 从正文登记实际兑现。不会要求每章机械展示所有标签。

篇幅、视角、文风、项目硬约束仍由项目配置管理。BookSpec 固定生成时的参数快照；之后以当前项目配置为准，重做策划前须重新保存输入。主分类在采纳时明确映射到现有 `config.genre`，由原命名模块的标签映射预载规则；`optionId/conceptId` 不当作命名 G/T 或自然表达模块编号。

契约变更差异按已有兑现证据和生成依赖标明已知关联，其余资料标为待人工核对。当前没有完整的逐约束章节依赖图，因此影响范围保守扩大；不会声称已经精确定位所有受影响章节，更不会自动重写正文。

## 资源和接口

固定资源位于 [resources/skill/tags](../resources/skill/tags)。实际内容为 482 个唯一选项、19 个题材基线、25 张概念卡、8 条规则、4 个配方。首版沿用提供的八组上限与固定版本；精确配方必须满足主分类及全部概念条件，部分命中只列为候选提示。

25 张概念卡只覆盖其中 32 个选项。界面区分详细知识草案、题材基线草案与仅登记信息，未声称全部有专业知识。知识是建议，作者意图优先，例如不能因“科幻末世”主分类强行加入灾变。它是本地快照，不同步番茄后台。

资源锁校验全部资源 SHA-256；安装包沿原 `extraResources` 包含资源，离线可读取。`scripts/check-deliverables.mjs` 核对源资源与打包资源逐文件一致。

新增 IPC：`tags.catalog`、`tags.validate`、`tags.saveDraft`、`tags.start`、`tags.selectDirection`、`tags.reviseDirection`、`tags.diff`、`tags.restoreProjection`。`run.events` 按任务分页读取持久化历史，实时事件仍使用原机制。聊天任务卡创建的执行记录保存来源聊天 ID。

核心实现见 [结构定义](../src/shared/tags.ts)、[确定性编译与校验](../src/core/tags.ts)、[S01 子流程](../src/core/tag-planning.ts)、[界面](../src/ui/TagWorkspace.tsx)、[自动测试](../tests/tags.test.ts)。
