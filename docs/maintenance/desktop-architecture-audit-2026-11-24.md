# 星月书台桌面客户端架构审计

本页按轮次保留验收结果。当前开发版为 **0.4.98-macos.5**，最新结果见文末「Mac 开发与第一章恢复」。日常启动和打包步骤见 [Mac 开发指南](../macos-development.md)。

2026 年 11 月 24 日。审计对象为本机 Apple Silicon 客户端，基线版本为 0.4.98-macos.2，修复版本为 0.4.98-macos.3。

**本机写作和恢复流程通过了本轮验收。公开分发仍有两项门槛，包括正式发行签名，以及 Windows 和 Intel Mac 上对同一版本的验证。** 最值得修的是作者可能直接承担损失的几条路径。旧版遇到目标作品损坏时会先关闭当前作品，两个同名 Word 导出可能互相覆盖，备份也可能漏掉作者自己命名的文件。已有的回归测试在改动前全部通过了可在本机运行的项目，这些边界仍需要单独验证。

## 架构和功能覆盖

桌面窗口和浏览器管理后台共用一组命令契约。桌面主进程负责系统对话框、文件授权和密钥，业务工作进程负责作品、任务和数据库，独立文档进程负责导入解析。作品包含可阅读的文稿、SQLite 数据库和保存历史内容的对象库。一次保存能否恢复，取决于这三部分能否对应到同一个版本。

从桌面界面、后台界面、主进程、预加载桥接、业务进程和文档进程六个入口追踪，共覆盖 420 个生产 TypeScript 模块，包含类型引用。命令表有 182 项，其中 126 项绑定作品，56 项属于全局。原生验收通过桌面桥接调用了其中 20 种命令，其他路径分别由源码检查和自动化测试覆盖。

桌面窗口已启用沙箱和上下文隔离，关闭渲染端 Node 访问。主进程同时核对窗口与主框架来源。浏览器管理后台绑定本机地址，写请求校验来源和会话令牌。这些是应当保留的权限边界。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

## 已修复的问题

| 优先级 | 用户会遇到什么 | 修复和验证 |
| --- | --- | --- |
| 高 | 打开损坏或被占用的作品，会失去当前作品的编辑会话。导出尚在写入时也可能切走作品。 | 先验证目标数据库、历史对象和快照，再交接原会话。作品操作在执行期间绑定原作品。验证了目标损坏、目标被占用和导出期间切换三种情况。 |
| 高 | 客户端异常退出后，两个进程同时接管遗留占用锁，可能同时判断自己可以写入。 | 接管阶段使用由操作系统释放的 SQLite 写锁，持锁后重新核对原占用记录。验证了接管互斥、释放后重开以及正常持有者受到保护。 |
| 高 | 两次 Word 导出都可能在写入前看到同名文件尚不存在，随后互相覆盖。 | 完整文档先写入临时位置，发布时独占目标名称。在隔离目录同时导出两篇不同稿件，只有一篇成功，成功的一篇可完整导入。 |
| 高 | 作者自己的文件可能因名字类似内部数据库而漏备。备份清单与作者文件同名时会发生冲突。恢复中断还可能留下半成品作品目录。 | 排除范围缩小到客户端控制目录。发生清单撞名时使用独立的文件目录，继续支持原备份格式。还原时逐文件校验实际复制的字节，再检查 SQLite 和引用对象，最后发布完整目录。 |
| 高 | 旧版随应用分发的 Electron 44.6.0 位于上游高危证书公告影响区间，单查生产依赖会漏掉它。 | 升级到同一主版本的 44.11.5，并更新受影响的构建依赖。完整依赖和生产依赖两种审计口径均已复查。 |
| 中 | 同一批任务在启动过程中继续排新任务，可能导致队列中的任务被启动两次。不同作品使用同一个操作编号时，也可能收到对方的待处理结果。 | 先为本批任务预留资源，再执行回调。进行中的操作按数据库隔离。验证了嵌套调度和两个独立数据库各自的去重行为。 |
| 中 | 从作者视角切换到读者、人物或历史范围时，旧检索结果可能继续显示。重复句子的证据也可能跳到第一次出现的位置。 | 检索结果绑定作品会话、快照、章节和视角。作者计划及维护操作只在相应范围展示，文稿引用保留原文起止位置。已在原生窗口切换视角。 |
| 中 | 不同浏览器会话使用的等待编号可能进入同一张宿主等待表。 | 每个浏览器会话独立维护等待编号到宿主编号的映射。取消、断开、撤销都按所属会话处理，并覆盖正常取消回归。 |

SQLite 在线备份取得数据库快照。客户端额外核对外部历史对象和文稿，弥补仅复制数据库无法涵盖整部作品的问题。普通备份沿用原格式，只有作者文件与清单撞名时产生的新格式需要本版或后续兼容版本还原。[SQLite 在线备份说明](https://www.sqlite.org/backup.html)

Electron 上游将 44.9.1 列为这一主版本的修补起点。基线的完整依赖审计报告 9 个受影响包，其中 2 个高危、7 个中危。修复后为 0 个已知受影响包。该数字反映此次锁定依赖与当日公告库的比对结果。[Electron 上游公告](https://github.com/electron/electron/security/advisories/GHSA-jr5w-w6x2-84p9) · [npm 审计说明](https://docs.npmjs.com/cli/v11/commands/npm-audit/)

## 代码与安装包清理

- 故事变更的后续审阅原有两份相同实现，现由同一个函数负责。移除了已退役的实验室事件类型，以及恢复流程合并后失去调用方的数据库检查包装函数。
- 实验室长文目录改为单次扫描。含 2,500 个同级小节、嵌套标题、代码围栏、生僻字和不同换行方式的样本保留了正确的原文范围。
- 旧版应用归档附带 7 个源码映射文件，共 35,395,101 字节。本版归档包含 0 个。业务归档由 53.0 MiB 降至 19.2 MiB，减少约 64%。这个比例只计算应用归档，Electron 运行时另计。
- 420 个生产模块均能追溯到入口。另核对了 5 组大于 1 KiB 的相同资源，它们分别由创作操作目录、运行时资源锁或参考资料直接引用，保留现有路径。旧执行器、数据库迁移和作者作品均有独立用途。本轮生成的 1,645 个隔离测试目录已移出项目工作区，临时目录中仍可查阅。

## 距离公开发行还差什么

1. **正式发行签名。** 当前 Mac 应用使用本机临时签名，已校验包的完整性。公开发行需要 Developer ID 签名与 Apple 公证。Windows 安装器的可执行文件签名也处于关闭状态。
2. **同版跨平台验收。** 仓库有 Windows x64、Apple Silicon 和 Intel Mac 三平台流水线。本轮取得了 Apple Silicon 的原生结果。Windows 应重点复验文件被其他软件占用时的导出与恢复，Intel Mac 应复验安装、启动与打开旧作品。
3. **维护成本。** 桌面入口约 2,800 行，业务服务约 1,770 行，执行器约 1,490 行。按作品生命周期、任务执行和设置分别迁移命令处理器，并让桌面与后台继续跑同一套命令测试，可降低改动一处影响其他功能的概率。
4. **启动性能和模型联调。** 构建仍报告桌面主界面脚本约 1.82 MB、后台脚本约 0.96 MB。后续可分别记录低配设备的冷启动和首次打开各模块的耗时，再决定哪些功能按需加载。真实供应商的流式响应、限流与账单结算仍需要单独的联调样本。

## 作品切换复验（0.4.98-macos.4）

补测发现，0.4.98-macos.3 打开一部含有不完整评审记录的旧作品时，会向作者报告打开失败，但后台已切换到目标作品。在界面和后台各指向一部作品的情况下，下一笔草稿可能保存到意外的位置。

本次把作品创建和会话管理从总业务服务中拆出。打开、创建和导入作品共用一次交接，先恢复并校验目标作品的完整返回数据，再释放原作品的写入锁。自动化回归核对了失败后的当前作品、目标作品锁，以及下一份草稿实际写入的数据库。Apple Silicon 原生客户端也走通了同一场景，关闭并重新打开原作品后可以读回草稿。

本版全量回归共 1,060 项，1,059 项通过，0 项失败，1 项 Windows 独占文件句柄用例按平台跳过。另行选跑的 60 项相关用例全部通过。1,200 章、300 万字样本也通过了保存修订、读取历史版本及提交中断后的恢复验证。

## Mac 开发与第一章恢复（0.4.98-macos.5）

| 复现的问题 | 修复和实测结果 |
| --- | --- |
| 新检出的源码没有前端生产构建，首次启动开发窗口会因查找发行资源失败而退出。普通打包命令还指向 Windows。 | 用只有源码和依赖的副本启动隔离开发，工作台和执行内核均已就绪。常用打包命令在当前 Mac 生成应用、DMG 和 ZIP，交付检查逐字节比较当前平台的应用程序和内置资料。 |
| 开发评估只查 Windows 配置目录，Mac 封面只列出 Windows 字体，管理后台把本机固定显示为 Windows。 | 评估读取 Mac 配置或指定的隔离目录。Mac 封面默认使用苹方，已保存封面按原字体读取，并为异机字体提供对应字形。后台通过已配对客户端取得系统名称，实测显示 macOS。 |
| 第一章已经显示的文字在强制退出后会回退。模型已经返回完整正文时，重开仍可能只有开头并再次请求正文。 | 可见文字在显示前保存，完整结果与该次用量同时登记。强制终止后恢复了已显示的文字。收到整章后强退、从备份还原再继续，直接进入审稿，正文请求与用量各一次。第一章采纳、备份还原并进入第二章也已通过。 |
| 正在排队的写作和讨论任务取消后仍可能发送。在 Mac 上停止终端任务时，子进程还可能继续写入作品。 | 任务排队期间绑定原作品，取消后腾出执行位置也没有发送。用延迟写入的子进程复现了旧行为，新版取消后，测试文件未被写入。文件加锁期间提交的正式版本也能在解锁后恢复。 |
| 连接测试把空白或已经截断的文字判为成功。 | 文字连通测试检查完整结束和有效内容，工具测试检查调用名称和参数。无效回执的离线用例均已通过。 |

桌面编辑器、创作实验室和后台工作台按首次使用加载。按生产入口页面的脚本及其预加载依赖统计，桌面首次载入的未压缩 JavaScript 从 1,825,028 字节降至 1,159,325 字节，减少 36.5%。后台从 2,783,008 字节降至 564,019 字节，减少 79.7%。已在打包的应用内打开文稿、输入中文、切换版本差异并读回草稿，也从浏览器走通了配对、打开封面和查看设备。

本机 **1,067 项离线回归全部通过，0 项跳过**。1,200 章、300 万字合成作品通过了中断恢复和历史版本校验。交付检查核对了 179 个程序与界面文件、238 个创作资源，以及 150 份依赖许可记录。Mac 业务归档内的 Windows 可执行文件和开发源码映射均为 0 个。开发文档中 20 个旧路径已指向仓库对应文件，44 个随历史机器保存的资料引用已标明出处。

授权的一次真实模型联调用隔离配置发送虚构短句，使用流式返回并关闭自动重试。账本中只有一笔完成请求，返回「星灯已亮」。首段文字约 2.9 秒到达，服务返回输入 38、输出 8 个 token，费用金额未知。
