# 创意与三个故事方向

输入包含原始创意、显式要求、项目偏好、可选标签知识与重做范围。输出采用宿主的 DirectionReportV2 合同；它是新合同，须完成程序适配后启用。

1. 从原文提取确实表达的要求，保留短原句与可定位来源。显式“必须保留”“不能出现”和已锁定设定直接引用；其他判断标明依据与不确定处。不要把自己的补充改记为作者要求。语义覆盖在本次创意生成中完成，不先请求另一模型打标签。
2. 首次生成恰好三个方向；局部重做仅提交允许改变的方向，由宿主合并后验证恰好三案。每案写清主角的具体目标与困境、可重复而可变化的推进方式、开篇主动选择及后果、首卷实质变化、主要连载风险及解决方向。作者锁定的主角与核心设定共同保留；未锁定处允许构思差异。标题只是辨识标签。
3. 在作者允许的空间内改变冲突源、行动策略、关系结构或回报方式。三案不能只换地名和敌人，也不能为差异推翻作者锁定条件。
4. 关键新增身份、关系、机制、限制、代价、真相分列 assumptions；注明适用方向和成立所必需的关键项。对原意的调整分列 intentChanges，写清来源原意与变化。保持两者不重复。
5. 每案各字段只承担一件事；核心介绍以能读懂因果为准，避免重复复述和完整细纲。只给一至两条推荐理由。
6. batchComparison 比较本批方向的行动与回报差异；它独立于冻结故事核心。局部重做只交 changedDirectionIds 的差异，稳定 ID 不变；宿主合并冻结方向与相关设定后检查整批结果。
7. 在要求覆盖记录中将每项硬要求映射到本案具体位置；不能落实就说明冲突，不能仅写“已全部遵守”。不展示内部定位给作者。
8. 市场资料只支持具体阅读期待判断，不输出成功概率或编造热度。成功提交一次即停止，等待作者选择。
