# 百万字记忆作用域查询可行性原型

这是独立的 Python/SQLite 工程实验，未接入星月书台客户端。它验证：先用索引缩小事实范围，再加载 JSON，与全量加载 JSON 后筛选可以得到相同结果；同时执行少量记忆语义边界检查。它不评测模型提取或小说创作质量。

## 运行

在此目录执行：

```bash
python3 prototype.py --output ./run-new --queries 120
```

仅使用 Python 标准库。输出目录不得已有 synthetic-million.sqlite，以防误覆盖；每次使用新目录即可。生成的数据库是可复现测试数据，不必放入交付包。

## 数据生成

- 400章，每章恰好2,500个中文正文的 Unicode 码点（含标点、数字等），总计1,000,000码点。
- 每章30条合成事实或状态记录，总计12,000条。
- 80个角色。主分支11,400条，备选分支600条；两个分支的来源引用同一份不可变合成正文。
- 部分状态持续生效，其他状态有效20章，使用左闭右开区间。
- 每章包含对应记录的明确句子，再用固定中文段落补足长度。
- 没有运行 tokenizer，1,000,000码点不等于1,000,000 token。
- 语料结构是人为构造的压力夹具，不具备真实小说的语义复杂度。

## 计时方法

固定随机种子20261028；120次查询，每次选4个角色、一个分支以及第30—400章中的某一截止章节。比较相同编辑版本、相同有效区间、相同来源版本下的结果。

全扫路径读取并反序列化全部12,000条JSON，再按作用域筛选。索引路径先用复合索引与来源版本关联缩小范围，再反序列化匹配结果。每次查询都逐条比较返回值，120次全部相等，返回7—62条。

同一进程生成数据并预热5次后开始计时，属于暖缓存实验；每次交替两个路径的执行顺序。p95使用升序样本中ceil(0.95×N)位置的值。

## 实际结果

以run-002/results.json为最终记录，2026-10-28执行。

| 路径 | 样本数 | 中位耗时 | p95耗时 |
| --- | --- | --- | --- |
| 全量JSON读取后筛选 | 120 | 63.042 ms | 79.298 ms |
| 复合索引筛选后读取 | 120 | 0.419 ms | 0.731 ms |

机器条件：Linux x86_64，Python3.12.14，SQLite3.53.1；运行环境报告9个逻辑CPU。进程峰值RSS27.53MiB；合成SQLite数据库13,713,408字节。未测底层CPU型号、真实硬盘性能与冷缓存。

查询计划确认使用fact_scope与source_scope索引，并对最终结果排序。此实验没有把向量库、模型推理或原文I/O成本混入数值。

局部中位比例约150.3，只代表该合成实验中两个Python/SQLite查询路径的差异。不能将它表述为当前客户端或完整小说生成提速150倍，也不能据此承诺目标机器延迟。

## 七组可执行语义检查

1. 当前编辑版本下按第3章/第7章回看，正常状态演变前后的旧值均可正确取得。
2. 主分支与备选分支隔离，备选结果不会混入主分支。
3. 角色误以为甲是凶手时，人物包保留该错误命题，不包含客观真相“乙是凶手”；第6章角色纠正信念后才出现新命题。
4. 第1章来源改成新版本后，旧来源事实立即不再用于新版本查询；历史编辑版本仍能读取原事实，新版本修正记录独立进入。
5. 相同幂等键、相同载荷只写一次；同键不同载荷拒绝。
6. 出场角色覆盖不完整时拒绝；no_evidence不允许凭空新增情绪；no_change保留角色已有动机。
7. 16组分支、章节、编辑版本的功能查询，新旧查询路径结果一致。

## 边界

未评测当前客户端端到端性能、LLM抽取质量、embedding/FTS/语义召回、引用位置与原文文件I/O、冷启动、多用户并发、真实长篇人物与因果一致性。原型仅有章节粒度，没有实现完整V3的章内事件位置、故事时间偏序、反事实分支继承、角色记忆巩固或依赖图重放；这些需要在正式工程验收中补齐。

代码无注释，说明集中在本文件。该原型不修改现有仓库、现有小说或远端数据。
