# V2 实施与验收

当前实施顺序以 implementation-backlog-v3.md 为准。本文保留原产品能力和前序迁移参考；记忆、人物认知、来源位置与修订细节按 V3 合同适配。

## 第一批 对象共创

扩展现有 Conversation、ActionProposal 和 run.discuss，使讨论可绑定人物、关系、世界规则、卷、章与场景。现有自由讨论和明确修改候选的低打扰路径保持可用。实现 ObjectRef、基准版本、作用范围、独立或原子变更组、依赖影响、部分采纳和撤销。

验收场景包括只讨论不改作品、连续三轮只改当前角色、锁定能力后重做冲突、明确直接改当前候选不重复确认、两个窗口同时编辑拒绝过期覆盖、只采纳独立变更、撤销后当前数据与历史均正确。

## 第二批 专用画布

复用 CharacterInspector、StoryInspector、RelationshipGraph、MemoryStudio 与 NarrativePanel。建立共享 WorkbenchScope；人物卡、关系边、章节状态、剧情层级、世界规则都能定位同一对象并发起讨论。中央画布和右侧讨论可各自聚焦。

验收包括切换截至章节不泄漏未来事实、人物视角不显示未知秘密、计划与已发生状态不混用、缺失数据不补零、状态变更有来源、空项目引导可操作、键盘选择可用、窄窗口无裁切。移动节点只保存布局；改变有语义的关系必须进入可审查修改。

## 第三批 创意与文风

接入 concept-forge 与按对象选择的职责片段。保留一请求三方向、稳定编号、关键新增设定和原意调整。修复已有单方向冻结假设与方向ID检查缺口。启用声音档案、角色关系策略及同场景作者选择。

验收包括三案共享作者锁定前提、差异发生在因果与行动、普通作者创意得到具体可执行开篇、作者要求减少设定时机制被真正收敛、拒绝新增设定后相关剧情同步更新。文风用同一场景比较和连续章节样本检查，模型自评分不充当作者偏好。

## 第四批 依赖与连载

在新的版本模式下接入近期细化与远期意图，保留0.4.82完整批次模式。当前章准备状态从必需来源推导；只处理被修改对象影响的后续计划。正文采纳后提取有来源的状态增量，复用现有事实store与独立审核。

验收包括修改一个角色不重生成无关世界观、修改世界硬规则可列出受影响人物与章节、旧正文没有被静默重写、计划变更不会改写过去状态、修订后审核与记忆缓存绑定新hash、断网恢复保留候选和已有费用。

## 质量记录

自动检查记录结构、版本、来源、引用、范围与运行恢复。人工比较记录作者偏好、出戏原句、人物主动性、声音辨识和承诺兑现。真实作品记录入口、阅读、追读和评论的实际定义及观察窗口。每种证据单独展示。

## 发布条件

资源更新与锁文件同一提交，保留在途任务的规则版本。新对象与字段映射通过旧作品迁移验证；失败可退回旧界面与旧执行模式。界面就绪不意味着新协议已接入，必须完成工具schema、验证器、渲染器、事务和恢复映射后开放对应功能。
