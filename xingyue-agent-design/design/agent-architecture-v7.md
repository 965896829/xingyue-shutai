# 星月书台 Agent 架构整合方案 V7

## 决策与范围

V7 将源码架构审计并入 V6，采用本地模块化单体。保留 Electron、TypeScript、独立写作内核、Pi、SQLite、不可变内容对象和现有模型与工具网关；优先整理创作业务模块、任务契约、上下文范围及作品状态，再接入 V6 创作能力。现阶段不全面迁移 LangGraph 或 Temporal，不为每个角色建立常驻模型，也不因人物图谱而增加独立图数据库。

这份方案新增架构约束、实施顺序和验收要求，不改变此前的创作目标。V2 共创与声音、V3 长篇记忆与人物心智、V4 按需技能、V5 题材世界和包装可视化、V6 自由探索和质量验证继续生效。保留 19 个技能包、48 个操作、50 个注册绑定及 112 项提示词来源；本次不增加模型提示词。新增 TypeScript 仅为待实现的宿主接口合同，不能据此启用 adapter。现有设计注册保持 `active=false`、`adapter.state=unavailable`。

审计基线为项目 0.4.82，提交 `b505f6f459db74871f39f63acf6106b827c8a353`。实施时先核对实际 HEAD，重新定位对应职责，不能把固定行号当成修改脚本。已核实的现状及来源见 `current-architecture-audit-v7.md`。

## 当前底座继续承担什么

当前应用的宿主掌握规范请求、工具范围、费用、恢复和正式采纳。Pi 提供回合与工具执行循环，使用顺序工具和 `maxRetries=0`。V7 保留这一控制边界；执行库升级或替换不能另开未记账的供应商连接，不能增加独立重试器或第二套会话权威。[源码](https://github.com/965896829/xingyue-shutai/blob/b505f6f459db74871f39f63acf6106b827c8a353/src/core/runtime/task-loop.ts)

数据库事务和不可变对象继续保存正式版本，Markdown 继续作为可恢复物化和外部编辑入口。候选指纹、审批、版本竞争、依赖检查和 Outbox 继续在现有正式提交入口执行。新增世界规则、人物心理和关系更新必须汇入这个入口。[源码](https://github.com/965896829/xingyue-shutai/blob/b505f6f459db74871f39f63acf6106b827c8a353/src/core/storage.ts#L744)

工作流重构不能改变远端结果未知的含义。已发出的请求即使没有收到完整结果，也不能直接清零费用或当成未发送；是否重新请求仍由现有网关根据结果、错误类型、预算和授权决定。正式本地采纳的幂等保护与远端模型请求是两种保证。

## 模块职责

| 模块 | 管理内容 | 稳定边界 |
| --- | --- | --- |
| 应用命令 | 作品、会话、编辑、任务和采纳入口 | 保留当前命令契约和 operation 回执 |
| 领域工作流 | 开书、章节、共创、修订的步骤与等待 | 引用既有 Run 和执行记录，不建立竞争状态机 |
| 能力注册 | 动作、提示词、schema、工具和校验绑定 | 延续 V6 目录，未实现绑定不得激活 |
| 上下文编译 | 版本、视角、来源、必要约束和预算 | 模型可见资料与宿主私有证明分别保存 |
| 执行适配 | Pi 回合、取消、恢复与工具调度 | 不掌握正式作品写权 |
| 模型与工具网关 | 请求、回执、预算、协议能力与副作用 | 单一发送和重试所有者 |
| 作品领域 | 世界、人物、事件、计划、修订影响 | 复用 V3 至 V6 合同与现有提交事务 |
| 查询和投影 | 人物卡、关系、时间线、伏笔及索引 | 可重建、带来源与水位，不独立创造事实 |
| 质量评估 | 回放、匿名比较、真实反馈和文本问题 | 区分程序正确性、模型判断和真人意见 |

物理部署仍为现有桌面程序和写作内核。模块名称不意味着新增服务进程；目录移动也不算完成架构改造。第一轮提取职责时，保持现有命令响应、模型请求、停止、恢复和采纳语义。

模型协议和供应商能力判断收拢到 capability adapter。工作流只声明需要结构化提交、正文流、工具、缓存或视角会话隔离，不在各个业务分支反复按模型名称判断。

## 四类工作流

| 工作流 | 默认职责 | 可复用能力 |
| --- | --- | --- |
| CreationWorkflow | 原始创意、三方向、作品方案、初始配置与命名 | concept-forge、story-contract、world-design、character-design、packaging |
| ChapterWorkflow | 章前任务、正文、必要审查、章后状态及候选 | rolling-outline、scene-contract、chapter-draft、chapter-review、memory-delta、memory-review |
| DiscussionWorkflow | 讨论、比较、局部共创、声音学习、隔离排演 | co-creation、voice-calibration、memory-query、reader-feedback |
| RevisionWorkflow | 变更范围、影响检查、前文与未来计划同步 | revision、canon-audit、character-reflection，以及按需复用其他动作 |

这是默认归属，不是新的固定顺序。相同能力可由不同工作流调用，但每个任务实例只拥有一个明确的工作流版本、执行记录和预算归属。世界规则可以在创作中途讨论，书名可以随方案修改重新评估，排演不要求先完成整部大纲。

S01 至 S11 保留为新手引导和进度视图。任务是否可执行由宿主核验实际前置资料、当前授权、冲突及版本决定。缺少正式章前资料可以阻断依赖它的正式续写，但不阻断讨论、手写编辑或在隔离分支中的探索。题材推荐世界模块，作者可提供、关闭或增加模块；不能用分类名称强制锁死创作能力。

工作流的循环和分支仍受总预算、取消信号、恢复版本及有效授权约束。讨论不会自动成为正式设定；冻结内容可以由作者明确修改，已有充分授权的候选编辑不再要求重复确认。采纳动作继续绑定具体候选和范围。

## 任务契约与已有类型的关系

新增 `vnext/architecture-contracts-v7.ts` 只汇集宿主执行边界，不替换 V3 至 V6 的故事合同。包中没有既有 `TaskEnvelopeV6` 类型，V7 不以一个弱化字符串范围结构冒充它；实际复用以下定义。

| V7 合同 | 复用的已有语义 | 本次补充 |
| --- | --- | --- |
| TaskSpecV7 | CreativeTaskPolicyV6、WorkBaseV6、ReadSetV3 | 工作流节点、既有执行引用、锁资源、预算账本及宿主私有标记 |
| OperationBindingV7 | SkillOperationRegistrationV6 | handler 与 schema 版本、显式工具副作用、接入前激活门槛 |
| CompiledTaskContextV7 | CompiledScopedPacketV6、ReaderPrefixPayloadV6、CharacterTurnPayloadV6 | 与当前任务身份绑定的联合类型 |
| TaskResultV7 | VersionRefV5、ObjectAuthorityV5、ReadSetV3 | 候选或只读结果引用，不具正式提交权 |
| CoreChapterCandidateV7 | ChapterMemoryDeltaV3、ChapterMemoryBatchV3 | 正文与核心记忆同版提交所需宿主聚合 |
| ProjectionBindingV7 | MemoryOutboxJobV3、ProjectionWatermarkV5 | 现有 Outbox 引用、计算性质和失败重建规则 |

`TaskSpecV7` 是宿主内部对象。其完整 `CreativeTaskPolicyV6` 可能包含作者秘密，不能整体发送给读者或角色模型。reader_prefix 和 character_turn 只发送 V6 定义的 modelPayload；hostPrivateProof 只存宿主。初始作品继续使用 `initial_work`，尚无正文时不伪造已采纳正文或故事时点。

能力目录使用 skillId、operationId、targetKind 定位行为；当前 `runtime/operations.ts` 的 operationId 是用户命令去重回执。二者用途不同。新注册表不能覆盖原回执表，也不能将“找到一个能力名称”当成“操作已经成功”。

`OperationBindingV7.retainedRegistration` 保存该任务采用的 V6 注册快照或引用解析结果，权限仍由唯一的宿主能力目录裁决。`architecture-policy-v7.json` 中的 50 项绑定是实施归属映射，不是第二套可激活注册表。TaskResultV7 是 handler 返回值，持久状态仍写回原执行记录，不再另建一张同权的任务表。

TypeScript 类型不承担运行时安全。激活前必须实现真实 schema 和交叉校验：项目、分支、基础快照、读集、授权、候选、注册绑定、资源 hash 和输入输出版本相互匹配。读集继续包含 source、fact、artifact、predicate 和 absence，新增匹配事实或原空集合变化同样使依赖结果失效。

允许缺少资料的探索分支必须与 CreativeTaskPolicyV6.mode 一致，不能把探索放行用于正式续写。任务、上下文证明、候选和 Outbox 引用的基础版本及范围必须一致；所有数量、字节上限和预算字段在运行时校验合法值。正式采纳资格由现有提交入口重新核验，类型中出现一个字符串 id 不构成授权。

## 工具副作用和恢复

每个工具显式声明 effect、输入输出 schema、输出上限、上下文策略、写入范围和未知结果处理。模型可用 effect 仅包含 read、draft_write、candidate_proposal，正式提交仍为宿主命令。新工具名称不决定权限或可否重放。

原工具白名单和参数检查保留；显式副作用合同由宿主验证，不能信任 Skill 自述。只读工具在结果未知时，也要核对读取范围、潜在费用和重试政策，不能因为名字是 read 就无条件重发。草稿或候选写入一旦开始而结果未确认，继续使用现有回执核对流程。

恢复绑定保留 executor、checkpoint、workflow、handler、模型配置和资源版本。旧任务按原版本恢复；不支持的旧语义保持只读或由明确迁移产生新任务，不能把旧执行记录改成新版本后继续。无副作用的上下文编译可以重建；已完成工具结果复用回执；未知模型请求保留 unknown。新增只读子任务受父任务总预算和取消控制，正式写入继续串行提交。

## 整请求视角编译

作者、读者和人物采用独立编译政策。作者可使用全局计划，但模型必须分清计划与事实；读者只接收实际呈现的前缀；人物只接收该人物的获知、误信、经历和表达依据。模型新增场景中的假设观察保留分支与来源，不转成正式获知。

隔离覆盖系统总控、共同方法、操作文本、消息、工具名称与 schema、附件与标题、检索、摘要、历史回复、provider state、缓存、修复和错误反馈。V6 的专用总控和方法替换继续执行，不能只在作者总控后追加“你不知道后续剧情”。缓存键和复用会话绑定 requestAudienceHash、分支、截止位置及真实编译请求；跨角色或读者边界不能复用全知 native session。

宿主需捕获最终发出的序列化请求，验证其中不包含未知资料、私有证明或可推断秘密的内部命名。旧请求的上下文收缩不等于人物知识边界已满足。初读如果只提供节选，结果明确标记节选范围，不能用缺失部分的推测代表完整阅读。

## 长篇领域与增量处理

V3 的四种时间、角色获知事件、主观信念、版本、分支与来源证据继续使用。稳定人格和当章状态分层维护；章后批量检查所有实际出场及有证据受影响的人物，记录 changed、reviewed_no_change、insufficient_evidence 等覆盖状态。人物出场不意味着必须改变人格或为每项情绪编造数值。对白只直接证明“说过什么”，是否证明真实心理由证据类型区分。

当前存储已有 delta-v1 快照。本次主要优化的是提交和查询计算：先测事实量、共享来源数、修订频次及延迟，再按 entity、world、timeline、章节与状态建立索引或映射表；从变更集更新相关事实；在同一可信源版本下批量校验证据；按范围提取人物与关系。新索引必须有 generation、水位和范围，未就绪可以准确降级，不能静默给出不完整结果并宣称全书无冲突。

`applyJournal` 当前会遍历 `04_` 正式台账并替换事实表；新实现迁移到结构化领域写入时，要选择唯一权威入口并保留与原文的来源绑定。过渡期允许比较新旧读模型，但影子结果不得独立写正式状态，不能长期双向自动同步两份事实真相。原始正文、旧对象和快照保留，坏迁移可回退，不把已有外部改稿默认为系统输出。

知识图查询、全文检索和可选向量召回都通过统一作用域与来源验证。先改善现有 SQLite 查询，再用实际瓶颈决定是否更换可插拔索引。引入叙事领域事件无需重写整个产品为事件溯源框架；运行事件和“角色背叛”等故事事件仍是不同记录。

## 一章的首个完整实施闭环

第一条纵向实施线为：作者意图与任务范围、章前上下文、正文候选、必要检查、章后核心事件及人物变化、作者采纳、同版提交、局部投影刷新。先让这一条链稳定，再复制到世界规则、自由讨论和复杂排演。

章后结果始终绑定最终正文 hash。正文修改后，相关审核和记忆必须重新验证；旧记忆不能因为结构正确就继续搭配新正文。核心事实、覆盖结果和必要依赖尚未就绪时，不能把章节当作完整可续写状态。用户可以讨论、编辑或保存隔离草稿。

人物卡、关系图、知情边界、伏笔和时间线优先由结构化资料本地计算。阅读体验、解法相似性等附属分析可异步完成，采用 V6 可独立解析的 adjunct 和 V5 版本、水位、撤回契约。附属投影失败不撤销正确核心提交，也不免除核心记忆要求。语义编辑生成 ChangeSet 候选；拖动布局、切章、放大和回放只改变视图，不调用模型或改动故事事实。

可视化刷新不启动新模型。需要新的语义判断时才建立明确分析任务，保留请求预算与来源。正文流程中必须等待的仅是当前采纳策略要求的核心步骤；可选统计和观察移出关键等待链路，结果过期则标识并重建。

## 提示词职责与 V6 接入

V7 不增加一层“架构总控模型”。`agent.md` 保留跨任务原则，专项提示词保留本轮目标，运行时规则由代码执行。现有 V6 三种总控变体和单核心加单方法加操作的装配策略继续保留。修改提示词时固定其内容和资源 hash，不能让在途任务悄悄切换新规则。

V6 六项增强接点如下。

| 能力 | 所属接点 | 前置工程条件 |
| --- | --- | --- |
| chapter-draft.explore | 章节或共创中的探索分支 | 创作授权、局部身份、分支读集和候选转换 |
| co-creation.rehearse | 共创中的单角色回合 | 整请求人物视角隔离、有限回合及父预算 |
| voice-calibration.learn-edits | 共创中的声音偏好提炼 | 改前改后证据、修改原因和可撤销偏好 |
| chapter-review.first-read | 章节中的按需初读 | reader_prefix 编译、真实曝光范围和会话隔离 |
| canon-audit.patterns | 修订或章节中的按需比较 | 有来源的场景投影、有效水位和范围完整性 |
| reader-feedback.compare | 共创或评估中的结果解释 | 宿主固定统计、真实与模拟来源分离 |

正常三方向继续一次模型请求，不增加固定标签分类或独立方向审核。文学建议、真人声音和继续阅读意愿进入质量评估；状态正确、权限正确和来源可信通过工程检查保证。角色数量、Skill 数量和规则数量都不作为质量提升证据。

## 技术选型与再评估条件

保留 Pi 和 ExecutorAdapter；对其升级按固定版本验证现有恢复、供应商协议及工具语义。LangGraph TypeScript 的节点、检查点和中断可作为工作流设计参考；只有实际分支和重放维护压力显著时，才在隔离流程试点。其检查点不替代作品正史、角色知情或读集验证；恢复节点可能重新执行之前代码，副作用仍需宿主管理。[LangGraph 持久化](https://docs.langchain.com/oss/javascript/langgraph/persistence) [中断](https://docs.langchain.com/oss/javascript/langgraph/interrupts)

Temporal 的生产部署需要 Service 与 Worker，可自建或托管。只有跨机器长任务、关机后云端继续、多用户共享等明确需求出现后，再评估其部署和迁移成本。当前不把它列为桌面产品前置依赖。[Temporal 部署](https://docs.temporal.io/production-deployment)

近期值得吸收的是持久状态、执行循环和工具通过稳定接口分别演进；模型上下文只是从持久资料中按需构成的视图。V7 在本地应用中采用这个思路，并保留现有网关和正式采纳权。[Anthropic 2026 工程文章](https://www.anthropic.com/research/managed-agents) [Temporal 记忆与状态](https://docs.temporal.io/ai/featured/memory-state-stripe)

## 验收与实施关系

本方案的模块和类型是实现约束，不是已完成代码。按 `implementation-backlog-v7.md` 和 `acceptance-protocol-v7.md` 逐批执行。首先复用已有崩溃、unknown、候选指纹和过期版本测试，完成职责提取；再落实任务及视角契约和首个章节闭环，随后做百万字增量负载与 V6 质量能力。架构评估记录实际请求、版本、耗时和故障结果；文学评估单独记录作者盲选、跨章一致性、改稿原因与目标读者意见。

实施编号统一为 R0 冻结与恢复基线、R1 无行为变化提取命令和工作流、R2 任务及整请求上下文契约、R3 一章同版核心闭环、R4 长篇增量性能、R5 V6 能力逐项接入。旧版功能批次作为工作内容保留，执行优先级服从这条依赖顺序；版本登记和恢复门槛不能为赶进度跳过。
