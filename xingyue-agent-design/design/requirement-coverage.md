# 用户目标到工程措施的映射

| 用户目标 | 方案位置 | 实现与验收 |
| --- | --- | --- |
| 全局分析当前GitHub | audit与报告基线 | 固定0.4.82提交；核心、共享合同、169资源和关键UI/测试；范围与未验证项分别说明 |
| 参考前沿成熟方案 | sources与报告参考表 | 官方仓库/文档、维护/测试/许可证据；按适配性选模式 |
| 番茄爆款与现象级目标 | fanqie-editorial、StoryContract、PromiseLedger、reader-feedback | 阅读欲望、人物独特选择、持续发动机、阶段兑现、终局收束；真实读者实验 |
| 总控精简 | runtime两版总控、RequestCompiler | 不变量常驻，专项与事实按需；阶段/工具/合同仍由宿主管理 |
| 每阶段完整提示词 | compat/26项＋creation/5项＋vNext模块 | 原模板和五项检查保留；vNext显式迁移，非只粘贴即生效 |
| 覆盖作者每项当下要求 | AuthorContract、RequirementCoverage、来源原文 | 显式字段确定性建账；原文语义提炼有证据；当前阶段相关要求不漏载 |
| 去AI味与真人化文风 | VoiceProfile、CharacterVoice、SceneContract、局部修订 | 同事实试写、具体注意力/对白行动/节奏；作者盲评，不用AI检测概率 |
| 长篇连续性 | 现有事实store扩展、PromiseLedger、memory-delta | 计划/正史/角色知情分开；有证据增量；hash绑定与事务采纳 |
| 降低等待与调用成本 | 规则选择、短命名、可选telemetry、只读流式预览 | 记录token/首内容/最终可采纳时间；成功不固定额外复审 |
| 可落地与可回滚 | migration-plan与manifest | A原合同兼容、B配套schema/renderer/validator；版本锁、旧任务恢复、分批启用 |

覆盖率只能说明已登记要求有对应处理位置。自然语言是否被完整理解、是否满足文学期待还需作者审阅与读者评价；宿主不能把一张自动打勾表当作事实证明。
