# 创意共创与高辨识度设定

本方案延续 0.4.82 的一次生成三个方向、候选隔离和作者选择机制。目标是让每案同时具备鲜明设定、可持续情节、具体读者回报和人物选择，再通过作者讨论逐步收敛。这里的创作尺度是工程设计建议，不是平台推荐算法或已取得的商业成绩。

## 已有合同与接入边界

现有 concisePlanningReportSchema 只提交 positioning、directions、assumptions、recommendedDirectionId 和 recommendationReasons。每个方向保留 title、logline、storyEngine、openingDecision、firstVolumeChange、differenceFromOtherDirections、longRunRisk 和 intentChanges。不能直接添加爆款分数、成功概率、神级指数或其他新字段。

本包新增 concept-forge.md 是 vNext 的创意专项候选，使用已有设计稿 DirectionReportV2。它替代 requirements-and-directions.md 的专项职责，每次二选一。0.4.82 继续使用 creation/direction-planning/planner.system.md。首次生成仍一次返回三案；局部重做的差异提交需要新版宿主合并与验证后启用。

创意讨论使用 co-creation-editor 与当前对象视角。普通讨论返回自然中文；需要落地的变更提交候选。提到一个有趣点子不等于修改正式设定，作者选择一条建议也不等于授权重写所有依赖文件。

## 创意应当回答的六个问题

| 尺度 | 具体问题 | 进入现有内容的位置 |
| --- | --- | --- |
| 可复述 | 读者能否用一句话说清本书特有的处境或规则 | positioning、logline |
| 有因果 | 这条规则怎样改变主角能做的事、胜负条件或关系 | storyEngine |
| 有人 | 主角为什么非做不可，又怎样作出自己的选择 | logline、openingDecision |
| 有回报 | 第一次兑现具体让谁得到什么、改变什么 | openingDecision、firstVolumeChange |
| 可生长 | 后续变化怎样来自旧结果，而非只换更强敌人 | storyEngine、longRunRisk |
| 能收束 | 核心承诺在全书终点如何回应 | 选定后的 StoryContract 与 PromiseLedger |

“神级设定”在本方案中体现为：规则简明，推演丰富，主角使用它作出有辨识度的选择，读者能够想象并期待下一次运用。神秘名词、反转数量和额外能力不单独计作质量。

## 一次生成内的构思方法

宿主先提供原始创意、明确要求、已锁定对象、允许变化范围和必要题材知识。模型在同次生成中寻找最能改变行动与关系的一项核心机制，再形成三条不同主线。只交最终三案，不提交未选草稿、评分过程或思维轨迹。

三案优先在冲突源、行动策略、关系结构和回报方式上区分。作者已锁定的主角、能力、世界规则、情绪底色和结局继续作为共同边界；未锁定处可以提出新设定。无需每案强制使用完全不同的能力，也不能为了差异偷偷换掉主角。

每案检查一个可变的情节回路：人物采取行动，获得阶段回报，局面产生后果，对手或环境据此回应，下一次选择随之变化。回报可以是破局、经营成果、关系推进、真相、成长或日常恢复。代价可以是取舍、责任、时间、暴露、资源或机会，不必默认伤害亲友、献祭寿命或持续压抑。

首卷变化应落在人物、关系、制度或处境上。连载扩展可以来自影响范围扩大、利益关系变化、旧胜利引发新责任，以及主角使用同一规则的方法改变。核心机制足够支撑时，不继续添加一套新机制解释旧机制。

作者希望更强脑洞时，优先重构规则与人之间的因果；希望更强爽感时，优先安排可看见的主动破局和结果；希望更有活人感时，优先调整个人欲望、关系压力和说话策略。一次修改应明确主要目标，避免同时改动所有维度。

## 把三方向页面做成讨论起点

卡片首屏只显示方向标识、一句话卖点、主角第一步和主要阅读回报。开篇、连载机制、首卷变化与风险按需要展开。影响方向成立的新增设定在卡片中以简短中文明确展示；其余细节可以折叠，但不能悄悄采纳。

建议提供与内容对应的操作：继续聊这个方向、保留核心换主线、只改开篇、比较两案、采用选中变化。点击对象后，讨论线程绑定方向及版本，已选择内容作为当前输入，而不是每次把整部作品重新交给模型。

作者可以说“能力保留，改成经营路线”“这个人物我喜欢，只改他的动机”“第二卷不要误会冲突”。宿主把它们编译为允许修改对象、锁定项和依赖影响；AI 只提出当前范围的修订。普通的偏好表达留在讨论，明确采纳或已有直接修改授权才进入应用流程。

## 创意变更与依赖

| 改动 | 优先检查 | 默认不自动重写 |
| --- | --- | --- |
| 主角目标 | 开篇选择、关系、分卷目标 | 已采纳正文 |
| 能力规则 | 冲突解法、能力边界、相关世界规则 | 无关人物卡与独立支线 |
| 角色动机 | 出场行为、关键对白、关联场景 | 其他角色完整经历 |
| 主线推进方式 | 分卷、近期章纲、读者承诺 | 全书所有细纲 |
| 结局方向 | 核心承诺与长期伏笔 | 已发生事实 |
| 情绪与文风 | 声音档案、试写、未来正文 | 正史与规则机制 |

影响传播先标记需要复核的对象，再按作者授权生成修订。跨对象互相依赖的变更作为同一应用组；允许独立成立的改动才能分别采纳。采纳以后，以新版本重新检查相关候选，不能沿用旧版本的审核结论。

## 概念评估与实际反馈

创意阶段可以比较可复述性、人物主动性、机制可变性、近期兑现、原创意覆盖和长期收束。比较必须指出具体内容；只有标签、空泛赞美或没有因果的反转，应直接改写为可读的方案。

主机对字段、引用、编号、冻结范围和来源进行确定性验证。吸引力比较由作者和目标读者参与，保留各自选择及原因。没有真实取样时，市场判断标为设计判断；已有来源只用于具体阅读期待，不推出成功概率。

局部讨论通常只产生一个当前建议；只有作者需要比较路线时才给少量备选。创意生成正常一次成功即等待选择，不默认增加独立“神级评分员”“爆款认证员”或多轮相互打分。真实问题引发的修复与作者主动重做计为新的实际尝试。

## 验收场景

1. 三个方向保持全部锁定前提，并在实际推进方式上形成差异。
2. 作者只改开篇时，核心能力、首卷目标和冻结方向保持不变。
3. 作者明确拒绝某个关键新增设定后，所有依赖它的候选被标记需要重做。
4. 同一核心机制能推演出行动、利益和关系不同的后续情节，不靠反复换敌人。
5. 提出创意意见不修改正史；已授权的具体变更可以在既定范围内执行。
6. 正文、卡片和对话中没有内部 ID、工具轨迹、HTML 注释、评分过程或自检说明。
7. 商业阅读目标通过作品比较和真实反馈检验，不以模型自评高分替代。
