# 星月书台内置技能与长篇创作优化方案 V4

## 1 本轮结论

V4 在 V3 的百万字记忆、动态人物、对象共创和文风方案上，补齐内置技能的注册、选择、装配、运行、验证与发布。建议保留 TypeScript、SQLite、Pi 和现有模型网关，采用 Agent Skills 的开放文件格式，把创作能力组织为 19 个技能包、39 个按任务选用的操作。默认创作链不因包的数量增加模型请求。

技能负责可复用的创作方法；宿主负责检索、权限、版本、事务、状态投影、阶段推进和可视化。人物记忆、作者偏好和作品资料以有来源的数据保存，随当前任务进入上下文。它们不能混入技能源码，成为所有作品永久执行的指令。

本轮在 2026 年 10 月 29 日重新核验 GitHub main，仍为 0.4.82，提交 b505f6f459db74871f39f63acf6106b827c8a353。项目已经有 26 项注册技能，其中 21 项执行模型任务、5 项执行宿主逻辑；资源锁、候选权限、工具限制、输入版本和恢复控制已经存在。V4 对这些机制做扩展和整合。[V4C01][V4C05][V4N07]

当前交付是工程设计候选。应用接入需要实现对应 adapter、输出 schema、验证器与工作流迁移。原 V3 的详细记忆合同、SQLite 示例、动态人物合同及验证记录继续保留；新技能不能仅靠复制 Markdown 就获得尚未实现的能力。

## 2 当前项目值得优先改进的地方

| 现有机制 | 本轮核验结果 | V4 的改动 |
| --- | --- | --- |
| 技能注册 | 注册表校验固定 26 项，宿主职责 ID 写在代码中 | 改为有版本、按执行类型分类的能力目录 |
| 契约 | 权限和 tools 直接校验，输入输出等约束分散在 runner 与验证代码 | 用已注册 schema、adapter、验证器和预算绑定实际操作 |
| 参考资料 | 当前技能中匹配到的参考路径会整体装入 | 明确 required、conditional、on-demand，按任务选段 |
| 讨论依赖 | rulesHash 覆盖整个规则树，任务卡绑定全部扫描文档 | 绑定实际读集，并保留集合查询与空结果依赖 |
| 记忆提取 | 当前章节流程仍把完整累计记忆台账设为必需输入 | 同步迁移为 V3 稀疏增量及局部状态输入 |
| 输出与面板 | 多数阶段仍依赖 Markdown 模板 | 对象数据和正文形成权威版本，Markdown 与画布作为投影 |

这些变化必须随运行代码一起实现。现有 agent-guidance 分段、命名资料按需读取、缓存前缀和重复来源去重应继续使用；不能为统一目录而丢掉已有优化。[V4C01][V4C03][V4C10][V4C11][V4C13]

固定阶段直接由宿主选择技能。开放式讨论才需要动态发现。用户点击“生成三个方向”后，不增加一个模型请求来判断应该调用哪个技能；当前三个方向一次正常生成的路径继续保留。

项目当前依赖的是 pi-agent-core 与 pi-ai 1.4.0。Pi coding-agent 的技能发现与命令文档可以用于同版对照，但这些功能不会因为两个基础包已安装就自动进入自有客户端。[V4S04][V4S05][V4N08]

网文专项核验到 InkOS 的提交 53adac4e、Oh Story 的提交 70d1cf42，以及 Webnovel Writer v8 的提交 dbba2e47。后者 README 标明工作台版本 8.3.2；master 保留的是 v6，不能把两个分支当成同一个安装与运行方案。本文只采用相应工程机制，不将项目自述的创作效果当成已验证的本项目结果。[V4N01][V4N02][V4N03][V4N04][V4N05][V4N06]

## 4 整体工程结构

| 层次 | 职责 | 典型产物 |
| --- | --- | --- |
| 作者交互 | 共创、编辑、差异比较、选择范围 | 对象讨论、选区、采纳动作 |
| 工作流宿主 | 明确任务、冻结版本、决定调用与恢复 | TaskEnvelope、任务状态、成功回执 |
| 技能运行层 | 查找技能、选择操作、加载必要方法 | ResolvedSkill、ContextPlan |
| 模型与工具 | 生成当前候选或正文，返回结构结果 | 方向、ChangeSet、正文、审阅、Delta |
| 作品数据 | 事实、人物状态、承诺、计划及来源 | Canon、事件、状态投影、MemoryPacket |
| 确定性服务 | 验证、合并、索引、依赖失效与 UI 投影 | 可回放版本、就绪水位、角色卡与关系图 |

Prompt 是指令文本；Skill 是带选择条件和资源的能力包；Subagent 是独立上下文中的模型任务；Tool 是宿主暴露的操作接口。一个 Skill 可以复用现有的一次请求，多种审阅视角也可以在一次请求中完成。只有独立上下文、并行任务或独立核验有明确收益时，才增加子任务。

建议继续使用 resources/skill 作为发布资源根，新增 builtin 目录与 registry.v2.json。每个包以标准 SKILL.md 作为说明入口，把各 operation 的指引放在 references 中。运行 manifest 放在宿主管理的 registry 中；技能文件只能请求已登记的能力，不能注册任意执行代码。

建议新增的代码位置包括 src/core/skills/catalog.ts、resolver.ts、context-plan.ts、capabilities.ts、skill-snapshot.ts、evaluations.ts。现有 SkillRegistry 保留兼容入口；runtime/task-loop、tool-gateway、commit-kernel 和模型网关继续负责真正执行。共享合同在 src/shared 下登记，UI 读取运行状态和对象投影。[V4C01][V4C04][V4C07][V4C09]

## 5 建议内置的十九个技能包

| 技能包 | 操作 | 技能标识 |
| --- | --- | --- |
| 01 创意与故事方向 | 首次生成三个方向、按范围重做方向 | concept-forge |
| 02 作品方案与项目约定 | 建立完整作品方案、独立核验作品方案、配置项目参数 | story-contract |
| 03 对象共创与讨论 | 讨论当前对象、比较候选与取舍、提出局部变更 | co-creation |
| 04 世界规则与制度设计 | 建立世界规则候选 | world-design |
| 05 角色内核与群像设计 | 建立角色候选 | character-design |
| 06 长篇分层规划 | 全书主线与里程碑、当前卷设计、章节路线、章段节奏、近期批次细纲 | rolling-outline |
| 07 单章与场景合同 | 规划当前章场景 | scene-contract |
| 08 作品声音与试写 | 提炼声音档案、提炼并试写、按选择更新声音、已有档案同场景比较 | voice-calibration |
| 09 章节正文创作 | 生成当前章正文 | chapter-draft |
| 10 章节证据审阅 | 审核指定正文 | chapter-review |
| 11 有界修订与剧情变更 | 改善局部表达、修复已确认问题、提出剧情修订 | revision |
| 12 章后事实与人物状态 | 批量提取本章增量 | memory-delta |
| 13 记忆与角色状态核验 | 核验本章记忆候选 | memory-review |
| 14 有来源的故事记忆问答 | 回答记忆查询 | memory-query |
| 15 重大事件后的角色反思 | 生成反思候选 | character-reflection |
| 16 跨章连续性与承诺审阅 | 检查跨章连续性、解释变更影响、核验阅读承诺、卷末与完结审阅 | canon-audit |
| 17 平台与题材证据研究 | 收集并分析相关证据 | market-evidence |
| 18 名称与读者题面 | 实体命名与改名候选、书名候选、简介与题面文案、核验指定题面 | packaging |
| 19 读者反馈与创作实验 | 诊断并提出下一轮实验 | reader-feedback |

这些包覆盖既有创作流程。包内 operation 是同一领域的不同任务，宿主每次只选择一个，不会因为同包里列了四个操作就连续执行四次。前序 57 个提示词与职责资源继续作为设计依据和兼容资产，不注册为 57 个常驻 Agent。

world-design 和 character-design 负责初建或明确要求的批量建设；普通对象讨论统一走 co-creation，加本轮对象视角。rolling-outline 合并规划方法的管理，保留 book、volume、roadmap、rhythm、batch 的任务边界。packaging.review 必须再由 targetKind 选择唯一实际合同，书名、角色名与简介不共用一份模糊 schema。

以下职责始终由宿主执行：项目初始化、配置校验、检索编译、完整查询、证据定位、角色覆盖校验、版本 CAS、采纳事务、依赖失效、索引水位、批次推进、字数统计及可视化刷新。章节语义摘要有需要时可以成为模型操作，不能与本地归档混算。

## 6 技能如何选择和加载

### 6.1 固定任务直接选择

界面按钮、阶段节点和用户显式技能命令先解析成 operation。宿主检查操作适用对象、工作流版本、输入就绪状态和预算，再加载技能。已知需要的原文、角色状态和模板由程序一次准备，不让模型重复申请读取。

### 6.2 开放讨论限定能力目录

自由讨论进入 co-creation，宿主按当前对象、权限与工作流过滤可用能力。目录只提供必要名称和描述。模型可以回答、比较、提出变更或提出下一项操作请求；宿主负责判断是否执行。已有明确授权且可回退的修改不重复询问。执行完整章节或跨对象改动时，绑定新的任务范围与实际输出合同。

自然语言请求不能只靠“角色”“记忆”等关键词机械选技能。“把角色卡打开”是本地视图操作，“这个人物为什么会背叛”是讨论，“修改他的动机并调整第十章”才可能产生有依赖的变更任务。需要模型补读资料或激活其他方法时，那次模型往返必须计入成本，不能承诺所有自由对话都只要一次调用。[V4S02]

### 6.3 三层资源装配

第一层是过滤后的名称与描述；第二层是当前技能的共同方法与本次操作指引；第三层是有用途和版本的资料。普通阶段直接预装第二层和已知必需资料，自由讨论才使用受限激活入口。整个过程中只保留一个有效总控、一个主技能、一个当前操作和必要领域片段。

同一段规则以内容标识去重。正文任务已含声音原则时，只加入本场 VoiceSlice，不重复装入完整 prose-voice。作者选了某个题材，只加入相关知识卡，不把整套题材库注入。

技能资料是静态方法；Canon、VoiceProfile、人物状态、市场证据和读者样本是动态数据。每份资料注明 sourceKind、范围、版本和用途。外部页面和作品片段不能授予工具权限，也不能覆盖作者要求。

### 6.4 单次任务绑定

任务绑定核心规则、技能、操作指引、实际参考资源、输入输出 schema、adapter、模型配置与真实 read-set 的摘要。read-set 包括具体记录，以及可能受新事实影响的查询条件、空结果、分区 epoch 和完整性。相同正文 hash 配上不同读集，不得复用旧记忆提取结果。

缓存区分包完整性与本次语义依赖。校验包可以覆盖全部资源，本次任务只绑定实际使用的方法和数据；否则改一本书不相关的标题规则，也会让正在修改的人物任务失效。压缩保护当前活动技能与授权边界，任务结束后从原始资源组装下一任务，不永久累积所有历史技能。[V4C10][V4S02]

## 7 百万字记忆仍然是第一工程优先级

V3 的六层结构继续使用：不可变的正文与作者决定；有来源的事件和命题；当前状态投影；可追溯的分层摘要；实体、全文、向量、关系和承诺索引；为当前场景编译的有限 MemoryPacket。技能只是这些服务的消费者和候选结果生产者，不能另存一套“技能私有正史”。

故事发生时间、叙述揭示位置、人物获知事件、编辑版本保持独立。当前正史回看早章与查看当年的历史编辑版本是不同查询。分支固定父版本与覆盖层；故事世界和时间线不能代替编辑分支。原文位置继续采用 Unicode 码点半开区间，旧 UTF-16 设计只在单位明确时转换。

检索先直接加入硬约束、当前状态与到期承诺，再做实体、中文别名、FTS、向量和有限因果路径召回。分支、版本、来源与视角过滤贯穿召回和结果验证。两字中文名走精确实体与别名索引；穷尽性问题使用完整分页查询，不能把 Top-k 当成“全部”。需要的硬约束超过预算时拆分或扩展任务，不能默默删除。

章后 memory-delta 一次批量提取本章事实与人物变化，memory-review 占用原有独立核验位置。输入是当前正文、相关入场状态、必要前史及人物覆盖集合。输出是有来源的稀疏增量，不再每章抄写完整累计台账。

宿主核验正文 hash、读集、来源、角色名单、覆盖与作用域后，在既有事务边界提交正文及核心状态。关键记忆与当前版本一致后，依赖它的下一章才可继续；无关对象讨论不受阻。向量和非关键摘要可以异步，水位必须表示所需范围内完整完成，不能只取最大的已处理序号。

修订旧章时，源依赖和查询依赖共同使受影响事实、人物信念、摘要、索引与计划失效。先回放仍有效事件，语义依赖变化的内容重新提取；不能盲目重放旧增量。已采纳的后续正文标明影响范围，未经授权不自动整书重写。未知结果的模型请求继续遵守现有网关策略，租约到期本身不授权重发。

V3 已有百万码点合成查询原型与合同验证，本轮保留其原始结果，不把它描述为完整客户端或小说质量测试。本轮技能目录校验也不能替代真实模型与读者评估。

## 8 将人物个性变成可以进入场景的条件

character-design 建立稳定人物内核：长期欲望、保护的利益、冲突价值、底线、惯用策略、注意习惯和关系中的表达方式。短标签可帮助浏览，真正影响写作的是“在什么条件下会选择什么，以及为何付出这个代价”。不要求每个人都有创伤、秘密或固定口头禅。

scene-contract 使用角色当前目标、压力、所知与误信、关系、可用资源和本场说话意图。宿主把这些数据编译为角色入场片段，正文技能据此写选择和反应。例如，一个人确信朋友背叛，与作者知道朋友正在卧底，是两层不同资料；角色对白只能使用其获得的信息。

章后继续记录目标与动机、情绪、信念、关系、身体资源、承诺、表达策略七类动态维度。每个实际参与者都有覆盖结果，可以是 changed、reviewed_no_change、insufficient_evidence、mentioned_only 或 unresolved_identity；有覆盖不等于七项都必须发生变化。

心理活动区分原文明确内心、发言、动作、可靠叙述、作者确认和模型解释。人物撒谎可以形成言语事件，不能直接形成世界事实。动作可能有多种动机，证据不足就保持未知。回忆中的旧情绪落到对应故事时段；当前回忆引起的反应另记当前事件。

character-reflection 仅在重大选择、价值冲突、关系断裂或作者要求时触发，可以批量处理相关人物。重新登场先由宿主读取既有状态；只有重大未决变化需要解释时才生成反思候选。反思不能自动改写稳定人格。普通章节复用一次记忆提取，不给每个角色额外开一个 Agent。

批量反思为每个目标人物绑定独立 scope、证据包 hash 和读集摘要，并纳入执行快照。宿主验证 actorId 与视角一致，目标名单覆盖完整；多人共享一次请求时，仍按人物限制可用证据和结果归属。

人物质量评估增加三种场景试验：同一难题下不同人物的选择是否可辨；同一人物面对不同关系是否会调整策略；价值成长是否有事件与代价支撑。去掉姓名后的对白盲评只作为辅助，不能为了可识别而强迫所有人物使用口头禅。

## 9 把真人化文风做成作品能力

文风采用 VoiceProfile、场景级 VoiceSlice 和作者修改证据。优先使用作者自有样本、获准参考和本书已采纳正文；参考仅提供表达特征，不向本书注入人物与情节事实。

voice-calibration 可以在一次调用里给出候选档案与同事实短试写。作者已有声音档案时，再按需要用 pilot 操作比较，不默认连跑两轮。对话场景、动作场景、亲密场景和信息交代场景可以使用不同片段，保持同一作品的总体声音。

revision.voice 从三层处理读感：词句与人物声音；场景详略和注意力；因果和人物选择所需的依据。表达与详略在允许范围内直接修；需要新增动机、事件、知情或结果时进入 revision.story 的有版本变更合同。这个划分吸收了 Oh Story 的分层诊断思路，同时保留 V3 的来源、范围和采纳机制。[V4N03]

宿主可以统计重复句式、意象复现、逐字复读、截断、占位符、内部字段泄漏和字数。统计结果用于定位，不能把自然语言信号全部变成硬禁令。文本没有命中词表也可能像提纲；某个长句、解释或停顿有叙事功能时应保留。

作者反馈形成偏好候选，记录作用范围、来源、采用与撤销。只改本章的一句表达，不自动成为全书禁词；对当前书的偏好，不自动扩散到所有作品。技能源码的改变进入离线评测与版本发布，不能在连续写作中悄悄自改。

## 10 强设定与连续阅读回报

concept-forge 继续一次提交三案。每案围绕主角可主动执行的行动、独特规则、反制与代价、首次可见回报、下一轮难题建立连载引擎。区别落实到冲突源、关键选择和推进机制，不依靠换名或堆设定。所有影响因果的新增前提明列为 assumptions，原创意变更单列，作者锁定内容不被覆盖。

同一次生成中推敲四个问题：主角是否有值得跟随的欲望；机制是否持续迫使人做有代价的选择；胜利是否改变关系或局势；重复使用机制时是否产生新的难题。作者需要深入比较时，再用共创操作推演具体段落或备选分支，结果保持候选计划。

rolling-outline 持有全书核心承诺、卷级节点与终局约束，只把近期窗口展开到可写场景。3 至 5 章细化、10 至 20 章意图窗属于起步参数，依据题材和实际质量调整。原 0.4.82 的 S06、S08 仍要求全批次产物，滚动窗必须与阶段门槛一起迁移。

canon-audit.promise 与 ending 分别检查承诺兑现和收束。它们引用实际正文与计划，区分已兑现、推进中、延期、放弃候选和缺少证据。宿主负责完整承诺查询，模型分析因果和读者体验。不给模型一个 Top-k 摘要就让它宣称全书伏笔已清空。

市场研究和真实读者反馈用于提出有证据的选项。真实样本、模型模拟和方法判断分别标记；保留样本时间、渠道、数量与未知项。以作者采纳、角色辨识、具体因果、阅读意愿和真实连载反馈衡量改进，不把模型自评分包装成平台结果。

## 11 共创与专用可视化面板

对象讨论绑定 objectId、对象版本、编辑分支与当前章节。作者可以只讨论、比较备选、修改选区、重做某个方向或调整一组相依对象。ChangeSet 给出最小变更、依赖组、影响范围与必要的决策；未选择的修改不能顺带被采纳。

角色卡展示稳定内核、当前目标、最后观测情绪、信念、关系变化和最近证据。关系图使用同版本的有向关系边，时间轴同时区分故事时点和叙述位置。承诺面板展示来源、计划窗口与实际兑现证据；记忆面板展示范围、来源版本、覆盖和就绪水位。

打开这些面板直接查询数据投影，零模型调用。让模型画第二份人物卡会产生重复事实与额外成本。缺失的心理依据在界面显示未知，不画成零；模型分析的情绪强度或成长曲线要有来源与性质标识，不能冒充精确客观量。

界面保留共创、写作、检查三种工作状态。左侧对象导航，中间画布或正文，右侧当前对象讨论和差异。普通作者界面只显示正在做什么、结果和可操作差异；技能版本、资源摘要和调用轨迹放在开发者检查面板。

## 12 执行合同与发布治理

运行 manifest 是本项目扩展，不能冒充 Agent Skills 标准字段。它声明包版本、operation、输入输出 schema、资料需求、能力请求、验证器、预算和支持的工作流版本。解析键包含 skillId、operationId、targetKind 与 workflowVersion。packaging.review 缺少 targetKind 时报告无法解析，不选第一条绑定。每个 operation 必须解析为唯一实际 schema；文字说明不能代替 Zod 或 JSON Schema 的运行校验。

最终工具范围由宿主已实现能力、当前任务政策、用户授权、数据范围和技能请求求交集。除实际需要的补读或联网外，结构化任务通常只有一个提交出口，纯正文可以没有模型工具。SKILL.md、网页、参考小说和第三方 manifest 均不能增加权限。[V4C07][V4S01][V4S09]

内置技能随应用发布并校验包摘要。用户覆盖建立明确版本与启用记录；同名来源显式区分，不采用静默覆盖。第三方包先作为静态指令和资料导入，脚本需另走宿主能力登记与隔离策略；模型不能因为读取到 scripts 目录就执行其中内容。

执行快照冻结实际生效的全部工具名称与 schema hash、验证器版本、逐角色证据包及授权绑定，不能只保存能力名称。任务开始后固定有效资源，运行中升级只影响后续任务。已有规则文本不能通过输出说明来替换，旧任务恢复继续使用旧工具与回执协议。无实际 adapter、schema 或验证器的 operation 保持不可激活，目录不向模型宣告它已经可用。

建议记录 taskId、skillId、operation、资源摘要、实际读集摘要、模型与工具次数、输入输出用量、首字时间、完成时间、候选采纳与恢复状态。只保存可核验的操作轨迹与简短决策依据，不要求记录隐藏推理过程。

## 13 如何证明技能有用

采用四类评测。第一类检查选择是否正确，既有应触发案例也有不应触发的近邻案例；第二类检查来源、版本、权限、范围、覆盖和恢复合同；第三类比较文学效果；第四类比较模型请求、token、延迟和费用。[V4S07][V4S15]

文学评测固定同一模型、参数、创意、记忆包和场景任务，对比 V3 与 V4。保留独立留出样本，给读者随机顺序的盲评版本。分别评价作者要求保持、设定吸引力、角色选择、对白差异、表达自然、因果完整和继续阅读意愿，并记录严重退步。

起步可用 20 个创意任务、30 个场景、10 个修订任务及两部各 30 章的原创连载案例；这是建议规模，不是已完成实验。路由、工程与文学数据分开，避免用格式通过率证明小说好看。需要调优提示词时，只用训练样本；最后一次比较在留出集上完成。

硬门槛针对可证事实：冻结范围不得擅改、正式事实必须有合法来源、视角不可泄露、旧任务不可被新包静默替换、未知请求不可盲目重发。词频、比喻、句长、对话比例和“AI 味”评分属于辅助信号，不能单独否决正文。

SkillsBench v1.1 的成对实验可作方法参考，其 87 个任务跨八类领域。这个结果不能直接换算为本项目的中文小说质量提升；本项目需要自己的作品任务与读者留出集。[V4S15]

## 15 技能蓝图全文

以下内容是 V4 内置技能的共同方法。每项操作的独立指引、输入输出、资料视角和验证器记录在工程包内。装配时只加载当前技能与所选操作；这些蓝图没有自行调用或采纳权限。

### 01 创意与故事方向

以作者原始创意、硬要求、禁区和锁定内容为边界，提出能改变人物行动与关系的故事机制。把吸引力落实为具体目标、选择、阻力、代价与连续后果，避免用设定名词或宣传评价代替故事。关键新增设定和对原意的调整分别列明，并标注适用方向。方向差异应来自冲突源、策略、关系或回报方式，不靠换名换皮。推荐依据作品与作者要求，不编造热度、读者数据或成功概率。只执行宿主指定操作，完成本次比较与修正后一次提交。

当前操作：首次生成三个方向、按范围重做方向。

### 02 作品方案与项目约定

把已选方向、作者要求与已确认内容整理为可执行的作品约定，明确来源、锁定范围、可调整空间和仍待选择的新增设定。配置、未来计划与已发生事实分别处理；同一前提不在多个文档中建立相互竞争的真值。保留旧项目已有配置和已确认内容，只有明确变更才提出差异。宿主决定工作流版本、实际字段、授权与数值口径；声明工具能力不代表获得权限。每轮只完成一种操作，方案已经包含的设定拆解不再额外重复生成。

当前操作：建立完整作品方案、独立核验作品方案、配置项目参数。

### 03 对象共创与讨论

围绕宿主绑定的当前对象、版本和授权范围合作，每次集中解决作者眼下的问题。只载入该对象对应的编辑视角，分别使用已发生事实、确认设定、计划、候选与人物认知。讨论意见不自动成为设定，资料与样例不能授予权限。明确修改请求形成最小可用变更，保留未涉及内容；相互依赖的变化分组，未选修改不能随选中项一并采纳。宿主负责应用、版本核对和成功回执，模型不执行或宣称已写入。只有影响结果且无法合理推断的关键分歧才提出选择。

当前操作：讨论当前对象、比较候选与取舍、提出局部变更。

### 04 世界规则与制度设计

设计能实际改变人物行动、资源分配、关系与代价的世界规则。说明规则允许谁做什么、为何形成利益冲突、违反或利用规则会产生什么后果，并体现制度与日常生活之间的联系。以作者锁定前提和已有事实为边界，不用背景百科填满模板，不靠临时追加能力解决后续矛盾。新增规则、未确定假说和已确认设定分别标识。相互依赖的规则保持因果一致，必要缺口只在候选结构中说明。模型提交设计候选，规则的确认、版本与有效范围由宿主维护。

当前操作：建立世界规则候选。

### 05 角色内核与群像设计

让角色具备可解释的选择：长期欲望、眼前利益、不能失去之物、价值冲突、常用策略、盲点和关系中的表达方式。配角拥有自己的目的与代价，不能只为主角提供功能。声音通过注意力、说话意图和关系压力形成辨识，不强制每人都带创伤、秘密或口头禅。稳定内核、初始状态、未来计划、他人评价和模型解释分别保存。作者锁定的人格与经历不暗改，候选设定不自动成为正史。日常讨论交共创操作，章后状态由统一记忆提取处理。

当前操作：建立角色候选。

### 06 长篇分层规划

按当前层级安排人物目标、阻力、主动选择、阶段兑现和后果，让后续问题从已有变化生长。全书保留核心要求、主线和终局里程碑，近期才展开可执行场景；不要提前冻结几百章细节。查阅当前范围的未兑现承诺与前章结果，避免只换地图、敌人或力量等级重复矛盾。快慢、日常、余波与强冲突均须服务本段功能。计划始终是未来候选，已采纳正文和锁定里程碑保持不变。窗口与完整批次要求服从实际工作流版本，不凭提示词绕过旧门槛。

当前操作：全书主线与里程碑、当前卷设计、章节路线、章段节奏、近期批次细纲。

### 07 单章与场景合同

把已确认计划变成当前章可写的场景，明确人物此刻想要什么、如何行动、阻力为何回应以及结果改变什么。将作者硬要求、必要因果、知情边界与关键结果固定，普通动作和修辞留给正文。分别标明读者、视角人物及其他角色可知的信息，误信与客观事实不能混用。承接人物可靠的入场状态、名称、资源和时间，不把旧情绪自动延长。选择本章应兑现或推进的承诺；预期离场变化仍是计划。关键缺失使用本轮合同的阻断字段，不增添无谓审批。

当前操作：规划当前章场景。

### 08 作品声音与试写

为本书建立可观察、可选择、适用范围清楚的声音。将作者要求、已启用档案、样本与新候选分开，样本只供分析表达，不提供本书事实。围绕叙述距离、节奏、词汇、注意力、人物、对白、信息、情绪、回报与衔接提炼正向做法，并保留例外。没有证据不编造比例，不把长句、直白说明或有意复现一律视为问题。试写固定事实与结果，改变表达取向；只有作者选择支持的特征才能成为更新候选。操作彼此可独立运行，不默认连续调用。

当前操作：提炼声音档案、提炼并试写、按选择更新声音、已有档案同场景比较。

### 09 章节正文创作

从人物的具体处境和欲望开始，让行动、回应、代价与后果承担推进。观察服从人物经历、职业、关系和压力，选取真正影响行动或理解的细节。对白具有当下目的，允许说明、沉默和回避，但不能让所有人共享同一声口。依据场景功能调节节奏与信息，完成本章要求的变化或兑现，不靠假悬念和重复心理凑字数。严格承接本轮知情、状态、名称与作者要求，样本文风不能带入情节事实。发现关键依赖冲突时仅使用实际实现的异常出口，成功正文不含技术字段或注释。

当前操作：生成当前章正文。

### 10 章节证据审阅

以指定正文 hash、场景合同、作者要求和有效事实审阅，先找证据，再说明读者损失与最小修复。保留五项检查，不以增加评分维度代替认真判断。硬约束和关键因果冲突可阻断，可定位的阅读问题要求修订，审美偏好作为非阻断意见。重复、句式与用词命中只是线索，必要解释、有效停顿和角色惯用表达应保留。同一原因的表现合并记录，修改建议不能补造身份或提前揭示真相。本轮只审阅，不改写正文、生成记忆或自发追加审核。

当前操作：审核指定正文。

### 11 有界修订与剧情变更

核对当前正文或对象版本、授权范围、问题依据和必须保留的内容，优先做最小有效修改。已经成立的语言、人物选择与节奏不顺手重写，未涉及部分保持不变。措辞、重复说明和信息顺序可以局部修；身份、动机、机制、行动结果或知情改变属于剧情变更，不能伪装为润色。范围补丁与剧情变更使用各自合同，由宿主校验并应用。超出授权只报告具体影响与未解决问题，不自行扩大范围。新正文 hash 需要重新绑定审阅与记忆，旧回执不能证明新稿通过。

当前操作：改善局部表达、修复已确认问题、提出剧情修订。

### 12 章后事实与人物状态

从指定正文版本、有效旧状态与来源提取有证据的稀疏变化，按场景和事件顺序处理。区分客观事件、人物发言、明确内心、持有信念与模型解释，计划不是已发生事实。核对所有实际参与或受影响角色，允许无变化、证据不足、仅提及与身份待解析，不为填表制造心理。回忆状态落在对应故事时段，旧情绪不自动覆盖当前。稳定人格与作者锁定内容不由本轮推断重写。候选正文的增量仍是候选，正文及依赖版本变化须重新核验，只有宿主能确认正式同步。

当前操作：批量提取本章增量。

### 13 记忆与角色状态核验

以当前正文、确认设定和有效旧状态核验增量，分别判断 supported、contradicted 与 unclear，并给必要来源。提取结果不能作为自身成立的证据，衍生台账也不能替代原文。检查角色身份、覆盖、事件顺序、时间范围和信息获得过程，区分发言、内心、信念与世界真相。回忆不得覆盖现在，一次情绪不得改写稳定人格，情绪是否持续不能仅由章数间隔决定。来源或版本失效时明确指出，不补造事实、不改写正文、不宣告采纳。完成当前审核即停止。

当前操作：核验本章记忆候选。

### 14 有来源的故事记忆问答

根据宿主确定的项目、分支、编辑版本、故事时间、叙述范围与视角回答。区分当前正史在过去时点的状态和旧编辑版本当时保存的内容，不能混用。人物确信不等于世界真相，作者知道的信息不自动属于人物。精确和全量查询由宿主执行，模型负责解释有效结果及来源。检索未命中不是不存在的证据，有限召回不冒充全部记录。资料不足、投影未就绪或查询未完成时说明实际缺口，不用猜测填满答案。回答不改变设定、人物状态或历史版本。

当前操作：回答记忆查询。

### 15 重大事件后的角色反思

依据指定人物的稳定内核、当前状态和有来源经历，提出可能改变其自我认识、关系判断或目标权衡的解释。只使用人物能够经历或获知的信息，保留犹豫、矛盾与仍未改变的部分。明确区分正文已经写出的内心、作者确认的心理和本轮候选解释，不补造成长所需的旧事。反思不自动修改人格、阵营、感情、信念或长期目标。没有足够依据可以不提出候选。按本轮事件批量处理指定人物，选择、后续描写与正式状态生效仍由作者和宿主决定。

当前操作：生成反思候选。

### 16 跨章连续性与承诺审阅

以有效正文、确认设定、人物状态和承诺来源审阅指定范围。事实、角色认知、未来计划与作者有意留白分别处理，问题必须有可定位证据和具体影响。依赖发现、查询完整性、失效与重放由宿主负责，模型只能解释收到的范围，不能凭叙述宣告覆盖全书。区分需要修订的矛盾、可选改进与仍待后文判断之处，给出最小处理范围，不用新设定替旧问题补洞。已采纳或已发布内容不自动重写，审阅结果保持问题记录或候选建议。

当前操作：检查跨章连续性、解释变更影响、核验阅读承诺、卷末与完结审阅。

### 17 平台与题材证据研究

只研究当前策划或包装确实需要的问题，并使用宿主授予的范围和来源能力。区分平台规则、官方创作经验、公开作品题面和真实读者反馈，保留来源、发布日期、获取时间及适用范围。编辑推论单独呈现，搜索排序不冒充榜单，成功个案不代表普遍规律。样本用于理解承诺与表达，不复制专名、标志性台词、正文或独创情节。无联网能力时仅使用已注明日期的离线证据；冲突来源按时间与适用范围核对，不能凭主观选择宣告最新政策。

当前操作：收集并分析相关证据。

### 18 名称与读者题面

用准确、可辨识且符合本书气质的名称与题面传达真实阅读承诺。来源限于作者要求、已确认故事内容和标注清楚的参考资料，不为吸引点击发明能力、关系或剧情。实体新命名和已接受改名分开，保护旧名、别名、历史身份与人物知情，已接受改名通过有版本变更处理。字数、候选数量、推荐规则和审核字段服从本轮合同，不把某次实验约束写成平台通则。标题、实体名与简介有不同输出结构，宿主必须解析唯一 schema；本技能只交候选或审核，不发布。

当前操作：实体命名与改名候选、书名候选、简介与题面文案、核验指定题面。

### 19 读者反馈与创作实验

使用有来源、时间、正文版本、统计口径与样本量的真实材料；模拟读者意见必须独立标识。把入口、开篇兑现、局部理解、人物关系、长线重复、更新和曝光变化分开分析。单条评论不代表总体，指标变化可能受人群和曝光影响，保留替代解释。优先定位可操作的问题与少量单变量实验，不追逐少数意见推翻已确认方向。统计计算由宿主完成，模型解释证据和取舍。反馈可以支持作者偏好或编辑经验候选，不能自动写入正史、全局文风或平台发布操作。

当前操作：诊断并提出下一轮实验。
