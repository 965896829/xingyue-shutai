# V5 实施步骤

## 开发原则

记忆与人物优先级延续 V3。新分类入口、技能目录可并行接入；正式世界、标题与画布统一使用有来源的作品状态。每一批完成实际合同、适配器、验证和界面后独立验收，不通过直接切换 active 字段启用未实现能力。

## A 基础状态与目录

| 工作项 | 实现范围 | 验收重点 |
| --- | --- | --- |
| A1 记忆查询与事务 | V3 索引、必需状态、分支和 read-set、正文与记忆同版采纳 | 旧章修订、否定查询失效、出场人物覆盖、核心水位 |
| A2 分类身份 | 表面、频道、作品形式、分组、平台或稳定本地 ID | 不同表面不误合并，154 个旧 optionId/conceptId 不改 |
| A3 官方来源适配器 | 公开目录快照、提取版本、分页完整性、刷新差异 | 部分失败不删除旧项，旧作品固定快照 |
| A4 创作与发布分离 | CreativeGenreProfile、PublishingSelection | 混搭、自定义和未选标签可创作，发布规则有范围 |
| A5 新建入口 | 主分类可见，二级标签搜索，已有设定与自由输入 | 男频和女频目录正确；后台未核验部分不假称实时 |

## B 动态世界与共创

| 工作项 | 实现范围 | 验收重点 |
| --- | --- | --- |
| B1 模块注册 | 12 模块与 custom schema、三态选择和来源 | 题材不单独产生必填模块，未定不阻塞无关阶段 |
| B2 作者体系导入 | 原文、标准化候选、未解析覆盖、字段锁 | 名称顺序和边界保留，解释提案不混入正史 |
| B3 多体系合同 | 独立体系 ID、版本、适用人物阵营和时段 | 多条成长路线并存，不擅自折算战力和地位 |
| B4 S03 迁移 | 模板、输出 schema、validator、渲染器与阶段状态机 | 旧任务原协议恢复，新任务按模块输出 |
| B5 三方向扩展 | 单次请求轻量模块建议及新增假设 | 冻结故事、假设和模块建议一起保留 |
| B6 对象变更 | 最小 ChangeSet、依赖分组、锁与版本前提 | 拖布局不改剧情；部分采纳保留依赖完整性 |
| B7 规则压力测试 | 明确范围、相关状态、可复核场景与修订候选 | 只在作者请求或具体风险时运行，不逐章追加 |

## C 标题与承诺

| 工作项 | 实现范围 | 验收重点 |
| --- | --- | --- |
| C1 样本证据 | 榜单、书页、统计窗口、观察时间、字段来源 | 搜索不当榜单，未知上架时间不使用更新时间代填 |
| C2 样本选择关系 | snapshot.sampleSelections、请求范围、精确或近邻匹配 | 无榜单类目不伪造；跨频道参考明确降级 |
| C3 分级降级 | ready、partial、stale、unavailable、disabled | 不可取时使用缓存或无样本候选，状态进入生成结果 |
| C4 包装承诺 | 载体版本、已确认设计、计划、正文或提案依据 | 早期标题允许世界/提纲为空，正文未兑现不标完成 |
| C5 定向审核 | packaging.review 按 targetKind 装配 | 实体名无榜单依赖，书名与简介按实际承诺复核 |
| C6 显示与存储名 | 显示标题独立，目录稳定 ID 与适配器 | 不把路径字符限制当平台或文学规则 |

## D 实时画布

| 工作项 | 实现范围 | 验收重点 |
| --- | --- | --- |
| D1 投影事件 | 采纳事务与 outbox、稳定事件 ID、读模型 | 事件幂等，水位范围明确，断线恢复不过度更新 |

| D5 线索与承诺 | 假说、支持、反证、揭示与兑现节点 | 假说不升级为事实，提纲不充当已发生事件 |
| D6 扩展视图 | 情节轨道、双时序、地理路线、资源与节奏 | 没有依据不画精确曲线；复杂组件按需接入 |
| D7 大作品交互 | 局部图、有界多跳、聚合、增量更新与后台布局 | 真数据测延迟与内存，不每个字重建全书 |

## E 迁移与质量评价

旧作品先只读解析，保留 Markdown 原文与现有任务版本。迁移生成候选与差异，处理未解析身份和不完整依赖；失败时旧流程继续可用。作者明确修改旧设定才能解除字段锁。

评测按本地合同、模型输出、人工盲评分开执行。新增 32 例只覆盖本轮关键范围；V4 的 36 例与 V3 的记忆、人物用例继续构成回归基线。不得用字符串包含规则、schema 通过或模型自评分代替行为与质量验证。

对同一作者创意固定事实、输出数量与预算，随机呈现旧版和新版方向、标题、试写，分别记录吸引力、具体性、人物可信度、持续写作空间及作者接受情况。反馈进入作者偏好和版本记录，不无差别强化所有用户的同一表达模板。

每个变更记录代码版本、工作流版本、prompt/package digest、模型配置、上下文 token、请求次数、首字延迟、完整结果延迟、失败和修复原因。只有测得数据后才设最终性能门槛。
