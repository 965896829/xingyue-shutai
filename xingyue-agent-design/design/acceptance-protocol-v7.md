# V7 架构验收协议

## 范围与状态

V7 验证现有可靠性是否在模块化重构后保留，以及新任务、视角、人物记忆和投影是否形成完整链路。它补充 V6 质量验收，不替代文学、真人偏好、连续章节或平台数据验证。

配套 `evaluation/architecture-v7-cases.json` 定义 24 个待执行案例：8 个 local_contract、14 个 app_integration、2 个 performance。所有案例 status 为 not_run，executionCount 为 0；本次交付不包含这些应用行为的执行结果。文件解析、引用检查、类型检查和案例计数仅属设计包验证。

V6 的 40 个质量案例与 V3/V4/V5 有效回归保持各自原状态。既有仓库崩溃和记忆测试是可复用验证入口，本次阅读测试代码不算重新执行。

## 证据分层

| 层级 | 验证对象 | 应报告的证据 |
| --- | --- | --- |
| local_contract | 真实装配与校验代码配合隔离夹具 | 输入、允许范围、实际请求或产物、确定性断言 |
| app_integration | 实际宿主、工作流、持久化、恢复和界面 | 事件、请求与工具回执、版本、事务、重启和 UI 结果 |
| performance | 实际存储与查询实现上的明确测试语料 | 设备、语料、冷暖条件、样本数、耗时、内存、存储与参考结果 |
| model_output | V6 真实模型案例 | 实际提供方、模型、配置、发送请求、输出、成本和语义标注 |
| human_blind | V6 作者与目标读者评阅 | 实际展示版本、顺序、独立参与者、选择、平局、弃权和排除 |

前两类可以使用明确标记的模拟模型，但不能由此宣布模型写作能力通过。performance 只说明被测规模和数据条件下的工程表现。后两类遵守 [V6 质量协议](acceptance-protocol-v6.md)。

## 运行前记录

每次执行记录代码 HEAD、未提交差异、工作流与合同版本、规则 hash、执行器版本、测试数据版本、运行环境、成本上限和评价目标。保存案例 ID、开始结束时间、执行层级、结果、失败原因和证据路径。

独立的 `oracle`、秘密 canary、预期真相、故障注入点、性能阈值和匿名候选映射只能由宿主或评测器读取，不能自动拼入被测模型请求。结果从实际行为与产物计算，不由模型自行宣告。

## G1 原有恢复与提交语义

重复命令编号及相同输入复用结果；同编号不同输入拒绝。发送后结果未知保留 unknown 及实际账目，重启、租约过期、工作流切换或 Pi 循环都不能自动再次发送。停止后的迟到结果可以保留已收到证据，但不能继续执行工具或改变正式作品。

在提交前、事务内、事务后待物化等边界注入失败，验证正式数据库与文件最终一致。外部改稿保留，不用旧内容静默覆盖。旧候选、过期授权和错误 stateVersion 不能采纳；相同已采纳候选重复提交返回既有结果。

这里验证本地正式提交的幂等和远端未知的保守处理，不宣称模型供应商提供 exactly-once。旧任务使用保存的 executor、checkpoint、规则和合同版本；不支持的版本保持可读并给出可处理原因，不静默换语义执行。

## G2 能力注册与实际工具效果

任务合同必须对应真实 handler、输入输出 schema、上下文策略、工具能力、范围校验、预算和恢复。26 个现行资源、19 个设计包以及新旧工作流有明确映射，旧版本资源校验继续有效。active=false 或 adapter unavailable 的设计项不能被界面或路由绕过。

工具效果以宿主登记的实现为依据，显式区分只读、草稿写、候选提议等。测试一个名称不含 propose 或 submit 的写工具，以及一个名称相似但只读的工具，确认名称不决定重放策略。任意未授权工具、越界范围或不匹配的效果声明被拒绝。

现有命令 Operations 回执、新能力目录、Run、ExecutionRecord 与正式作品版本分别承担自己的职责；不能为了统一名称合并成一张没有语义边界的状态表。

## G3 作者自由度与依赖

缺少完整世界百科或后续大纲的新作品，只要具备当前探索所需资料，就可以讨论或试写。缺少某项核心状态只限制依赖它的正式动作，不阻断所有创作入口。

作者明确授权的局部候选修改直接执行，保持修改范围；新的正式采纳仍经过宿主入口。作者能够明确修改旧约束，其他未授权约束继续有效。不能通过额外多次确认降低已经授权的创作自由度。

读集包括返回来源、没有返回的结果及查询谓词依赖。插入一条此前不存在的相关伤势、承诺或规则，应使依赖旧空结果的候选失效；无关变化按声明范围处理。避免只比较已返回文件 hash 而漏掉新事实。

## G4 整份请求的视角边界

检查实际发送的系统、总控、共同方法、操作、工具/schema、历史、附件、引用、检索、缓存、原生会话和错误反馈。reader_prefix 不获得未来正文、全书大纲或作者真相；character_turn 只获得该角色可见的观察和信念，不附秘密真值或真假标签。

先用唯一 canary 检查直接泄漏，再用 V6 真实模型案例评估隐含信息和语义越界。canary 未出现不等于所有隐含剧透都已识别。跨作品、分支、版本、截止位置或人物复用会话时，必须证明实际范围相容，否则重新建立隔离上下文。

可在作者任务中使用必要的未来计划，但这些资料不能随共享方法或恢复消息进入独立读者和角色任务。信息范围由宿主授予，模型传入的角色名或 audience 参数不能自行提升权限。

## G5 正文与人物记忆同版

以最终正文 hash 绑定核心记忆、必要审查与人物状态差异。编辑正文或合并探索分支后，旧差异失效；不能先采纳正文、再把必要记忆作为随意可失败的后台结果补上。

人物覆盖检查允许变化、无变化、依据不足和仅提及。稳定人格不因一次情绪自动改写。人物认为某事为真与作者世界中的真相分别保存；情绪诱因、目标、行为、信念和关系变化有来源与生效位置。运行日志不能替代叙事事件来源。

正式采纳经同一事务更新版本、核心事实和依赖。候选预览清楚标注其分支与基础版本；历史回看不能作为当前事实。前文修订后，相关状态、计划和评估正确失效，下一章按新来源读取。

## G6 投影与实时分析

人物卡、关系图、时间线、伏笔表和检索索引来自同一版本或明确的候选分支。切章、筛选、布局与回放不发送模型请求；关系和规则的语义编辑进入统一 ChangeSet 与采纳。

可选阅读、节奏和解法分析使用独立可解析载体，继承父任务预算，可取消和重建。其失败不回滚已正确提交的核心事实，也不能把必要检查降为可选。过期异步任务完成后，产物不能覆盖更新版本的投影。显示当前数据版本、缺失与重建状态。

本地画图与模型分析分别记录耗时和调用。按需语义分析可以异步运行，主流程是否等待以真实依赖为准，不因为某个面板存在就强制增加一轮模型调用。

## G7 百万字规模与增量正确性

先记录原实现基线，预先确定目标设备和关键操作的可接受耗时、内存、存储及取消响应，再实施优化。语料至少覆盖代表性的 100、500、1000 章档位，并随章节增加人物、事实、证据和历史修订；所有数据规模均记录实际值。

增量更新与完整重建的独立参考结果逐项比较：正式事实、有效范围、关系、知情边界、来源有效性和依赖失效应一致。测试新增、修改、撤回、旧章改稿、分支合并与重建中断。内容校验缓存命中后，仍检查当前版本、可见范围和修订待决状态，不因字节相同绕过来源可用性。出现不一致时先保留证据和原版本，不用更快的错误结果通过性能验收。

记录提交、上下文编译、人物查询、来源校验、全文或语义检索、重建、首屏和停止恢复的耗时分布，报告冷缓存与暖缓存、样本数量、峰值内存、数据库与对象增量。缺少实际测量时保持未执行，不写主观的毫秒级目标已经满足。

仓库既有 1200 章和 300 万字体积测试保留为存储扫描测试；长期承诺、人物误信、跨卷回归、伏笔、物品归属和因果准确率继续用有明确真值与修订过程的长篇案例验证。[现有规模脚本](https://github.com/965896829/xingyue-shutai/blob/b505f6f459db74871f39f63acf6106b827c8a353/tests/scale.ts)

## 结果与放行

一个案例只有实际执行、收集证据并满足预先定义的 oracle 才能从 not_run 改为 passed。blocked、failed、skipped、not_run 分开保存，执行次数与真实调用次数分别统计，不以测试总数表示覆盖完整。

R0—R1 以现有行为和恢复不回退为门槛；R2 以任务契约、授权和整请求范围为门槛；R3 以一章核心同版闭环为门槛；R4 以增量语义等价和预定性能目标为门槛；R5 再加 V6 的真实输出、连续章节和真人偏好证据。硬范围和数据错误不能被文学均分抵消，文学建议不能无依据升级成自动拒稿规则。

框架试点须单独比较维护成本、复杂度、恢复、调用和迁移结果。没有可测净收益时保留当前 Pi 和宿主；工作流图不能作为人物关系图已经实现的证据，框架检查点不能作为百万字记忆已经正确的证据。

## 迁移与回退

迁移绑定明确的旧版本与目标版本，保留原文、内容对象、身份和来源 hash；未解析项保持待决，不默认合并角色或强制填充世界模块。旧任务只在可证明语义兼容时转接，否则保持原执行或只读处理。

回退通过关闭新入口、恢复原处理器或生成新修订完成，保留请求、产物和作者决策历史。已提交数据的回退不能靠直接覆盖旧数据库文件实现；实际恢复方式按当前存储备份协议验证。所有费用未知状态继续保留，禁止在回退或重新运行时清零预算。
