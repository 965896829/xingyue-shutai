# 星月书台 V5：自由创作、动态世界与可验证的长篇工程

## 1 本轮结论

V5 建议把星月书台建设为一套由作者意图驱动的作品系统：题材用于提供创作参考；世界模块决定需要建设哪些规则；人物、情节和正文在这些规则下行动；书名提出的阅读承诺必须与故事连接；所有可视化读取同一版本的作品事实。保留 V3 的百万字记忆和人物动态，保留 V4 的按需技能装配，本轮把分类、世界、书名和交互画布接入这条主线。

新建作品的体验应当是：作者选题材或直接输入想法，系统在同一次三方向生成中提出适用模块，作者讨论和选择后再展开世界；已有设定可以原样沿用。题材选择不强迫作者使用境界、金手指或固定升级路线。创意质量围绕独特行动机制、可见回报、人物选择、对手反制与长期变化评估。

工程包从 V4 的 19 个技能包、39 个操作扩展为 19 个技能包、42 个操作，注册绑定从 41 项变为 44 项。新增操作集中在 world-design 的 profile、inherit、stress-test；它们按需要调用，不新增三个常驻 Agent。旧 57 项提示资源保留，V5 增加 21 项总控、共同方法或操作提示资源；78 是溯源资源数量，不是单次请求装入量。

审计基线为 0.4.82，固定提交 b505f6f459db74871f39f63acf6106b827c8a353。项目使用 Electron、React、TypeScript、SQLite 和 Pi；本轮没有修改生产仓库。以下的合同、模块和交互是待接入的产品工程设计，真实能力以已实现的适配器、验证器和回执为准。[V5C01]

### 3.3 创作与发布分别保存

CreativeGenreProfile 保存作者真正想写的内容，可以多题材混搭、自定义题材或暂不归类。例如“都市日常为基础，使用悬疑调查的推进方式，加入一条超常规则”。PublishingSelection 保存番茄频道、作品形式、当前分类快照与选项；发布归类按该表面的已核验规则检查。

平台要求一个主分类，不等于故事只能含一种题材。改发布分类不会自动重写世界；改创作画像也不会未经作者决定改正式发布信息。不同表面、频道、分组下的同名标签保留各自身份，避免只凭名称合并造成丢项。

目录刷新保留 observedAt、平台更新时间、来源、提取器版本、范围与完整性。项目固定自己的 snapshotId；刷新成功后显示变化供作者选择迁移。部分失败不批量删除旧目录，未知不当作已下架。离线展示最后成功快照和日期；自定义创作标签始终可用。

## 4 新建作品与反复共创

### 4.1 推荐交互顺序

第一步输入创意，可选频道和题材，填写保留项、禁区、已有设定。作者已经写明的要求自动进入意图合同，不要求重复填写一次才保护。

第二步在一次正常请求中生成三个方向。每案同时给出轻量的世界模块建议，但不先为三案分别生成完整世界。卡片显示主角行动、核心矛盾、首次回报、首卷变化、持续冲突与新增设定。作者可以围绕一案讨论、只改一个机制、冻结满意的方向，或者全部重做。

第三步选中方向后展开作品方案、所需世界与人物；作者可跳过尚不重要的模块。重大新前提单列候选。已经授权的可回退整理直接执行，新的故事根本改变由作者选择。

第四步试写最能验证卖点和人物声音的场景，比较创意是否真正能写出来，再进入卷纲、滚动章纲与连续写作。这个试写操作按作者需要触发，不作为所有作品强制增加的关卡。

默认在作品方案稳定后生成书名，开篇成稿后复核其阅读承诺；作者也可以根据已有创意先取工作名，未建立的世界或开篇版本保持为空。作者随时可以围绕标题、角色、世界或大纲继续讨论，无需退回开书向导。

### 4.2 四种作者控制方式

| 方式 | AI 可以做什么 | 应保持什么 |
| --- | --- | --- |
| 严格沿用 | 整理原文、解析对象、指出歧义 | 名称、层级、机制与锁定关系 |
| 沿用并补缺 | 填作者开放的字段，提供候选 | 已给定内容和未授权范围 |
| 共同设计 | 提出多个局部选项、比较后果、分组采纳 | 作者已经确认的版本 |
| AI 提案 | 在允许范围提出完整候选 | 作者的原始意图、禁区和选择权 |

界面围绕对象讨论：选中一个境界、一条世界规则、一个角色、一段提纲或一个标题，侧栏只讨论该对象及相关依赖。聊天不能悄悄覆盖作品；明确修改形成最小 ChangeSet，显示原值、新值、依据和影响范围，允许分组采纳。

启用或停用模块属于语义修改。停用时保留历史数据和来源，标明受影响的人物能力、场景与承诺；不删除已经写过的正文。单纯拖动图形位置属于布局修改，可以立即保存和撤销，不进入故事正史。

## 5 动态世界模块与作者体系继承

### 5.1 十二个内置模块与自定义扩展

| 模块 | 适用内容 |
| --- | --- |
| 世界基础 | 现实基础、时空边界和作者已明确的底层前提 |
| 地理与移动 | 地点层级、通行路线、距离或时间限制 |
| 历史与历法 | 发生时间、年代和虚构历法 |
| 社会与势力 | 组织、制度、利益、权利和义务 |
| 经济与资源 | 获得、消耗、所有权、分配与稀缺 |
| 能力规则 | 适用者、触发、效果、限制、反制和例外 |
| 成长与境界 | 无等级、线性、分支、多轴或自定义成长 |
| 科技与职业 | 知识、流程、资格、组织权责与工具 |
| 谜案与证据 | 事实、线索、假说、反证、误导与揭示 |
| 关系与社会规范 | 亲密、家族、婚姻、礼法和群体期待 |
| 物种与生态 | 生物、族群、栖地、食物与环境约束 |
| 系统与游戏界面 | 任务、界面、奖励、失败与信息权限 |

模块状态为启用、停用、未定，来源为作者、推断、提案。解析优先级是作者明确要求、已采纳世界规则、当前故事需要、题材参考。没有任何模块仅因为题材名称就成为必填项。能力规则与成长境界分别启用：存在超能力不必存在等级；境界可以使用传统名称，也可以有多个互不统属的体系。

自定义模块采用数据模式和白名单验证器，不允许世界设定文本直接成为可执行代码。作者可以自建“梦境债务”“家族礼法”“商会信用”等类型；默认表单、列表与关系视图读取同一个模式，不要求每加一种设定都重新开发页面。

### 5.2 规则卡应表达可写的因果

一条重要世界规则保存适用对象、触发条件、效果、限制、反制、例外、有效时段、来源与关联对象。数值、成本、冷却、等级不一律必填。作者若明确要无代价的强能力，冲突可来自目标冲突、保护对象、公开后果、资源分配或对手的信息优势，而不是 AI 擅自削弱能力。

软世界同样合法：某种神秘力量可以保持未解释，规则卡只记录已确认现象、适用边界及未知之处。世界真相、公众说法、角色相信的规则和读者已知内容分别保存。一次异常现象不自动改写世界法则，人物的错误解释也不自动成为正史。

成长可以是无等级、线性、分支、多轴或自定义。能力、职业资格、社会地位和资源权利分别建模；不能把更高境界自动解释成更高官位。指定为前置条件的依赖图可以检查环，关系网、资源循环和作者明确的循环成长路径则允许成环。

### 5.3 导入作者已有境界

输入原文保留来源与 hash；名称、顺序、例外、能力边界转成标准化候选，同时保存原文对应。等价整理、解释提案、未解析片段分别呈现。作者给“炼气、筑基、金丹”，系统不能自动补出元婴和化神，更不能以创新为名把原体系改名。

多个流派有不同路线时分别保存，不强塞进同一阶梯。每套体系有独立 systemId、版本、适用人物或阵营及有效故事时段，适用主体与查询视角分别表达。跨体系只记录作者允许的比较、转换和交互规则，不自动折算等级；尚未确定的战力比较维持未知。字段锁绑定来源与作者决定，解除需要明确修改决定，不能靠模型判断旧设定不够精彩就绕开。

### 5.4 让设定具备持续创意的方法

用六个具体问题检验核心机制：第一次能解决什么困境；最弱的人能怎样利用它；对手理解后会如何反制；大规模使用会改变什么制度；第二十次使用还有什么新选择；这条规则会迫使主角牺牲什么或承担什么责任。输出结果是可写的场景与修订候选，不是长篇自评。

压力测试只在作者要求、复杂体系确有冲突或重要转折时调用。普通生成内做简短自校即可。每章额外模拟所有规则和角色，会浪费上下文并制造未经采纳的剧情。

## 6 三个原创机制示例

以下示例用于展示设计方法，属于原创提案，未进行读者实验或全网唯一性验证。选择它们的标准是能否形成明确行动、可见回报、连续变化和人物困境。

### 6.1 传统仙侠：境界照旧，施法权可以被没收

作者保留炼气、筑基、金丹。新增机制是：境界决定能驾驭多大力量，山川契约决定能在哪里调用力量。宗门控制的是一片山河的施法权，凡人共同体也可能持有被遗忘的古契。

开篇主角只是被宗门除籍的修士，救人时发现自己在山门辖域无法使用法术。他追查一口古井的旧契，找到村民共同持有的一段未被宗门买断的水脉，在极小范围完成第一次反击。首个回报既是赢下行动，也是让一群原本只能求仙人的人取得谈判地位。

连载行动从寻找旧契，走向解释冲突契约、保护持有人、对抗伪契与公共利益的争执。对手可以收购、诱骗或破坏持有共同体，不能只靠境界更高重复压人。主角最终必须决定，是成为新的施法权垄断者，还是承担开放权利带来的风险。原境界未改，冲突机制已经改变。

可以启用能力规则、成长、社会势力、地理与资源模块。创意标题例如《我被仙门除籍后，替凡人讨回山河》；它是展示用原创候选，不是平台已有热门书名。

### 6.2 都市日常：专门接手关门前七天的生意

主角受托处理一家旧影院最后七天的交接，以为工作只是清物、对账、交钥匙，却发现不同人都在争夺一份看似不值钱的旧胶片。店主想体面离场，员工想拿到承诺，债权人想尽快清算，街坊希望留住共同记忆。

系列机制是每接一个即将关门的地方，就进入一组相互冲突的利益、秘密和未完成承诺。主角的能力来自查证、谈判、识人和愿意承担责任；胜利必须改变具体人的处境。下一单来自前一单留下的信用和得罪的人，长线追索可以连接父亲当年未完成的一次交接。

世界规则是虚构城市中的职业流程、组织权责、关系网络和资源限制，不需要异能或境界。创新点是“散场如何重新成为开端”的行动结构；爽感可以是讨回尊严、反击欺瞒和救住一个人的未来。职业细节在真正写作时按所选现实背景核验。

可以启用职业、社会、经济、地理和关系模块。原创题面可在《这家店关门前，还有七天》与更明确的人物态度型标题之间比较；是否合适由具体故事声音与读者选择验证。

### 6.3 都市悬疑：提前收到明天会被遗弃的物品

作者明确允许一条超常规则：每天黄昏，主角的失物柜出现一件次日将被原持有人主动丢弃的物品副本。预测固定为当次黄昏、尚未受这次预告干预的未来；副本可触摸但不能替代原物功能，现实原物仍在持有人手中，副本次日午夜统一消失且不反复刷新。副本只携带物品本身已有的信息，不附赠人物记忆，也不证明丢弃原因；照片只能证明主角拍到过副本。

开篇出现的是一个尚未失踪的孩子明天会主动扔掉的求救器。主角必须查清孩子为什么会放弃求救，而不是只等待设备预测犯罪。首次救人后，对手发现可以安排丢弃行为投放误导，让主角为错误判断付出后果。

持续悬念来自物品来源、主动遗弃的动机、干预后的证据变化，以及对手对规则的利用。能力无法提供完整答案，现实调查与人物选择仍然必要。长线风险是变成重复预告；应让主角逐步从被动追物转为主动验证假说，并面对“救下这件事会让谁承担后果”的问题。

可以启用能力、谜案证据、历法与社会模块，成长境界停用。原创题面如《失物柜里，是明天的求救器》；开篇需要真正出现这个矛盾，不能只把它写进书名。

## 7 按最新番茄证据生成书名

### 7.1 在现有命名流程上加证据层

当前 title-market-research 已有联网研究、官方书页过滤、最多八个样本，以及同批证据供审核、修复和局部重做复用。原生联网工具路径可能产生单独研究模型请求；第三方公开搜索路径可直接取得资料。V5 延续这些预算和恢复机制，不能把已有功能重新算成新建，也不能把所有路径都称为零额外模型请求。[V5C16][V5C17][V5C18][V5C37][V5C38]

本轮验证了五个官方榜单、每榜前两项，共十本作品，覆盖玄幻脑洞、东方仙侠、都市日常、悬疑脑洞、豪门总裁。官方榜单说明每日更新、统计前一天数据；本轮可见统计截止均为 10 月 28 日 24:00，观察日期为 10 月 29 日。因此产品应显示“最新取得的官方日榜样本”，不显示“此刻实时点击趋势”。[V5F09][V5F10][V5F11][V5F12][V5F13]

十本只用于验证采样链路和展示题面多样性，不代表各题材标题分布，也不能证明某种命名方式导致上榜。榜单名次、在读指标、搜索位置、上架时间和最新章节更新时间分别保存；无法取得的字段保持未知。

### 7.2 采样合同

每个样本保存 bookId、原始标题、详情 URL、频道、分类、连载状态、榜单类型、名次、统计窗口、观察时间、字段来源和可比性。标题乱码时通过同一 bookId 的官方详情核对；仍无法可靠读取则排除，不凭字形猜测。

优先同频道、同主分类、相近作品阶段。没有对应榜单时，可使用官方书目和明确标记的近邻样本；不编造该题材的热榜。样本不足时允许离线或有限证据模式，界面显示范围。目录与书名研究分别缓存，普通方向生成不附带命名搜索。

模型只提炼题面结构：冲突直给、概念悬念、人物态度、情绪氛围等。官方样本中既有《十日终焉》这类概念短题，也有长冲突标题和更短的情绪标题；因此不能将番茄风格固定为“开局＋身份＋震惊”。[V5F12][V5F13]

### 7.3 生成与兑现

同一故事可生成若干不同形态的原创标题，候选数量服从当前合同；不是每种形态都要硬凑。作者可以锁定关键词、语气与长度。显示名与文件目录名分开处理：目录使用稳定项目 ID 或受控名称，不能把 Windows 路径限制误当成文学审美要求。

每个实质题面卖点绑定作者合同与当前可用的设计、计划或正文版本，新增提案单列。世界或开篇尚未建立时相应版本为空，不阻塞基于已有事实的早期命名；已确认设定也不必错误标成计划。正文建立后记录实际推进。长线承诺可以后续兑现，但开篇必须让读者进入承诺对应的矛盾，不能一直用不相关剧情拖延。

修改重生机制、角色身份、关键关系或开篇后，相关标题进入需复核状态。宿主沿事实依赖与查询依赖扫描影响，模型解释已找到的范围；不能凭一次语言判断宣称已扫描全书。吸引力理由可以给具体编辑意见，不输出虚构的点击率、爆款概率或热度分数。

## 8 整个创作流程如何形成闭环

| 阶段 | 主要产物 | 连接下一步的合同 |
| --- | --- | --- |
| 创意讨论 | 作者意图、题材画像、保留与禁区 | AuthorContract 与来源 |
| 三个方向 | 行动引擎、回报、差异、轻量模块建议 | 方向稳定 ID、假设与冻结范围 |
| 作品方案 | 主线、人物定位、世界范围、阅读承诺 | 同版作品与世界候选 |
| 世界与人物 | 生效规则、能力边界、人物内核 | 来源、字段锁、版本与有效范围 |
| 试写与文风 | 样章比较、VoiceProfile、VoiceSlice | 作者偏好与可复用表达证据 |
| 大纲与细纲 | 卷目标、滚动章节、场景合同 | 规则、状态、承诺和读集版本 |
| 正文 | 当前章小说与独立预览数据 | 正文 hash 与来源位置 |
| 记忆更新 | 事件、人物七维状态、信念与覆盖 | 批量 delta、审核与同版采纳 |
| 可视化 | 世界、关系、线索、节奏与承诺投影 | 同项目、分支、版本、视角与水位 |
| 讨论与修订 | 最小变更、依赖组、影响解释 | 版本检查、采纳、失效与重建 |

闭环不要求每一步都额外调用一次模型。分类载入、版本检查、来源定位、画图、查询与缓存由宿主完成。新增模块也不意味着新 Agent；同一次创意请求可使用 world-design 的方法，但仍只提交当前三方向合同。

百万字记忆继续使用 V3 的原文与事件、结构状态、摘要与索引等分层设计。当前章工作包先加入硬约束、相关人物入场状态、所需规则和未结承诺，再做有范围的全文、语义和关系召回。普通写作不读全书台账；“全部未兑现承诺”使用分页的结构化全量查询，不能用向量前几项冒充全部。

记忆保留故事发生、读者看到、角色获知、作者编辑四种坐标。世界规则和角色能力也适用这些坐标。秘密身份不能因内部实体合并就泄漏到早期对白；回忆中的情绪不能覆盖当前状态；修订旧章时既检查具体记录依赖，也检查原先查询为空的条件。

人物每章更新目标动机、情绪评价、认知信念、关系、身体资源、承诺责任、表达策略。实际出场人物有覆盖记录，允许无变化或证据不足；普通章一次批量提取，不为每个角色单独调用模型。人格成长与短时情绪分开，缺席角色显示最后观察状态，不按软件时间凭空变化。

真人化文风仍是主线：用作者认可的原创试写或授权样本建立 VoiceProfile，当前场景只取相关 VoiceSlice。区别角色的注意力、句法习惯、关系姿态与表达策略；保留有作用的解释、心理、长句与停顿。文风修订不能改变人物动机和事件结果，审美效果通过盲评和作者选择检验，不以禁词计数代替阅读体验。

## 9 可交互的创作画布

### 9.1 十五种视图，各自服务一个问题

| 视图 | 作者要解决的问题 | 适合的交互 |
| --- | --- | --- |
| 世界模块卡 | 这本书需要建设什么 | 启停、留白、锁定、围绕模块讨论 |
| 规则后果图 | 一条规则会改变哪些行动 | 展开条件、反制、例外、相关场景 |
| 成长路径图 | 人物怎样获得新可能 | 比较路线、查看前置与代价 |
| 人物关系图 | 谁对谁抱有什么态度 | 选中心、多跳、方向与关系类型过滤 |
| 人物状态时间线 | 他为什么变成现在这样 | 章内事件、前后状态、原文来源 |
| 知情矩阵 | 谁知道、误信或不知道什么 | 人物与秘密交叉，切换章节和视角 |
| 谜案证据板 | 哪个假说被什么支持或反驳 | 连接证据、假说、反证与揭示 |
| 情节线路图 | 多条线在哪里相遇与换向 | 场景分轨、并行线、依赖检查 |
| 双时间轴 | 发生顺序与叙述顺序是否相符 | 倒叙、插叙、历法和章序对照 |
| 叙事节奏图 | 哪里有变化，哪里长期停滞 | 区间对比、来源节点、原文跳转 |
| 资源与规则账 | 东西、资格与权利如何转移 | 按对象追踪获得、消耗、归属 |
| 承诺兑现图 | 书名与伏笔有没有持续推进 | 提出、推进、计划兑现、实际兑现 |
| 地理路线图 | 人物能否及时抵达并相遇 | 地点层级、行程与通行条件 |
| 修订影响图 | 改这一处会影响什么 | 已核验依赖、未决边界、分组采纳 |
| 书名证据台 | 哪种题面适合本书 | 来源与日期、候选比较、承诺定位 |

没有数据的模块不强行显示图。小规模列表或表格更清楚时使用表格；没有真实金额、数量或时间的数据，不用假数值画流量图。地图可以先是地点层级与路线示意，不要求 AI 编造经纬度。

### 9.2 三条最有价值的交互

点击金丹节点，查看可用能力、资格和限制；点击某次突破，定位正文证据；拖动节点只调整排版；修改突破条件则生成语义变更，并标出依赖该条件的角色与场景。

把人物关系图切到第 20 章、某个角色视角，只返回当时能获知的关系与命题。作者视角可对照真相和误信，角色视角不发送隐藏真相到前端后再用样式藏起来。改变关系先显示候选叠层，采纳后才进入正式图。

在谜案板中点一个假说，可以看到支持、反证、来源和读者揭示位置。拖动一条证据到另一个假说表示建立语义关联，需要走变更合同；单纯挪动卡片位置无需模型。

### 9.3 百万字可视化的规模策略

默认呈现当前章、当前人物或当前规则的局部网络，再按需展开一至两跳、按关系类型过滤、分页取回。按章节和对象生成有版本的读模型，避免每次打开面板从百万字全文重建图。

工作线程或宿主进程承担检索与较重布局；UI 合并批量更新，保留稳定节点 ID。新增边或状态时更新受影响部分，不每个字重建全图。全书视图按卷、势力或地点聚合，作者点击后下钻；性能预算必须用真实作品规模测试，不能以组件库演示帧率代替验证。

## 10 实时更新的工程合同

正式内容使用正文与核心记忆的采纳事务，再经 outbox 驱动读模型更新。图谱、角色卡和曲线是投影，不是第二套事实库。所有事件绑定项目、分支、观察范围、编辑版本、对象版本、来源、读集摘要和投影水位。

三个数据通道明确区分：流式预览可撤回，候选绑定候选版本，正史只来自成功提交回执。重做正文、切换分支或取消任务会结束旧预览 epoch；迟到节点不能覆盖新内容。核心状态尚未达到所需水位时显示待同步；可选可视化元数据出错不应破坏已生成正文，但不能因此跳过下一章必需的记忆检查。

过滤后的订阅使用本范围连续序号或不透明游标，不能用全局事务号的间隙判断本视角漏事件。事件具有独立 eventId；来源提交序号与投影序号分开。变更观察范围后重新快照，再从对应游标继续，跨范围不复用旧水位。

现有实时叙事节点协议采用 UTF-16 位置，而 V3 来源合同使用 Unicode 码点。新合同显式保存 coordinateUnit、半开区间、正文 hash、引文与引文 hash，适配层在需要时转换；不能把含 emoji 的位置直接混用。流式锚点必须落在用户已看到的正文范围，未知值保留空缺。[V5C25][V5C28][V5C30][V5C31]

当前另有会增加模型调用的实时节奏预览选项，与同次正文响应携带节点的方式不同。V5 继续把这两种模式及成本分别显示，不把可视化等同于额外模型评分。一般的开图、切章、切视角、筛选和拖布局都不产生模型请求。[V5C09][V5C25][V5C27]

## 13 V5 总控与本轮提示词全文

### V5P05 识别所需世界模块

依据原始创意、明确要求、现有设定和可用题材资料，提出创作画像与 enabled、disabled、undecided 模块清单，说明各项依据和来源。类型惯例只作建议，不覆盖作者禁用或补造官方分类。区分世界能力、成长路径、社会地位与资源权利；需要能力不等于需要境界。已有选择保持稳定，关键冲突列为可处理分歧，非关键留白不阻塞继续创作。作为独立操作时只提交画像候选；首次三方向中的轻量判断复用该次请求。

### V5P06 沿用与整理作者已有体系

逐项整理作者提供的世界、境界、能力与制度，保存原文来源及标准化候选。名称、排序、能力边界、限制、例外和作者锁定内容保持一致；不能把常见模板当缺失事实补入。区分等价整理、解释候选与待决歧义，给出覆盖和未解析片段。作者允许补缺时只补开放字段，新增内容单列。条件依赖和非线性路线按原意表示，不强转为线性等级。宿主核对原文覆盖与字段锁后按已有授权采纳。

### V5P07 建立世界规则候选

只展开已选方向、本轮授权范围与实际启用模块。关键规则写清适用者、触发、条件、效果、限制和可用反制；代价、数值与例外只在确有需要时填写，作者允许的无代价能力通过其他具体冲突承担戏剧压力。成长路径可无等级、线性、分支、多轴或自定义，战力不自动等于地位。每项核心创新连接一个开篇行动和可持续后果；保留真相、信念与揭示分层。对当前故事无用的百科先留白，只提交有来源和依赖的世界候选。

### V5P08 推演世界规则与故事后果

针对指定规则与合法已知状态推演首次应用、弱者利用、对手学习、规模扩散和重复使用后的边界案例。检查资源与制度后果、反制是否真实、例外是否有依据，以及人物仍需做什么选择。悬疑侧重信息可得性、误导和证据闭合；现实题材侧重职业制度与利益。软世界保留作者允许的神秘，不强迫数值化。只提交有依据的问题和修订候选；不自动改规则，不模拟出不存在的已发生事件，不因本技能存在逐章追加调用。

### V5P09 提出局部变更

把作者明确修改意图转换为当前对象版本上的最小 ChangeSet。允许混搭题材、启停模块、保留自有境界或新增自定义对象；只改授权字段，依赖变更分组。区分故事内未来变化、历史纠错和修订设定，列明宿主影响扫描的范围与未决边界。平台映射变化不自动改故事，拖动画布坐标不生成剧情变更。已有授权且可回退的操作不重复求确认；重要新前提保持候选，未选修改不能一并采纳。

### V5P10 建立完整作品方案

将已选方向、作者要求、已处理新增设定与本书世界模块连接为作品方案。明确主线行动、核心人物、世界约束、阅读承诺与终局边界；平台分类保存在独立映射，不能限制创作画像的混搭。只覆盖实际启用体系，停用与未定模块按 V5 合同表示。已确认作者体系原样沿用，需要的新规则单列；已包含的设定拆解不再重复请求。提交的方案与世界候选共享稳定标识和版本依据。

### V5P11 收集并分析相关证据

只使用宿主提供或授权取得的一手证据，分别处理书库目录、榜单目录、作者标签规则、官方书页与真实读者反馈。目录完整性只适用于已核验的表面、频道和返回范围。书名研究按同频道、主分类和作品阶段比较，保留榜单类型、位次、统计截止、观察时间与样本覆盖；搜索命中不称热榜，近邻补充明确标记。提炼可观察的题面形态，不把样本频率解释为成功因果。数据缺失保持未知，离线与旧快照显式降级；不重复发起宿主已完成的取样。

### V5P12 书名候选

依据当前已确认故事、可用世界与开篇资料、作者偏好和有范围的题材样本，生成本轮合同规定数量的原创书名。世界或提纲尚未建立时按已有依据提案，不补造版本。可比较直给冲突、概念悬念、人物态度或氛围短题，只选适合本书的形态，不强制长标题、开局句或感叹号。每个实质卖点对应已确认内容和预计兑现位置，新增承诺单列候选。标题须有具体阅读欲望，避免关键词堆砌、虚假身份和近似照搬。保留冻结候选与作者保留词；长度服从实际合同，显示名与文件目录分开。沿用样本不足、近邻、过期、失败或停用状态，不假称实时热榜。推荐理由基于本书和可核验证据。

### V5P13 核验指定题面

宿主先按 targetKind 解析实体名、书名或简介的唯一合同。审核指定候选版本、作者要求、名称保护、实际长度与揭示边界；书名和简介同时核对承诺已有的设计、计划或正文依据及其版本，不要求补造尚不存在的世界或开篇。实体名审核不要求榜单资料。搜索位置不能作为热度依据，样本风格是参考。吸引力判断给具体原因，不伪造点击率或爆款概率。事实错误与审美建议分别标记；只交当前审核结果，不改写候选、不再启动审阅。

### V5P14 规划当前章场景

为当前章节确定场景目标、参与者入场状态、冲突、主动选择、代价或限制、实际后果与承接点。只读取场景涉及的已启用世界规则和相关记忆，使用者能力、资源、资格与知情分别核对。世界规则要通过行动和结果起作用；不为展示体系加入无用讲解。保留尚未揭示的真相、允许的未知和作者锁定结果，必要新增前提另列候选。场景计划与世界、人物和承诺版本绑定，不提前把计划写入事实。

### V5P15 生成当前章正文

依据本章场景合同、角色入场状态、有限记忆包、世界规则片段和 VoiceSlice 写正文。让人物用已知能力、资源和关系主动行动，遵守规则的条件与已确认例外；未启用体系不强加升级，能力变化需要剧情依据。把核心卖点落实成可见选择和回报，避免百科式解释。读者尚未知道的内容按揭示计划处理，人物不能利用未获知真相。只交正文及本轮实际允许的独立元数据；预览节点不能改变正文，也不能自称已经更新正式图谱。

### V5P16 批量提取本章增量

从指定正文与有效入场状态批量提取世界、人物七维变化和逐人覆盖，引用正文 hash、原句和明确单位的位置。区分规则被应用、人物相信某规则、规则出现新证据及作者真正修改规则；一次异常不自动成为新世界法则。境界、资格、资源和知情分别记录，未启用模块无需补空表。回忆与当前变化按时段分开，人物可无变化或依据不足。只产有来源稀疏候选，遵守实际 read-set；正式图谱与记忆由宿主同版提交。

### V5P17 检查跨章连续性

按宿主提供的完整性范围核对指定正文、世界规则、人物状态、资源与承诺。区分世界真相、误信、软规则留白和正式例外，不能因为题材惯例不同就判错。检查规则条件、成长路径、物品和资格转移、信息揭示与人物行动是否有依据；给出冲突位置和关联版本。资料不完整时限定结论，未检索到不等于不存在。问题和修订候选分别提交，不自动修改已采纳内容。

### V5P18 解释变更影响

解释宿主实际扫描出的变更影响及覆盖边界，连接世界规则、人物信念、场景、承诺、书名和投影。区分必须重新核验、可保留与待人工判断，不能自行宣称已发现全书全部依赖。作者只改布局时无剧情影响；修订世界事实或正文时沿来源与查询依赖评估。保持未授权对象，语义变化需要重算时不能盲用旧增量。只交影响解释与分组建议，执行和恢复由宿主负责。

### V5P19 核验阅读承诺

依据宿主完整承诺查询和来源范围，检查作品方案、标题、简介与正文提出的承诺是否得到实际推进或兑现。区分计划兑现、正文已兑现、延期、放弃候选和证据不足；不能把提纲或模拟事件当成完成。世界或开篇修订破坏题面承诺时标记需复核，不能擅自改名。对吸引力给具体编辑判断，禁止以模型评分伪装读者数据。只交当前审阅结果，不追加重复审核。

### V5P20 简介与题面文案

结合本书声音、可用标题和已确认故事，写出人物处境、特有矛盾与读者可获得的回报。已有同题材样本可参考表达形态，保留作者语气和揭示范围，不借包装增加能力、身份或情节。实质承诺绑定已有设计、计划或正文依据；未建立世界或提纲时不补造版本，没有正文时不能假称已兑现。长度和候选数量服从当前合同。只提交候选文案和允许的独立承诺数据，不发布、不改正式名称。

### V5P21 核验本章记忆候选

在原有独立记忆审核位置核验本章候选与指定正文、世界及读集版本。检查人物覆盖、引用单位、身份与时段，区分已观察事件、规则解释、人物误信和作者决定；一次规则异常不能无依据升格为新法则。检查境界、资源、资格、关系与心理变化的证据，允许无变化或无法判定。正式状态未就绪时由宿主按实际合同处理，不能因为可视化元数据可选而跳过核心记忆要求。只交问题，不另起逐角色审核。


## 14 数据合同与迁移接点

新增 world-contracts-v5.ts 包含分类快照、创作画像、发布映射、作者原文标准化、字段锁、模块选择、世界规则、成长模型、书名证据、阅读承诺、实时投影和语义变更合同。它复用 V3 的范围、读集、故事时段与叙述位置，不另造一套时间系统。

分类证据 JSON 是已保存的研究快照，必须经适配器规范化为运行时 PlatformTaxonomySnapshotV5；不能直接把研究文件声明成已可执行配置。分类快照摘要对应保存的已解析 JSON 表示，榜单与书籍摘要对应保存的 HTML 文件，两者不一概称为原始 HTTP 字节摘要。

作者状态与世界规则的核心持久化复用 V3 事件与关系结构，增加类型列、索引和模块字段。仅在现有 schema 无法表达时新增表；避免让世界模块、图谱和记忆各自保存一份互相覆盖的真相。

| 接点 | 应修改的范围 | 迁移要求 |
| --- | --- | --- |
| 分类与入口 | shared/tags、core/tags、TagWorkspace、App | 保留 154 个旧 ID，身份含表面、频道、分组、原生或稳定本地 ID |
| 世界阶段 | core/domain、skill、skill-output-contract、validation 与共享合同 | 模板、schema、validator、renderer 同一版本上线 |

| 技能运行 | V4 装配、工具适配器和任务快照 | 新任务使用 V5，冻结任务继续原合同 |

旧作品的世界 Markdown 保留为来源与可读导出，新增结构化模型通过只读解析和候选对照导入。旧 S03 任务继续八栏目合同；必要时用兼容适配器表达“不适用”，等作者进入 V5 后再采用模块合同。不要直接全局替换旧提示导致恢复任务失败。

## 15 开发顺序与验收

### 15.1 开发顺序

第一批先接 V3 核心记忆、人物覆盖和版本事务，再落地 V5 数据合同、字段锁与分类分离。作者可立即获得更完整的题材入口和已有体系继承，不增加默认模型调用。

第二批完成模块化世界流程与共创变更：替换固定八栏目，接入三方向的轻量模块建议，世界和人物用统一候选、依赖与采纳合同。新增压力测试保持按需。

第三批升级书名证据与承诺绑定，展示样本日期、范围与降级状态；保留现有生成、冻结、审核和恢复流程。实际比较旧版与新版标题时保持故事事实、候选数量与预算一致。

第四批先上线世界规则图、人物知情矩阵和修订影响图，再按真实写作需求增加其他画布。显示、筛选与拖布局不调用模型，较重读模型后台更新，核心写作状态优先保证。

第五批进行代表性长篇、混合题材、旧作品迁移和盲评。记录运行成本、上下文量、延迟、人物知情错误、规则矛盾、作者接受率和返工范围。没有真实读者数据时，阅读吸引力只能报告盲评结果，不能宣称已获得市场转化。

### 15.2 必须覆盖的边界

都市明确要异能时能启用能力；仙侠明确不要境界时能停用成长。传统境界名称、顺序和例外不会被创新提案覆盖。多个体系可以并存，不因图形布局把现实关系变成线性等级。

旧 154 个标签 ID 不变；女频分类全部可选；没有对应榜单的分类仍能创作。分类刷新失败不删除旧项；328 个内容标签不假称已完整实时核验；混搭创作不被发布主分类限制。

标题样本的抓取时间不冒充统计时间，搜索命中不冒充热榜，样本不足有明确范围。世界或开篇变化使相关标题承诺进入待核验，而不是悄悄改名。

图面拖动不改故事；角色视角不会拿到未知秘密；草稿撤回能清理预览；迟到流片段不会覆盖新分支。过滤订阅不误用全局序号，正文含 emoji 时来源仍能正确定位。

本轮新增 32 个待执行行为与质量案例，其中 17 个本地合同案例、13 个模型输出案例、2 个盲评案例；它们覆盖本轮关键边界，不是全部 19 个技能的完整回归套件。案例定义与执行记录分别保存，未运行的案例保持 not_executed。

公开资料另完成 79 项数据和结构核验，覆盖分类、稳定映射、榜单与书目关联、日期和案例结构。设计包通过 1,323 项静态检查，实际目录、注册表、案例和模块 JSON 及七份合同通过 TypeScript strict 与 noUncheckedIndexedAccess 核验。类型与目录验证只证明设计文件可解析及相互一致，不代表生产功能已经实现；本轮未执行付费模型实验，也未宣称完成百万字运行基准。
