# V7 架构改造与功能接入清单

## 实施目标与版本关系

保留 Electron 独立写作内核、TypeScript、Pi、SQLite、内容对象、统一模型与工具网关、候选采纳和任务恢复。先整理创作业务的责任边界，再接通 V3 长篇记忆和人物、V5 动态世界与可视化、V6 质量与自由探索。V7 不新增必须常驻的 Agent，也不改变 19 个设计技能包、48 个操作与 50 个注册绑定的范围。

本文件的 R0—R5 是 V7 的实施顺序，取代 V6 A—F 的排期顺序；V6 的创作目标、提示词、质量协议、数据边界和案例继续有效。阶段批次只安排开发，不要求作者按同样顺序创作。旧文件保留用于追溯，新实施从本文件进入。

源码审计基线为 0.4.82，提交 `b505f6f459db74871f39f63acf6106b827c8a353`。实施前必须核对当前实际 HEAD、适用 AGENTS.md、工作区改动和测试入口；已实现部分沿用，不能回退用户的新代码。当前审计证据见 [当前架构审计](current-architecture-audit-v7.md)，目标边界见 [Agent 架构](agent-architecture-v7.md)。

先建立当前行为清单和少量可重放的请求、回执、候选及提交夹具。区分已存在的运行机制与待扩展的领域功能，不把目录调整当成一次架构迁移。

| 工作 | 完成条件 | 保留的证据 |
| --- | --- | --- |
| R0.1 实际基线 | 记录代码提交、工作区差异、运行环境、规则及模型配置版本 | 基线记录和已有能力对照 |
| R0.2 数据与任务所有权 | 明确正式作品、候选、任务、请求、工具、投影各自的写入者 | 状态所有权表与调用入口 |
| R0.3 恢复行为 | 重放重复点击、发送后未知、停止后迟到结果、过期候选、数据库提交后文件未写完 | 实际请求次数、回执、状态迁移和事务标识 |
| R0.4 老任务兼容 | 已保存任务继续使用原 executor、checkpoint、prompt 与合同版本 | 支持版本表和不能自动恢复的原因 |

现有 SQLite 事务、CAS、审批指纹、Outbox、单项目写锁、模型意图与预算账本、工具回执、增量快照已经存在。R0 的任务是确认它们在实际 HEAD 的边界和相关回归，而非再建立一套同名机制。[源码：正式事务](https://github.com/965896829/xingyue-shutai/blob/b505f6f459db74871f39f63acf6106b827c8a353/src/core/storage.ts#L744)；[源码：Pi 宿主边界](https://github.com/965896829/xingyue-shutai/blob/b505f6f459db74871f39f63acf6106b827c8a353/src/core/runtime/task-loop.ts#L40)

退出条件：保存一组可复用的基线证据；受影响的已有故障回归没有已知失败。没有运行的项目明确保留为未执行，不转写为通过。

## R1 拆分命令与领域工作流

从现有 Service 和 AgentRunner 中逐步抽出开书、章节、讨论、修订四类流程。第一批抽取保持当前对外命令、请求装配、预算、候选语义和恢复行为；不要在同一补丁中同时替换存储、供应商协议和所有提示词。

应用命令处理器负责接收作者操作和校验输入，工作流负责步骤与依赖，执行层负责模型和工具回合，正式提交服务负责采纳。模型能力与协议兼容策略移入供应商适配边界；工作流只声明所需能力，不另开绕过统一网关的连接。

工具定义明确声明副作用、允许范围、幂等与结果未知处理，不再仅靠工具名称前缀判断。先迁移现有工具的等价效果，不同时扩大权限；新增写工具在对应能力接入时另行验证。宿主按登记的实现校验这些声明，外来 Skill 不能自行授予写入权限。现有 `runtime/operations.ts` 仍是用户命令的幂等回执；新增能力注册目录不能替代它。

退出条件：同一基线夹具在重构前后具有相同的外部请求、候选范围、预算与恢复结果；新的业务流程能够单独定位和验证。回退通过恢复原处理器绑定完成，不能删除已经持久化的请求与作品记录。

## R2 统一任务契约与整份请求的可见范围

建立版本化任务与能力契约，复用 V3/V5/V6 的作品身份、作者授权、读集、基准版本、分支与预算类型。定义动作处理器、输入输出 schema、提示词配置、工具、副作用、上下文策略、验证和恢复方式。已有 Run 与 ExecutionRecord 继续承担执行持久化，不为新注册目录再建立竞争的任务账本。

| 工作 | 完成条件 | 关键边界 |
| --- | --- | --- |
| R2.1 双体系兼容 | 26 个现行资源与 19 个设计包有明确映射及版本路由 | 不能把固定 26 直接改成 19 后绕过历史资源检查 |
| R2.2 按资料放行 | 任务依据实际前置产物、范围、版本和授权决定可运行性 | S01—S11 保留为新手路线，不成为所有讨论的必经门禁 |
| R2.3 视角编译 | author、reader_prefix、character_turn 使用各自允许的资料 | 总控与共同方法实际替换，所有请求表面受同一范围约束 |
| R2.4 依赖检查 | 正向读取、空结果和条件查询都能发现相关变更 | 不以仅比较几个已返回文件 hash 代替完整依赖核验 |
| R2.5 激活条件 | schema、handler、授权、恢复、验证和界面入口全部接通后才允许开放 | 设计注册继续 active=false、adapter unavailable |

视角范围覆盖系统、方法、工具定义与结果、消息、附件、引用、检索、缓存身份、原生会话和错误反馈。秘密 canary、期望答案和宿主私有核验证明仅供测试或宿主，不进入模型上下文。相同文字不代表可以跨视角复用会话。

退出条件：任务装配和权限边界可通过实际出站请求与工具轨迹验证；独立请求不能因历史、缓存或错误修复继承全知资料。用户已经明确授权的候选局部修改直接执行，正式采纳继续依据作者策略走统一入口。

## R3 完成一章同版采纳的完整链路

以一章正文为第一条业务验收主线：章前人物与必要约束查询、正文候选、原有必要审查、核心记忆和批量人物变化、作者采纳、正式快照、局部查询与界面刷新。现有正文、审稿、记忆与采纳链继续复用，R3 为它补齐 V3/V6 的明确领域合同和依赖，不重新制造同名流水线。沿用现有事务，将新增领域记录纳入同一正式版本。

人物层区分稳定人格与当章状态。每个出场者都检查变化，也允许无变化、依据不足和仅提及；不能为了填表改写人格。作者真相、人物误信、计划和正文事件分别表达，有依据的情绪、目标、行动与关系变化才形成状态差异。所有人物可由一次章后任务批量处理；场景排演的角色回合按需启动。

正文编辑或探索合并后，以最终正文 hash 重新绑定必要检查与记忆，不能沿用旧候选的状态差异。正式提交的核心必须完整；阅读体验、解法比较等附属结果有独立可解析载体，允许失败和重建，不把核心记忆降级成可选。

人物卡、关系图、知情边界、伏笔、时间线使用同一正式版本或明确的候选分支。图上改语义产生 ChangeSet，拖动布局不写作品事实。运行事件记录任务发生了什么；叙事领域事件记录故事发生了什么，二者不互相冒充。

同步完成旧世界模板与新模块的数据迁移设计，保留原文、身份、来源 hash 和作者已有选择。题材仅推荐模块，作者可沿用自有体系、混搭、停用或暂不确定，不强制境界、金手指、代价或固定冲突套路。

退出条件：当前章、人物状态和关键记忆同版可追溯；改前文后受影响项正确失效，后续查询不使用旧结果；可选投影不可用不影响已完成核心版本的浏览。第一批真实样稿与匿名比较基础在此建立，沿用 V6 质量协议。

## R4 按实测优化百万字更新与查询

现有 `delta-v1` 已压缩历史快照；真正需要测量的是正式提交的全台账事实重建、当前查询的全事实扫描、重复来源读取与向量排序成本。不能把“磁盘快照是增量”误写成“所有处理已增量”，也不能把这些路径未经测试就写成已发生的性能故障。[源码：事实重建](https://github.com/965896829/xingyue-shutai/blob/b505f6f459db74871f39f63acf6106b827c8a353/src/core/storage.ts#L807)；[源码：增量快照](https://github.com/965896829/xingyue-shutai/blob/b505f6f459db74871f39f63acf6106b827c8a353/src/core/snapshot-codec.ts)

先用有实体、事实、来源、时间变化和历史修订的语料测量，再依瓶颈实施可索引字段或映射表、变更集级事实更新、同源版本的校验复用和局部关系查询。内容 hash 与原文坐标的校验可以复用；当前正式版本、可见范围和修订待核对状态仍须重新核验，不能把字节相同当作当前可用。增量实现必须与全量重建参考结果一致，仍保留灾后重建和人工修复路径。需要时再替换向量索引适配器，不预设引入外部图数据库。

测试覆盖 100、500、1000 章的代表性档位，并逐步增加事实和修订量；报告语料性质、章节、字符、人物、事实、证据、索引、设备、缓存条件、样本数与操作耗时。比较提交、上下文编译、人物查询、重建、取消响应、首屏、内存和存储增长。性能目标在优化前根据基线与目标设备确定，不能看过结果后修改阈值宣布通过。

退出条件：同一输入下的语义结果保持一致，关键操作达到预先记录的性能目标，停止与恢复有效。重复文字填充的体积测试保留其用途，不能计为长期叙事和人物因果准确率验收。

## R5 按依赖接入 V6 增强与产品验收

| V6 能力 | V7 接入条件 | 沿用的质量要求 |
| --- | --- | --- |
| 本书声音与改稿学习 | 编辑证据、作用域和版本撤销可用 | 纠错不冒充审美，人物和作品偏好不无依据扩散 |
| 探索草稿与人物排演 | R2 范围与分支契约、R3 合并采纳可用 | 空作品可探索，有限角色回合，最终正文重新提取 |
| 读者首读 | reader_prefix 整请求隔离与展示版本可用 | 按实际阅读截止取材，不混入作者真相和答案 |
| 跨章解法比较 | 有来源的场景索引与覆盖范围可用 | 允许有意回响，不用相似度自动改稿 |
| 真实反馈分析 | 原始反馈与宿主统计、实验记录可用 | 模拟与真人分开，分母、平局、弃权和排除保留 |
| 世界与交互工作台 | 动态世界契约和同版投影可用 | 所有语义修改回到统一 ChangeSet 与采纳 |

可视化以已存结构化数据派生为默认。额外语义分析明确计费、可取消、可异步；不再让每个面板自行生成一份事实。必要检查留在主流程，可选观察不无条件阻塞正文呈现或核心采纳。

沿用 V6 四层质量验收，执行相关 40 个 V6 案例及 V3/V4/V5 有效回归。V7 的 24 个案例用于架构边界，不替代真实模型、连续章节、真人盲评和平台数据。LangGraph TS 仅在编排维护负担有证据时局部试点；Temporal 等外部服务待跨机器持续任务或多人协作成为实际需求后再评估。

退出条件：每个开放能力都有完整输入到产物、状态、界面与恢复的实现证据；记录实际质量、成本、耗时、迁移结果与未执行范围。没有 adapter 的能力不能靠切换设计注册状态显示成已完成。

## 持续交付与回退

每批交付代码差异、影响行为、实际运行命令与结果、未运行项、迁移和回退方式。独立工作可以并行，正式写入继续由既有宿主顺序提交。结果未知的付费请求按原记录核对，不因租约或工作流重启盲目再发。

旧作品按版本迁移；迁移前保留可恢复基线，迁移失败回到可读旧版本，不删除未识别原文或强行合并角色。回退通过新修订、原 handler 绑定或关闭新增入口完成，保留旧事件、请求和作品历史。只有依赖缺失核心状态的操作被阻断，讨论、手工创作和隔离探索继续可用。
