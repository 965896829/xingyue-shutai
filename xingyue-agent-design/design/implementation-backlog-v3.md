# V3 实施与迁移

## 21 数据与文件接入

| 位置 | 核心改动 |
| --- | --- |
| shared types 与 studio | 时间、版本、独立信念、人物覆盖和查询作用域 |
| storage | 复合索引、增量提交、投影、水位和依赖查询 |
| memory records | 原来源兼容、码点证据校验、按 hash 缓存 |
| memory studio | 数据库范围查询、人物视角、游标分页 |
| context compiler | 本章必需记忆、人物入场状态和预算工作包 |
| runner 与 memory review | 新增量合同、同 hash 候选、批量覆盖和独立核验 |
| service 与 story impact | 采纳事务、查询依赖失效和修订重放 |
| embeddings 与 prose index | 增量队列、批量向量、后端适配和水位 |
| UI | 章内状态、历史版本、信念对照、来源和更新覆盖 |

新 TypeScript 与 SQL 文件是设计合同和迁移参考，需通过实际 schema、adapter、验证器、事务及恢复实现后启用。现有 V2 SourceRef 草案使用 UTF-16 位置，当前项目证据采用码点；V3 明确使用 Unicode 码点，并要求适配器验证转换，不能混用。

独立人物合同中的候选和正式状态由宿主决定，模型不能通过填写一个字段授予自己正式写入权限。SQL 示例使用独立前缀展示增量结构，实际接入映射到现有权威来源与事务，不运行新旧两套相互竞争的正史。

## 22 迁移和实施顺序

第一批先修记忆基础：区分正常有效期结束与纠错撤回；完善人物误信命题；改全量事实查询和全台账输入；在现有采纳事务上引入结构化增量。先验证有来源、有边界、能回放。

第二批加入人物动态心智：正文名单、逐人物覆盖、章内事件转移、目标与情绪的有效范围、人物信念及入场状态编译。把现有模板要求变成可检查的工程能力。

第三批完善检索和修订：中文别名、混合召回、因果与承诺查询、查询依赖、来源缓存、后台水位，以及可替换向量后端。用基准决定是否开启 ANN 和重排。

第四批接通可视化与共创：角色变化面板、作者和人物视角、版本回看、事件来源以及讨论中的局部修改。已有画布可先接入稳定投影，复杂图形编辑后续扩展。

旧项目迁移先核对事实 ID、来源、有效区间和 snapshot，再建立索引与投影。旧误解条目缺少具体命题时标待核对，不能自动补写。旧章节原文和台账留作可回退来源；新模式通过版本开关启用，在途任务保留原资源 hash 和旧工具合同。

## 23 交付使用

设计包保留上一版的总控、26 项兼容技能、5 份创意与命名资源、共创协议、声音与正文专项。新增长篇记忆、人物心智、检索与修订设计，V3 数据合同与 SQL 草案，章后更新和审核提示词，原创多章示例、评测计划及可复现查询原型。

阅读顺序为本报告、design 的 V3 设计、vnext 的 V3 合同与提示词、evaluation 的测试与原型，最后查看 audit 来源索引和验证记录。当前协议以 V3 文档为准，旧兼容路线继续服务尚未迁移的 0.4.82 任务。
