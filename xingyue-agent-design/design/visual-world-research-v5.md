# V5 可视化与世界观工程研究

核验日期：2026-10-29。范围：一手官方文档、发布记录、许可文本与选定源码；未安装组件，未执行应用集成或性能测试。项目采用 Electron 44.6.0、React 19.3.0、TypeScript 5.9.3、Vite 8.3.3、React Query 5.103.1 和 Pi 1.4.0，当前没有图谱库依赖。[V5V01]

## 1 选型结论

保留项目现有小型 SVG 关系图，并把首批新增组件收敛为 React Flow + Apache ECharts。React Flow 优先承担尚缺的世界模块、境界/能力先决图与线索编辑板；ECharts 承担多指标节奏、出场热图、资源/承诺变化与联动选章。现有关系图和实时节奏的具体源码证据由并行项目审计报告提供，本文件不把已有能力写成新增能力。已有 React Query 继续作为查询缓存，不再引入平行缓存真相。

人物图默认以当前人物、卷、场景或关系类型形成有限邻域，先升级现有 SVG 的语义、筛选和证据交互。等实际全书网络查询、路径分析或大图基准显示需要时，再懒加载 Cytoscape.js。G6 是一套可替代图引擎，不能把它与 Cytoscape 同时当默认依赖。vis-timeline 只有复杂时间区间编辑明显超过现有图表能力时加入。Yjs 只在多人共同编辑或跨设备并发出现时再引入。

这是对当前栈与工程规模的选择，不是对所有图库的全局排名。库版本仅为本轮可复核候选，接入时锁定经过测试的确切版本。

## 2 能直接采用的部分与需要适配的部分

### React Flow

直接采用 npm 包、节点/边模型、键盘操作、选择与连接交互。作品字段通过自定义节点显示。依赖连接可使用连接验证拒绝成环，普通人物关系、资源循环和因果反馈不应统一设置为 DAG。[V5V03][V5V05][V5V06]

性能策略采用官方建议：节点和回调稳定引用；选中对象与全图数组分开订阅；折叠大树；简化视口外或低缩放级别的细节。图库不提供本项目的正史采纳、人物知情或来源验证。[V5V04]

React Flow 官方明确没有内置完整自动布局解法。第一阶段沿用确定性层级位置和作者布局；需要自动布局时通过独立 LayoutAdapter 接 Dagre、ELK 等，分别核验版本、许可和性能。其 MIT 核心与收费 Pro 示例、模板和服务属于不同交付范围，不能把网页中所有演示代码一并视为可直接复制的 MIT 核心。[V5V37][V5V38]

### ECharts

用数据驱动更新和交互事件做图间联动。图表接收已投影数据，不从小说正文临时编造指标。设置稳定 series id，局部更新保留缩放窗口；点击峰值定位到章节和支撑事件。[V5V09][V5V10]

dataset 可帮助共享表格数据，但图网络等特殊结构不能假定全都接受同一个 dataset。作品对象模型先独立定义，再由每个图表适配。[V5V11]

### Cytoscape.js / G6

Cytoscape 适合需要图查询和路径的视图，支持 JSON 与渲染分离；大量元素时控制标签、复杂边和动画，成批修改后只对需要区域重新布局。[V5V13]

G6 的多渲染器和布局是另一条路线。选择 WebGL 不会自动解决数据量、语义过滤或线程阻塞。其 5.x 已移除内置 undo/redo，说明作品级撤销本来就应由宿主的版本与 ChangeSet 管理。[V5V16][V5V17]

### vis-timeline / Yjs

vis-timeline 对普通日期和时间区间很方便；虚构历法、未知时段和“约三日前”必须保留宿主的时间表示，不能为适配 JavaScript Date 而制造精确时间。[V5V20]

Yjs 解决共享数据并发同步。它不能判断“同一角色在同一场景有两个互斥动机”应采纳哪个，也不能替代 V3 的版本、来源和授权。[V5V23]

## 3 两个新增创作工程参考

### Novalist：类型可扩展、实体随故事位置变化

固定提交：176673f36923db488b444e2ef2552d5611cb88fb。实际 MIT LICENSE 已核验。[V5V31]

README 描述 Electron/React 前端与 .NET 10 核心，提供世界资料、场景、规划和图谱工作区。与当前应用前端接近，但其核心与存储模型不同，不能整套直接嵌入。[V5V25]

实际源码值得借鉴：

- CustomEntityTypeDefinition：自定义实体类型、字段类型、默认值、枚举、必需项，以及关系和章节分区开关。适合借鉴为“世界模块和自定义实体”，让作者自行创建宗门、能力、法律、案件或职业体系。[V5V26]
- EntityStateOverride 与 EntityStateResolver：实体可以有 act/chapter/scene 局部状态，包含地点被毁、物品易主等；展示时选择相应范围的状态。这为世界观不止静态百科提供参考。[V5V27][V5V28]
- PlotLanes：React/SVG 多情节线，共享场景被突出，点击回到场景。可以作为轻量情节编织图的表现参考。[V5V29]
- PromisesPanel：承诺与兑现场景的成对连接、未兑现/断裂/顺序状态、回到正文。可借鉴面板交互，状态语义应映射到 V3 的完整承诺来源合同。[V5V30]

其范围覆盖优先规则不具备本项目 V3 的四个时间坐标、来源位置、人物获知和编辑分支语义。移植时应复用自己的投影系统，而非让 Novalist 的 overlay 成为第二份事实。

### StoryLine：场景矩阵与多线叙事可视化

固定提交：6aa9800fddd7800d8af3e1fea0ce3023b58fff14。实际 MIT LICENSE 已核验。[V5V36]

这个项目是 Obsidian 插件，README 描述场景矩阵、泳道时间轴、地铁式情节线、自定义 Codex 类型和反向引用。它的新增价值主要在“多视图查看同一场景与实体”。[V5V32]

本轮读到的源码表明：

- StorylineView.ts 用 SVG 绘制多情节线并按 act/chapter/sequence 排序，还会排除尚未提升成场景的便笺；这种“草稿想法与正式场景分开”的语义值得保留。[V5V33]
- StoryGraph.ts 根据场景、人物、地点和道具建立图，并提供类型筛选；其 wikilink/名字身份应替换为星月书台稳定 entityId 与有来源关系。[V5V35]
- RelationshipMap.ts 使用两两斥力、每帧重建 SVG；源码说明该简单方式针对少于 100 个节点。不能照搬为百万字全书关系图的性能底座。[V5V34]

结论：借鉴视觉组织和交互，局部 React/TypeScript 逻辑可在许可与适配检查后提取；不要整个复制 Obsidian 宿主、名称解析或全图物理模拟。

## 4 推荐面板：让每种结构选对表现形式

以下为本次工程设计，不是对外部项目功能的转述。

| 面板 | 主形态 | 关键交互 | 对作品的作用 |
| --- | --- | --- | --- |
| 世界模块 | 可折叠卡片与模块依赖图 | 启用、停用、导入、锁定、单模块讨论 | 决定本书需要哪些体系 |
| 境界与能力 | 先决有向图＋能力/成本矩阵 | 对照两条成长路线，点开条件与反制 | 显示能力变化及代价，避免只排境界名 |
| 世界规则 | 规则—受影响对象—后果图 | 点击规则查看场景实例、例外和冲突 | 让创新规则进入情节因果 |
| 人物关系 | 有向、多类型、可按时点过滤的关系图 | 选人物展开一两跳，切作者/人物视角 | 显示关系来源和变化 |
| 人物状态 | 事件时间轴＋七维变化列表 | 对比入场/离场状态，回到证据原文 | 解释变化，不强造精确心理数值 |
| 知情与误信 | 人物×秘密/命题矩阵 | 切换故事时点、人物获知事件 | 防止作者知识泄漏进人物对白 |
| 悬疑线索 | 证据—假说—反证板 | 查看支持/反驳、信息已向谁揭示 | 保留误导与真相的层级 |
| 情节编织 | 多线地铁图或章节×情节线矩阵 | 选择共享节点、拖动计划次序 | 看出交汇、断线、重复与空窗 |
| 双时间轴 | 故事发生与叙述揭示并排泳道 | 连接同一事件的两种位置 | 处理闪回、并行和非线性叙事 |
| 节奏 | 多指标曲线与事件锚点 | 刷选章节联动正文、筛选指标 | 保留实际观测与模型判断区别 |
| 资源与势力 | 流向图、关系图和区间台账 | 查看来源、消耗、所有权与条件 | 仅在真实有数量时画定量流量 |
| 阅读承诺 | 提出—推进—兑现链＋到期列表 | 跳转证据、比较计划与实际 | 管住伏笔、目标和读者期待 |
| 地点 | 层级树＋旅行路线，必要时地图 | 过滤故事阶段，检查通行限制 | 地图坐标不冒充真实距离 |
| 变更影响 | 对象依赖图与差异列表 | 选依赖组、预览受影响对象 | 局部修订仍能闭环 |
| 书名工作台 | 候选卡＋题材样本分布 | 看来源时间、比较承诺与正文吻合 | 真实数据、模拟判断分别标记 |

不能把“所有内容都图谱化”作为目标。数十个字段的角色档案用表单与证据列表更清楚；路径与关联再用图。键盘、搜索、列表替代视图必须保留，颜色不能成为唯一语义。

## 5 实时更新的工程闭环

### 5.1 三类状态

- 生成中预览：只进入当前任务的候选覆盖层，可随任务取消清除。
- 待采纳候选：有完整对象与版本绑定，但不改变正式记忆和关系。
- 已提交正史：通过宿主事务形成新版本；从它更新正式投影与面板。

打开面板不调用模型。模型流式输出可以显示局部预览，但不能边生成边写正式人物关系。

### 5.2 统一投影键

建议查询同时绑定 projectId、branchId、canonRevision、storyTimeScope、revealScope、perspective、projectionVersion。当前编辑分支、故事时间、作者/人物视角都影响图中内容。

候选图使用 candidateId 和 baseRevision 叠加在已确认底图上。故事分支、编辑分支、不同世界线的 ID 不能互相替代。地点移动只改布局时，保存到 UI layout 状态，不生成小说事件。

### 5.3 事务、事件与订阅

宿主在同一个核心提交事务中写作品变化、关键状态与 outbox。提交成功后发布带事件 ID、顺序、提交版本与受影响对象 ID 的通知。投影器形成可查询的 read model，再发布对应完成水位。

订阅从“快照版本＋游标”开始，随后补发其后的事件，关闭读快照与开启订阅之间的竞态。客户端去重、检测游标失效、重连后补发；历史被压缩时重新读取快照。过滤后的订阅使用服务端返回的 opaque cursor 或范围水位，不能把全局序号的非连续误判为漏消息。

面板按一个一致快照展示互相关联的数据。核心投影未就绪时保留上一稳定视图并显示更新中；不能把不同正文版本的角色卡和关系边拼在一起。向量索引、低优先级摘要有独立水位，不阻塞不依赖它们的对象查看。

### 5.4 交互回写

拖动坐标、缩放与展开是本地布局。修改关系、改变境界条件、调动场景顺序是语义命令：携带 baseRevision 与 objectVersion，生成 ChangeSet，验证范围与依赖后按已有授权提交。发生并发修改时展示差异或重新基于新版本计算，不能用图形操作覆盖较新的正文。

撤销语义修改走作品版本与补偿变更；撤销布局只恢复视图。图引擎自带 undo 栈不能成为正史恢复系统。

## 6 百万字场景的性能与测试

### 性能设计

- 默认呈现当前上下文的有界子图，提供可扩展的邻域与搜索，不一次渲染整书所有事件。
- 全书概览聚合成势力、卷或场景群；放大后再展开。未知关系不能为了连通画布而新增。
- 稳定 objectId/edgeId，按增量修改数据，保留用户布局。
- 更新事件成批送入渲染帧，布局计算放 worker；拖动时暂停无关布局。
- 保留筛选条件与视口，节点变更不使全图重新居中。
- 图表估计数据和实际观测数据使用不同标识；不绘制无依据的“爆款概率”。
- 正式性能阈值以项目 Electron、真实设备和可复现数据集确定。本轮没有测量节点上限或宣称固定毫秒性能。

### 必须覆盖的回归

1. 玄幻项目禁用境界模块后不再要求补齐境界，旧事实仍保留可追溯。
2. 都市项目主动添加超能力模块后，模块和图按作者选择出现。
3. 修改世界规则产生可见影响集，未采纳前正文与正史不变。
4. 关系图切到旧故事时点不显示未来关系。
5. 人物视角不显示其未知真相；误信边与世界事实边区分。
6. 同一人物多个别名仍保持稳定 ID。
7. 流式预览中断后候选节点被清理，正式图不受污染。
8. 重连去重与补发，不因重复事件形成重复边。
9. 图形拖动与语义变更分别撤销。
10. 新版正文未完成投影时不出现混合版本面板。
11. 悬疑证据缺失保持未知，不以评分或最短路径自动宣布凶手。
12. 大图在筛选、缩放、展开时保持可操作，键盘和列表替代视图可用。
13. 自定义历法/模糊时间按原单位展示，未映射为伪精确公历。
14. 定量资源缺失数值时退化为定性关系，不填随机流量。

## 7 对 V4 的最小扩展

不新增“可视化 Agent”。扩展 world-design 的模块与规则操作，扩展 co-creation 的对象类型与字段视角；正文、记忆、审阅只读取当前作品实际启用的体系。

前端增加 ProjectionQuery、ProjectionSubscription 与 SemanticCommand 适配。统一选择上下文在面板之间流转，事实仍由 V3 数据服务提供。若需要生成世界图的布局说明，也应是可撤销布局候选，不是另存一份世界观文本。

优先实现：自定义模块与实体合同 → 世界规则/当前状态投影 → 有界关系图与能力图 → 情节矩阵/双时间轴 → 节奏与承诺联动 → 可选大图与多人协作。先落实语义和版本，再增加视觉表现。

## 8 本轮核查边界

所有外部项目功能来自本轮读取的一手 README、官方文档或指定源码；详细来源见 v5-visual-world-sources.json。本轮没有运行 Novalist/StoryLine，没有安装这些可视化库，没有证明它们在现有应用内无冲突。可直接采用的组件与需要适配的业务代码已经分开列明。
