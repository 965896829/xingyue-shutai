# 流程与调用预算

## 现有0.4.82流程

从创意新建：本地项目与任务 → S01内部三方向一次生成 → 本地结构校验 → 作者选方向 → 完整作品方案 → 独立方案审核 → 作者确认与命名流程 → run.accept → S02。完整方案已经产生设定拆解，不能再画成接着额外执行一次S01。

常规阶段：S02配置/文风 → S03世界 → S04人物 → S05分卷 → S06本批章纲 → S07本批节奏 → S08本批细纲 → S09单章 → S10正文流水线。S10流水线含writer、review、memory和必要的独立记忆/未来计划审核；采纳会推进S10/S11，进入下一章S09或新批S06。

当前叙事preview、工具续读、实际修复与容量拆批可能增加模型调用。默认preview.maxCalls=8仅限制checkpoint drain，不涵盖全部plan/final调用。因此不能把正文成功链写成固定三次，也不能把8当完整统一上限。

## 建议流程

保留已有候选隔离和采纳事务。在创意选定后，用可选的同场景文风试写验证表达；正式写作采用全书里程碑、当前卷、近期可执行场景三层规划。每章以一个冻结SceneContract写正文，现有综合审稿一次收集问题，必要时局部修订，再提取记忆并做必要独立证据核对。可视化从主链移到按需sidecar，绑定正文hash。

首次项目可以先写短试稿或开篇小样再投入长篇设计，但必须使用现有独立试写任务或新增pilot模式；不能绕过0.4.82完整批次门槛。新rolling-v2完成迁移后，才允许近期3—5章细化、较远10—20章意图的可配置初始窗口。这些是实验起点，不是平台规律。

## 成功路径的调用分类

| 任务 | 推荐常规方式 | 例外 |
| --- | --- | --- |
| 三个方向 | 一次模型提交，宿主校验成功即停 | 结构失败有限修复；作者重做是新任务 |
| 文风同场景比较 | 可选一次生成2—3个短候选 | 不为每案再开“AI味审核” |
| 单阶段计划 | 当前任务一次完整提交 | 实际容量需要时分段，保留已有source reuse |
| 正文 | writer一次＋综合review一次 | 有实际问题再局部修复及重审 |
| 记忆 | 增量提取＋必要独立语义核验 | 复用已验证缓存；空增量可跳部分核验；批量按容量拆分 |
| 叙事曲线 | 按需，优先复用可用证据 | 不默认叠加plan/stream/final整套调用 |
| 真实市场研究 | 作者选择研究任务时调用 | 失败用注明日期的离线资料，不每章联网 |

预算必须记实际modelAttempts、已知用量、未知费用与重试。不将逻辑角色数当请求次数，不把工具提交当新模型请求。

## 恢复和版本不变量

每次尝试绑定task/attempt/epoch、inputHash、promptHash、sourceSnapshot、candidateHash。流式预览没有采纳权限；正式结果本地验证保存后才可选择。取消、重抽、切模型后的旧delta不能覆盖新尝试。审核或记忆所用hash与候选不一致即失效。

网络未知结果沿用现有保守恢复；没有供应商幂等保证时不宣称远端exactly-once。SQLite事务已能防本地重复采纳，这与远端只收费一次不是同一个保证。
