# 星月书台共创工作台 V2

基线为 0.4.82，b505f6f459db74871f39f63acf6106b827c8a353。V2 是本轮方案版本，不是已经发布的客户端版本。继续使用 Pi、现有模型网关、SQLite、候选与采纳事务。界面、讨论和生成读取同一套有版本的作品对象。

## 产品主线

作者输入创意后，一次得到三份可比较方向。选中方向后，可以随时讨论剧情、各层大纲、人物、世界或文风。每轮围绕当前对象及作者提出的变化工作，结果进入对象草案或明确授权的修改；进入正文前，只检查本章必要前置资料。正文采纳后更新有来源的状态，可在对应章节回看人物与故事。

作者体验依次经过创意、设定、规划、试写与正文、连载。界面只提供共创、写作、检查三种工作模式；共创内部按创意、剧情、人物、世界等对象导航，不再叠加一排阶段向导。S01—S11 保留为宿主执行阶段和迁移依据。讨论可跨对象自由进行；现行正式生成仍按已有 gate，新的依赖驱动执行必须完成 schema、validator、恢复和旧任务迁移后启用。

## 三个界面区域

左侧是当前作品对象导航。中央画布专门展示选中对象，依据类型切换卡片、关系、剧情层级、章节状态或世界规则。右侧是与当前对象绑定的讨论和变更预览，可收起。运行日志、token、工具与内部编号进入诊断层。作者看到的方案、正文、卡片和提示词正文不含解释性注释。

正文工作区优先文稿阅读与选段修改，中央图形画布按需切换。不能为了统一布局把小说强行切成卡片。移动或窄窗口按画布、讨论顺序折叠，保留当前对象、范围与确认动作。

## 一个上下文

WorkbenchScope 统一描述作品、时间线、截至章节、视角、选中对象、正式或候选范围。选中关系边、场景节点或角色字段时，把稳定对象ID和当前版本带入讨论。切换对象不清空既有对话；不同对象线程独立，允许显式追加相关对象。

讨论上下文由当前有效作者决定、对象快照、必要依赖、最近相关轮次组成。原始消息可回看；摘要不覆盖作者原话。旧版本建议、已否决方向和未采纳试写保留自己的状态，不自动进入正史。

## 一个修改入口

本地按钮优先确定动作和目标，模型在同一轮回答或生成必要变更。讨论不要求附带提案；请求改动时返回最小可用修改。作者明确授权、范围清楚且版本匹配的可回退定点修改，可以由宿主执行并提供撤销。当前授权尚未覆盖的重大跨对象改写、追溯影响或修改范围不明确时，先完成影响分析与具体差异，再让作者作必要决定。涉及已确认内容时，继续满足正式采纳与来源检查。

所有修改交给宿主验证和事务。正式版本的撤销以新修订记录实现，不删除历史。互相依赖的修改作为原子组采纳；独立修改支持逐项采纳。旧方案基于过期版本时进入待重新核对，不覆盖新编辑。

## 一个可视化数据源

人物卡、关系图、状态时间线、世界规则图、剧情板和正文引用均是现有事实与计划的读模型。确认设定、已发生事实、未来计划、人物认知和讨论候选分别标记。图中的数值需要真实来源和单位；未知保持未知。作者拖动位置只改变布局，连接一条有语义的边则需要形成关系或因果提案。

可视化查询不需要模型调用。已有来源不足时显示缺失，作者可另行发起提取或讨论。角色图像可作为可选参考资源，但不能决定人物事实，也不作为人物卡可用的前置条件。

## 精简后的请求

统一总控加一个当前任务。共创请求再选一个对象职责片段，附目标对象、有效作者决定、相关来源和实际工具合同。正文、文风讨论、校准与相关审稿按需载入当前文风与人物声音。创意任务使用 concept-forge 或 requirements-and-directions 之一，不同时装载。没有实际 adapter 的新工具不能靠提示词声明启用。

## 创意质量与声音

创意以高辨识度核心规则、主角主动选择、明确代价、有效反制和长期变化建立吸引力。首次三案保持一轮提交。作者喜欢某个机制、人物或开篇时，可以锁定对应部分继续讨论。神级设定作为编辑目标，不显示无依据的爆款概率或神级评分。

人物卡中的欲望、隐瞒、关注点和关系策略进入当前场景；作者认可的原创新段落进入声音样例。修订同时检查事实与声音，只对有证据的问题改变文本。工程检查、文学偏好和真实读者反馈分开记录。

## 接入顺序

先统一对象选择、讨论绑定和变更卡，随后提升已有可视化到中央画布。然后接入新创意专项、版本化人物声音和本章合同。滚动规划与增量记忆最后在独立版本模式中启用。每步保持旧任务、旧作品和旧输出合同的恢复路径。
