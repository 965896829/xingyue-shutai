# 项目结构与硬门槛验证

## 触发与边界

脚手架、阶段完成、批次、单章或跨文件修订后运行确定性检查；不以静态校验代替文学审阅。

## 必需输入

project snapshot、artifact states、mode=scaffold/stage/chapter/full、目标阶段/章号、配置与依赖。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`

## 执行步骤

1. 根据mode和产物状态选择检查项，planned文件不当已完成正文；scaffold允许零正文。

2. 章号解析最少三位而非恰好三位，按整数排序并检查重复、间断和总量上界。

3. 按配置计算当前/全部批次范围，支持非30批次与最后不足整批；检查总纲/节奏/细纲覆盖与类型强度。

4. 检查原模板必需字段非空、占位符、枚举、不适用理由；缺用户关键决策不能伪填完成。

5. 复读实际正文按统一口径计数；检查正文/事件来源hash、接受revision、索引、进度和物化状态。

6. 章模式查本章必要依赖，全量模式查所有已接受章节与批次；对结构之外的人物/知情语义交相应审阅技能。

7. 输出机器可读errors/warnings和定位；错误不能豁免冒充通过，警告人工保留需记录理由。

## 输出契约

遵循shared-contract统一信封。目标产物：

- ValidationReport
- 阶段或章节硬门槛结果

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 1000/1200章可识别
- 末批不强要30章
- 占位字段不能过关
- 报告没有编造语义检查已完成

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
