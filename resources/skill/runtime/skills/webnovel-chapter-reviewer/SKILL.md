# 证据式章节审阅

## 触发与边界

审阅候选正文的叙事、人物、回报、信息清晰、文风和结构重复时使用；评分不等于批准。

## 必需输入

保存后的候选正文hash、单章任务/细纲、配置、前两章与相关事实、确定性检查结果。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/templates/章节质量评分模板.md`
- `../../references/style-system.md`

## 执行步骤

1. 先看硬检查结果，定位字数/缺依赖/格式问题；不要用文学高分掩盖硬失败。

2. 只根据实际正文判定入口、主动选择、状态变化、阅读回报、新词意义和章末承接，标出证据片段位置。

3. 审视人物是否有独立欲望，反派是否无故降智；指出原因与最小修改，不只说“更爽”。

4. 比前两章的开场/推动/反制/兑现/结尾，判断同构而非简单同词；高潮例外给人工审阅。

5. 检查表达是否重复已经展示的信息；库存转场只作信号，避免误删因果解释和自然对白。

6. 输出blocking/error/warning/note及修复建议；主观判断标明不确定；原评分模板可保留，但不以80分等阈值自动接受。

## 输出契约

遵循shared-contract统一信封。目标产物：

- 08_章后更新/第{chapter}章质量评分.md
- 限定范围修复提案

质量报告先用中文说明结论和修改建议，再附一个客户端核验块。块的围栏为 `json wenxu-review`，内容为 JSON 对象：proseHash 使用宿主提供的当前正文哈希；checks 必须各含一项“开头有效性”“主角主动性”“人物一致性”“信息落地”“章末牵引”。每项包含 aspect、verdict（pass、warning 或 error）、quote（当前正文中连续的准确原文，8—1200 字符）、reason（具体判断理由，至少 8 字符）。不能引用细纲冒充正文，不能复用旧正文的审稿。偏好建议用 warning，明确需要修复的问题用 error；没有问题也必须说明原文依据。中文结论中的问题、引文、理由必须与核验块一致。客户端隐藏核验块，只向作者展示中文报告。

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 每个问题有规则与定位
- 硬问题和偏好建议区分
- 不报告AI来源概率
- 同一轮审阅不直接改正式稿

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
