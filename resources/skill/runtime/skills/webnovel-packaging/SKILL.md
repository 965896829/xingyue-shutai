# 书名简介与入口承诺

## 触发与边界

作者要求书名、简介、标签、开篇包装或对比宣传版本时使用；只能承诺作品实际能提供的内容。

## 必需输入

已确认读者承诺、实际开篇或可用计划、题材命名规则、平台公开格式要求、候选数量与授权。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/naming/common.md`

## 执行步骤

1. 明确目标是点击理解、辨识度还是正确筛选读者；包装不能承诺不存在的关系、系统、爽点或尺度。

2. 按作者数量给真正不同的卖点表达角度：角色困境、机制反差、关系张力或核心悬问，不默认夸张长标题。

3. 简介先建立可理解的主体、情境与变化，保留值得追问的后果；不泄漏核心身份真相。

4. 列各版本吸引的读者与可能误导的人群；与前几章实际兑现逐项对照。

5. 外部发布前核对平台最新格式/内容规则；没有可核验规则时注明，不宣称包过审。

6. 输出候选与选择理由，实验发布需独立授权，不同时改多个因素而声称找到因果。

## 输出契约

遵循shared-contract统一信封。目标产物：

- 10_市场与读者/书名简介候选.md
- 入口承诺匹配检查

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 包装与正文相符
- 无虚构平台认证
- 不复制竞品标志性表达
- 不自动改已接受书名或发布

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
