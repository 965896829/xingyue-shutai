# 批次闭环与归档

## 触发与边界

当前批次末章正文与章后更新完成时归档行为、写跨批摘要并提出下一批交接；不越权生成后续批次。

## 必需输入

批次实际范围、全部已接受章、当前行为日志、五台账、未兑现承诺、偏差记录和阶段授权。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/memory-system.md`
- `../../references/templates/批次人物摘要模板.md`

## 执行步骤

1. 检查末章确已接受且当前批次所有依赖闭环，不把最新候选当完成。

2. 归档详细行为日志，原文不丢；为每名活跃角色写起点、关键选择、情绪转折、关系、末态和下批承接。

3. 整理持续伤势、物品、期限、伏笔和知情边界；标明摘要覆盖的版本和出处。

4. 对照原计划与实际正文，列下一批必须调整的目标/关系/承诺，不盲延旧线。

5. 重建活跃日志只保留下批起点和必要承接；末尾不足30章按真实范围归档。

6. 获得归档接受和下一批授权后，路由chapter-roadmap→rhythm-designer→batch-outline；不得在本技能里跳过审批直接连续生成。

## 输出契约

遵循shared-contract统一信封。目标产物：

- 04_人物记忆库/历史归档/第{start}-{end}章情绪与行为.md
- 04_人物记忆库/批次人物摘要.md
- 下一批承接与归档changeset

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 所有章已接受
- 归档与摘要source hash齐全
- 不复制全部旧行为到新批
- 末批范围正确

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
