# 设定拆解与读者承诺

## 触发与边界

作者提供脑洞、神级设定、故事种子或要求增强卖点时使用。拆解成可验证的故事引擎，候选不自动成为设定。

## 必需输入

原始设定；已确认的禁区/读者/题材；可选市场证据；命名通用约束。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/templates/设定拆解模板.md`
- `../../references/naming/common.md`

## 执行步骤

1. 逐项提取原模板字段：题材、一句话卖点、核心神级点、困境、不公平规则、破局、反差、首章事件、连载动力、升级路线。

2. 先分作者确认、创意提案、方向待定。某书不需要世界不公平或金手指时写明不适用原因。

3. 增补读者承诺：点开时以为什么、第一章看见什么证明、为何追这个人、长线究竟期待何种变化。

4. 将设定写成主角可以主动选择且产生可见代价的机制；测试去掉专名后卖点是否仍有辨识度。

5. 默认给一个主推机制与少量真正不同的备选，不换形容词冒充多方案。新名字经过命名守卫。

6. 做连载压力测试：初期兑现、中期对手学习、后期选择升级与终局问题；不能只靠地图与数值重复膨胀。

7. 输出待确认项及推荐理由；首章设计只到本阶段允许的事件提案，不提前写正文。

## 输出契约

遵循shared-contract统一信封。目标产物：

- 01_设定拆解/设定拆解.md

读者承诺写入设定拆解的“读者承诺”小节，包含开篇证明、追读理由和长线期待；不另建读者承诺文件。

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 主角不是唯一被动承受者
- 核心机制可示范且可持续
- 不强塞系统/打脸/感情线
- 爆款可能性不伪装成概率

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
