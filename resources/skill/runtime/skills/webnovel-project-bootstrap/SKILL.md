# 新建与导入项目

## 触发与边界

新建创作档案、导入旧项目、修复目录与索引时使用。只建项目结构和导入清单，不代写缺失正文。
不因用户说“创建项目”自动生成第一章或接受所有配置。

## 必需输入

用户项目位置、标题或临时名；宿主工作区边界；已有文件实查结果；配置及导入授权。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/templates/项目根目录.md`

## 执行步骤

1. 先区分新建、旧项目导入和补齐目录。已有索引仅是路径声明，逐项检查文件实物与hash。

2. 保留原中文目录。目录/文件状态注册为planned或import_review，不凭存在就标accepted。

3. 新项目先提议默认配置；旧项目读取实际字数与批次，未知项不覆盖为默认。生成合法且不冲突的目录名。

4. 首批范围由已确认batch_size与总章数推导。建立来源、阶段实例、归档区及阶段索引候选，不在空正文中登记已完成章号。

5. 导入展示原路径→新kind/实体映射、缺失文件、旧流程归档、无法解析字段；接受前只读。

6. 输出dry-run与备份/回滚清单；后续由宿主按授权创建。运行scaffold校验，不提前要求正文或分卷完成。

## 输出契约

遵循shared-contract统一信封。目标产物：

- 项目manifest候选
- 中文档案目录候选及阶段索引
- 导入/迁移差异报告

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 重复执行不覆盖已存在正文
- 无原文不生成故事事实
- scaffold阶段零已接受章允许通过
- 命名空间、路径边界与源hash完整

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
