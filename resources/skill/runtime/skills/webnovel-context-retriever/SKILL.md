# 按证据构建章节上下文

## 触发与边界

续写、修订、角色回归、旧伏笔回收或任何依赖作品事实的任务之前构建上下文；不是自由编造摘要。

## 必需输入

项目/分支/revision、任务/章号、关键依赖清单、token预算、实体与世界/时间线过滤器。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/memory-system.md`

## 执行步骤

1. 从一致快照读当前配置、进度、改动影响及上一章；启用文风才加载适用版本。

2. 读取本章批次/单章计划，并抽取硬依赖：关键人物、伤势物品、期限、承诺、规则、知情限制。

3. 逐类检索人物与五台账，精确ID/章节先于语义相似；必要的原文直接定位，不仅依赖摘要。

4. 老角色回归或旧伏笔关联历史归档时定点回查；不把全历史常驻上下文。

5. 区分写作POV可表达事实、仅规划器可见的秘密、读者已知与暂不能揭示；全部保留出处和版本。

6. 预算不足先压非关键摘要并登记省略理由；不能装下关键约束则拆任务/返回blocked。

7. 输出manifest与未解决冲突，不宣称没读的文件已核验；源版本变化后包立即stale。

## 输出契约

遵循shared-contract统一信封。目标产物：

- ContextPacket
- context_manifest
- 缺失/冲突查询清单

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 关键依赖召回齐全
- 所有来源绑定hash
- 五类台账均有结果/无关说明
- 跨项目与世界隔离

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。

先从宿主snapshot source清单验证有效版本与五台账覆盖。编译L0/L1/L2包；按精确必需项＋中文词法＋可选向量／关系邻接召回。处理两字名与别名，不只靠trigram。记录索引水位、POV、来源、全部输入预算和漏项。候选／旧源／跨项目／未知信息不得进入可表达事实块；向量宕机时仅在精确依赖满足后降级。
