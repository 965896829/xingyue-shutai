# 正文候选写作

## 触发与边界

在本章批次细纲、任务清单和单章细纲齐备并获生成授权时写正文；不直接接受或发布。
没有任务/细纲不得仅依据分卷大纲续写；不能输出正文同时声称已经全库同步。

## 必需输入

当前snapshot、完整依赖manifest、已确认任务/细纲、启用文风、字数范围、知识/名称守卫。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/style-system.md`
- `../../references/naming/common.md`

## 执行步骤

1. 先做硬门槛预检：授权、版本、批次覆盖、POV、字数、风格和关键记忆。缺失则阻断。

2. 按场面推进，用动作、对话、判断和结果承载选择；初次术语给足够白话解释，避免事后总结聪明。

3. 入口符合章节功能；书籍开篇尽早显示卖点的具体作用与主角第一次有效选择，回报不等于必须打脸。

4. 控制揭示预算，遵守人物所知与视角；战斗有位置、接触、碰撞、结果、伤势，不堆招式名称。

5. 生成完整章末牵引，不用截断输出充当悬念。保存候选后实际复读和计数，超限进入定点修复。

6. 提交候选正文给reviewer与continuity-audit；只返回候选状态，不改人物库或推进正式进度。

## 输出契约

遵循shared-contract统一信封。目标产物：

- 07_正文章节/第{chapter}章.md

正文子调用仅返回正文，客户端保存草稿并计算内容哈希，再安排独立审阅。不生成内部存储文件或手填哈希。

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 正文保存后复读计数
- 2300—2700或项目指定区间
- 主角选择与回报可定位
- 只有宿主能接受

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
