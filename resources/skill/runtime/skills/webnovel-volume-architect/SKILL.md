# 分卷架构与终局承诺

## 触发与边界

设计长篇主线、分卷、人物成长、主要对抗路线和最终兑现时使用。

## 必需输入

已确认总字数/章长、读者承诺、世界规则、角色初始状态和作者终局偏好。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/templates/分卷大纲模板.md`

## 执行步骤

1. 计算总章数与各卷容量；原推荐6—10卷仅默认建议，服从故事与作者要求。

2. 明确全书中心问题、主角不可逆变化和终局回报；不只列不断升级的敌人名称。

3. 逐卷安排阶段目标、核心冲突/回报、关键选择、高潮与余波、长线伏笔和卷尾牵引。

4. 远期保留粗粒度关键点，近期进入章级；不先写死1200章每个动作。

5. 容量连续、章号不重叠；跨卷批次允许但必须映射清楚。末批按剩余章节，不为凑整拉长结局。

6. 检查中后期不是换地图重复开局，重要人物不是随卷丢弃，终局能兑现前期主要承诺。

## 输出契约

遵循shared-contract统一信封。目标产物：

- 05_长篇大纲/分卷大纲.md

路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 容量核对一致
- 主线和终局可辨
- 远近详略合理
- 不把卷数当平台硬要求

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
