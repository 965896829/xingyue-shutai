# 项目配置与授权模式

## 触发与边界

锁定或修改目标字数、章节长度、POV、题材、读者、硬约束、批次和授权范围时使用。

## 必需输入

已接受设定拆解、作者要求、当前配置版本、宿主批准模式与可用模型能力。

宿主任务信封、授权与源版本缺失时先读取，仍缺则返回blocked。不能虚构上下文。

## 先读资料

- `../../references/shared-contract.md`
- `../../references/templates/项目配置模板.md`
- `../../references/templates/文风样本与规则模板.md`

## 执行步骤

1. 保持原配置字段，核对批次大小、总章数、计数口径和作者要求。版本、预算及授权记录由宿主保存，不要求作者填写，不另行输出 sidecar。

2. 新项目可提议300万/2500/2300—2700/30章；作者已指定的值优先，变更必须标记来源与适用范围。

3. 总章数向上取整；末批截断，不为对齐而补无效章。先做长篇引擎可持续性判断，不把300万当商业刚需。

4. 区分用户硬约束与编辑软建议；公共打脸、金手指、恋爱结构等须明确选择才启用。

5. 建立文风档案未启用状态；收到样本或明确描述再调用voice-profile，不虚构样本分析。

6. 旧配置变更列受影响批次、篇幅、任务与正文；只润色的授权不能变更POV或人物关系。

## 输出契约

遵循shared-contract统一信封。目标产物：

- 02_项目配置/项目配置.md
- 02_项目配置/文风样本与规则.md


路径是changeset目标，实际写入候选区。{chapter}/{start}/{end}由宿主用最少三位章号格式生成，四位及以上不截断。

## 验收与失败处理

- 字数上下界有效
- batch_size正整数且末批合法
- 明确生成/接受/发布授权差异
- 旧书不静默重置默认

发现源hash变化、关键依赖缺失、越权或预算耗尽，返回具体阻断与已完成候选。不自行接受、改写正史或触发外部发布。
