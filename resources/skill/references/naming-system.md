# 中文网文命名系统：全题材扩展版

版本：v2.0  
用途：中文网文客户端的命名生成、命名审阅与改名提案规则。  
覆盖口径：覆盖本次约定清单中的36个分类名称及“其他”，并提供跨题材标签与旧名称兼容规则。该清单是本规则的适配范围，不宣称是已穷尽、已核实的番茄官方现行分类目录。分类名称的后续增删，不自动修改作品内容。

## 一、目标

名字应帮助读者判断对象属于什么题材语境、什么文化与势力，必要时辨认其职能和层级。命名服务于沉浸感、辨识度和自然称呼，不用现代行政机构的拼接法替代世界观设计，也不用生僻字、宏大词和抽象概念堆砌代替创意。

“一眼知道”不等于把全部背景、能力、真实身份和最终等级写进名字。悬疑身份、隐藏组织、伪装职业和未知物品，应按当前叙事视角保留信息；读者需要知道它是什么类型的对象，不必提前知道它的全部真相。

不同题材使用不同命名逻辑：现实题材重生活与行业语境，历史题材重时代与制度，幻想题材重文化与传承，衍生题材重所选原作版本和本书已确认改编约定。不能把所有作品都命名成玄幻，也不能把所有幻想机构都命名成现代部门。

## 二、规则效力、示例边界与既有内容保护

### 2.1 强制约束与默认建议

“不得”“必须”表示本规则的强制约束；“优先”“建议”“通常”表示默认建议；“条件参考”“条件例外”必须在条件成立时适用。

平台最高规则和修改权限先行。本书已确认的命名约定，可以覆盖本文件中的默认风格建议，不能被普通题材模板覆盖；作者明确指定的禁用名称，不因切换分类而解除。需要变更既有约定时，应形成明确的新版本，不能从一次临时讨论推定为永久授权。

规则更新不追溯授权改写旧稿。已接受名称即使命中本版审阅项，也应先标记问题、保留原文，不能自动替换、删除或阻断正常读取。

### 2.2 示例读法

本文中的“正向结构参考”只展示可用结构，不是固定候选池，不要求照搬，也不要求作品增设对应世界观。

“反例”仅供识别问题，不得进入候选名称、正式设定或正文。反例可以出现在审阅记录、规则引用中，但不得因被检索到、被摘要或被讨论，就被当成本书事实。

“条件参考”只在对应年代、制度、阵营或机制已经存在时适用。不得为了使用示例中的词，擅自添加阴间、审判、测命、天庭、系统、教会等设定。

### 2.3 适用环节

从灵感讨论、设定拆解、角色卡、世界观、各层大纲、细纲，到正文生成、补写、修订、摘要和资料提取，所有新名称均执行本规则。

摘要和资料提取应忠实提取原名，不能自行“美化”；发现疑似别名、错字或同名冲突时，提出核对项。未获接受的候选名称和草稿，不得自动写入正式人物库或世界事实库。

## 三、执行顺序与混合题材路由

### 3.1 命名前确认的内容

先识别作品的时代、地域、文化、世界规则及实际题材，再识别命名对象的类别、功能、所属阵营、上下级关系、命名者和命名年代。随后读取本书已确认名称、别名、作者禁用项，以及当前视角可以知道的信息。

同一对象可能有本名、化名、职位称呼、民间俗称、旧称和编号，应先确认本次需要哪一种，而不是把它们生成成不同实体。

信息不足时，优先沿用已确认语境，或使用不增加设定的临时描述。需要影响制度、身份或世界规则的新设定时，单独提出待确认项，不能把起名当作增设世界观的授权。

### 3.2 组合加载原则

运行时按“通用约束＋本书命名约定＋对象类型规则＋相关题材规则＋必要标签规则”组合使用。分类表是选择规则的索引，不是要求每次把全部题材示例输入生成器。

遇到冲突，先判断这个对象实际属于哪一时代、地域和文化，不能简单认定“主分类覆盖一切”。同一本都市修真小说里，现代医院与古老宗门可以采用不同体系；同一宗门内部混入另一套制度称谓，则需要本书已有的历史或组织依据。

**组合判断示例，仅演示规则选择，不生成书中设定：**

| 已确认的作品组合 | 命名规则选择 |
|---|---|
| 都市脑洞＋规则怪谈 | 现实社会名称采用都市规则；异常场景补充怪谈规则；不自动加入修仙机构。 |
| 古言脑洞＋穿书＋种田 | 土著名称采用当地古代语境；穿越者私下称呼可有现代差异；经营对象按生产与交易背景命名。 |
| 双男主＋东方仙侠 | 世界与机构采用仙侠规则；双男主仅补充两位角色及关系称呼，不另造一套世界词汇。 |
| 快穿＋年代＋悬疑 | 每个世界单独确定年代与命名空间；人物化名和案件称呼遵守知情范围。 |
| 科幻末世＋游戏机制 | 科技对象、灾后社会、游戏界面分别使用对应规则；游戏术语不自动成为所有居民的日常用语。 |

## 四、跨题材通用命名规则

### 4.1 人名

常规中文人物优先使用两字或三字姓名，读音顺口，生僻字少。复姓、少数民族姓名、外国姓名、历史真实姓名、艺名、网名、法名、道号等按自身语境处理，不能为了统一长度强行缩写或汉化。

主要角色要主流易懂、有辨识度，避免批量复用同一种“热门姓氏＋古风意象”的模板。未进行实际检索时，不宣称某个名字全网唯一，也不把主观印象包装成高频统计。

配角可以朴素，但朴素不等于滑稽、低俗或没有尊严；主角可以普通，身份尊贵也不要求姓名必然华丽。不要让姓名直接承担善恶判定：反派不必统一阴冷，女性不必统一柔美，男性不必统一凌厉。

同一家族、师承或地域可共享姓氏、辈分字或文化气质，但要控制关键人物的形近与同音。相似命名有明确家族或双生设定时可保留，不为“去重”破坏已确认关系。

本名、乳名、字、号、化名、艺名和昵称分别记录。谁能使用哪个称呼，应符合时代、亲疏、礼制、身份及知情范围；不能让所有人不分场合都使用同一亲昵称呼。

### 4.2 机构、势力与内部分支

先确认组织的真实性质，再确定名称。国家机关、地方官署、宗门、商号、公司、学校、教会、行会、帮派、军队和临时互助组织，不使用同一套后缀规则。

同一命名共同体应保有可理解的一致性，但不要求整个世界只有一种语系。兼并、改制、外来文化和历史沿革可以带来不同称谓，前提是有已确认依据，不能事后随意编理由掩盖混乱。

区分“机构”与“建筑”：一座楼、一个殿可能是组织驻地，也可能本身就是组织名。名字的后缀不能代替实体类型、隶属关系和规模信息。

“宗、宫、殿、阁、院”等不自动构成通用强弱排序；“局、处、科”等也不能凭字面替作者决定一套制度。上下级关系以本书设定为准，不在命名阶段擅自重排。

### 4.3 职位与称号

区分职务、官职、军衔、爵位、修为境界、职业资格、荣誉称号和江湖绰号，不能混为一条等级线。职位必须有可理解的职责，不能只靠单字或生造缩写营造神秘。

宗主、峰主、殿主、阁主、长老、护法、供奉、首座、真传、执事，只在已有相应宗门制度时使用；它们是可选称谓，不是必须全部配置的部门和岗位。

殿主、执令、行走、守门人、掌律长老、封律长老，只在对应职责已经明确时使用；“行走”与“执令”等不能仅因语感神秘就套用。“巡使”须确有巡行职责，其他带“使”的称谓须符合使者职责或已确认制度。

判官、阴差、鬼吏、拘魂将、殿主，只适用于已有相应阴间体系的作品，不要求其他作品新增地府。

### 4.4 功法、招式、法器、技术与物品

先区分功法、单次招式、修炼境界、武器、法器、材料、药物、设备、软件和技术项目。类别未确定时，不先生成一个听起来厉害的名称再倒推用途。

东方幻想中的功法、招式和法器，常用名优先控制在二至六字；这只是便于阅读的默认范围，不约束完整经名、历史原名、外语译名、型号或作者确认的长名。长名称应有稳定、自然的正文简称。

可从已确认的效果、形制、意象、产地、材料、传承或命名者出发，不要求每件物品都有传奇来历。名称可以暗示用途，不能为了“含蓄”故意变得不可理解。

**正向结构参考：**功法“玄元诀”、招式“断岳掌”、法器“照魂镜”。只展示不同对象的可用结构，不能混成同一类别，也不是默认候选。

**作者明确指定的反例：问罪碑、验命石、审判钟。**不得作为新候选照搬，也不能只替换近义字，继续使用同一种缺乏世界语境的生硬功能拼接法。不得由这些反例推导出本书需要测命、审判、定罪等设定。

上述反例不等于禁用所有带功能含义的名称。“照魂镜”这种在相应幻想语境中直观表达用途的名称，以及现代题材中准确的仪器、科室或设备名称，不能仅因“看得出功能”就判为违规。审查的是作者明确禁用项、题材适配与批量机械拼接，而非功能性本身。

### 4.5 境界、品阶与评级

先确定体系由谁建立、用于什么目的、在哪些范围通行，再命名。修炼境界、战斗评级、装备品质、职业等级、官阶和组织职级分别处理。

不得为了显得完整，自动补齐七境、九族、十二阶等工整体系；不得把每一级都做成同字数、同词根、动词加抽象概念的功能说明。

已有传承、考试制度、军用标准或游戏设计支持统一编号时，可以保持规整；不能为了反模板故意打乱一个合理的标准体系。

允许本书已有的俗称、古称、地域异称和学派异称并存，但必须对应清楚。不要只为制造历史感，给每个等级强行增加多套别名。

### 4.6 地名、建筑、商铺与公共场所

先确认真实或虚构地点、地域层级、自然环境、居民文化与使用年代。地名可依据地形、方位、物产、姓氏、行业或已经存在的历史事件命名，不能为了名字顺口新增地理或历史事实。

**正向结构参考：北域、梵帝城、青玄山。**仅用于展示地域与地点类型的可辨识结构，不要求作品采用这些名字。

现代街区、古代坊市、乡村聚落、星球殖民地、荒野据点应按各自语境处理。同一区域保持大体相当的命名密度，不能普通小城里每条巷子都像终极禁地。

区分行政名称、商业名称、民间俗称和旧址名称。真实地点随时代变化时，应核对使用时期；虚构地点也要维护改名时间与别名对应关系。

### 4.7 书名、卷名、章名与事件名

书名可以突出题材和卖点，但不能把长标题的宣传句式强行复制到所有人物、组织与物品名称上。章名、卷名不必统一字数或一律预告反转，除非作者已有格式要求。

案件、灾难、战争、赛事和历史事件的名称，应区分当时称呼、内部编号、媒体称呼与后世称呼。名称不得在叙事视角不知情时泄露凶手、幕后势力、事件终局或物品真实能力。

## 五、东方幻想命名的保留条款

### 5.1 机构结构

**正向结构参考——宗门主体：**宗、门、宫、殿、阁、楼、院、山、谷、城、府、堂、台。

**正向结构参考——内部分支：**执法堂、藏经阁、丹霞峰、问剑台、摘星楼、功德殿、拘魂殿。须与实际用途、阵营和已确认世界观相符，不应全部塞进同一个宗门。

**条件参考——超然势力：**殿、宫、天庭、仙盟、圣地。**条件参考——阴间体系：**地府、阴司、判官殿、拘魂殿。作品没有对应体系时，不启用这些参考。

### 5.2 “司”“使”与现代机构词

除非原世界明确采用相应官署制度，不要为了“管理某事”就习惯性生成“某某司”。除非职位确为奉命出行的使者，或已有制度明确使用该职称，不要为了“执行某事”就习惯性生成“某某使”。

**条件例外：“阴司”按传统志怪语境处理，不因含“司”就判为禁用。**真实历史制度或本书已确认制度中的官署、官职名称，也不能按单字命中机械删除。

**不适用反例：**在没有相应时代与制度背景的东方玄幻、仙侠中，无依据使用“管理局、办事处、数据中心、系统部门、异常处理科”。这些不是跨题材禁词；现代、科幻、游戏或明确建立对应组织体系的作品，应根据实际语境判断。

本条反对无依据的制度套用，不反对有意设计、已经确认且前后一致的混合文明。

## 六、分类适配规则：36项＋“其他”

以下编号是本规则内部模块编号，不是番茄官方分类ID。每项均继承前述通用约束。

### G01 都市日常

人名、单位、学校、街道、商铺和社区称呼以现实生活语境为主。主要角色可以有辨识度，周围人物不必人人使用精致古风名。

允许符合年代和业务性质的公司、部门、科室、工作室等名称。避免把普通企业写成隐世宗门、把普通职位起成权力封号，或无设定依据地出现全城公认的“王、帝、尊”。

### G02 都市脑洞

以都市社会的名称为底层，仅对已经出现的特殊能力、异常机构或原创机制加载额外规则。能力名称、机构名称与主角的个人外号可以不同。

不因“脑洞”自动添加系统、管理局、收容机构或异能等级；不把每件现实用品都改成奇物。新名称应帮助读者理解新机制，而不是用抽象术语遮盖机制尚未设计的问题。

### G03 都市高武

分别处理学校与训练机构、武道组织、军政机构、武学流派和战力等级。现代社会名称可以与已确认的武道称谓并存，但边界和隶属关系必须清楚。

避免把修为境界直接当作军衔或行政级别，也不默认全国采用同一套“某某司、某某使”。武技名可以有力量感，不用持续叠加“灭世、无上、终极”等词制造强度。

### G04 都市修真

现代公开社会与修真传承分别命名：公司、医院、学校遵循都市规则，宗门、洞府、法器遵循其文化和传承。公开身份、宗门身份、道号需要明确映射。

现代组织可以在已确认设定中承载修真活动，但不能在没有依据时把“公司、宗、宫、司”随机串接。同一对象从民用身份切换到修真身份时，要符合视角知情程度。

### G05 都市种田

围绕乡村、农场、家庭、合作组织、店铺、农产品和经营项目命名，突出地域与产业，而不是把整个农村自动仙侠化。

灵泉、空间、特殊品种等仅在已经确认时启用幻想规则；普通村名、地块、农具和作物不必全部另造专名。品牌名与村民日常叫法可不同，但不得无意义地增加别名负担。

### G06 战神赘婿

区分本名、婚姻与家族称呼、实际军职、组织职务、荣誉称号和地下势力外号。隐藏身份应有稳定的公开称呼，不在姓名或登场称号中提前泄底。

“战神”等题材称谓不自动等于真实军衔；需要军制时先明确真实或架空语境。避免所有家族都套同一种尊贵命名，所有配角都被迫用最高封号称呼主角。

### G07 传统玄幻

人名、宗族、宗门、城池、山川、功法和兵器遵循本书的东方幻想文化。不同地域、阶层与传承可以存在差别，不要求人人同一古风词库。

沿用已确认的力量体系，不为新卷机械追加更高一套“圣、神、帝、祖”。主角早年见到的普通事物应保留朴素层次，不让全世界从一开始就拥有终极名称。

### G08 玄幻脑洞

以已确认的玄幻文化为底层，为原创核心机制补充少量必要词汇。名称应有世界内的命名视角，不能把作者策划表中的功能句压缩成一套假古词。

不为了展示创意，强行生成整齐的抽象境界、职能官署和能力道具。机制可以复杂，人物在正文里的常用叫法应尽量自然；新概念越重要，越需要稳定而非频繁升级的称呼。

### G09 东方仙侠

按修行传统、师承、宗门和地域区分姓名、道号、尊称、洞府、经诀与法宝。人间官署、修行宗门和天界组织不默认共用一套层级。

“天庭、仙盟、阴司”等按已有设定条件启用。仙气不等于全员使用冷僻字、宇宙级意象或冗长尊号；凡人、市井、外门与高阶修士之间应保留命名层次。

### G10 西方奇幻

先确定本书各文化的语言感与译名约定，再命名人物、王国、领地、学院、教会、行会和法术。采用音译名时保持读音与译写一致，并在需要时提供稳定短称。

不强制套用两三字中文姓名，也不靠超长音译名证明异域感。爵位、教职、法师等级和组织职务分别处理；不同种族不应只按善恶模板分配优美名或粗哑名。

### G11 历史古代

先确定时代与真实程度。真实人物、地名、官署、官职、军制、年号等涉及事实时核对来源和使用时期；查不到的内容标为待核验，不能把猜测写成史实。

架空人物和组织遵循本书选定的制度背景。不得机械禁用“司、使”，也不把不同朝代的爵位、官制与礼俗随意拼装；借用现实原型而作了改动时，应在设定资料中区分。

### G12 历史脑洞

保留已确认的历史或架空时代底层，单独记录穿越、制度改革或其他脑洞造成的命名变化。明确哪些称谓原本存在，哪些由故事中的行动新设。

现代词可以作为穿越者的内心称呼或已建立的新名词，不应无缘无故成为全社会通用词。技术、机构和军制的改名，要跟随实际改革时间，不能提前出现在旧事件中。

### G13 抗战谍战

按时间、地域、阵营和身份核对部队、情报机构、职务、交通站、代号及装备名称。真实与虚构机构分开记录，不把影视印象当成可靠制度来源。

本名、化名、代号和职务称呼分别管理；称呼本身可能暴露身份。行动代号可短而可传递，不必个个宏大；代号、编号和组织称谓不能跨阶段无依据混用。

### G14 悬疑脑洞

案件、场景、线索、物证、异常对象和人物化名，按发现顺序与当前认识命名。允许调查者暂定名与真实名称不同，但必须绑定同一对象。

不能用案件名提前指认凶手，也不默认建立异常管理机构、等级榜或审判体系。陌生感优先来自事件与证据，不靠所有名称统一添加阴冷字制造。

### G15 悬疑灵异

根据实际采用的地方生活、民间传说、宗教背景或原创体系决定称呼。普通人物和日常地点可以保留普通名称，不能所有村庄、房屋和器物都以凶险词命名。

“阴司、阴差、判官”等按已确认体系使用，不因一个灵异事件自动引入完整地府。真实民俗资料与本书虚构设定应分别标记，不能把自造名目写成真实习俗。

### G16 女频悬疑

采用故事实际背景对应的悬疑、都市、历史或幻想规则。人物职业、机构和案件名称应独立于人物性别，不能把专业场景自动改写成古风恋爱命名。

主要女性角色不必全用柔美意象，男性角色也不必全用强势称号。情感关系称呼与调查身份并行管理，避免亲昵称谓在不合适的工作场景泄露关系或破坏人物设定。

### G17 科幻末世

按作品实际内容启用“科学技术”“未来社会”“灾后生存”中的相关部分；科幻不自动等于末世，末世也不自动具备星际文明或异能体系。

技术、设备、型号、机构和科研项目可以使用准确的功能性名称与编号；存在代号或民间短称时保持映射。灾后地点优先结合旧地名、实际设施、地形或居民约定命名，不让每个小据点都叫宏大的城邦或帝国。

### G18 游戏体育

竞技体育按项目、俱乐部、赛事、教练与队伍关系命名；电子游戏按设定区分职业、技能、装备、公会、服务器与赛事。体育文不自动套用魔法招式名。

电竞角色的真实姓名、选手ID、账号名和赛场简称分别管理。游戏界面允许规整等级、属性说明和功能名，但不能因此让现实生活中的所有人也说成游戏面板。

### G19 男频衍生

先锁定采用的原作、媒介版本、时间线和译名体系。已有角色、组织、招式、物品与地名优先保持该版本用名，新增实体贴合原作文化。

仅因“男频”不能擅自把原作体系改成升级玄幻。作者确认的架空分支与原作事实分别记录，不混入其他同人作品的私设；不能把原创作品套上原作专名当作原创命名。

### G20 女频衍生

同样以原作版本、人物身份和本书改编约定为基础。婚前婚后称呼、家族身份、封号和人物关系名称，应跟随本书已经确认的时间线。

不能为了言情效果，把原作人物统一改成另一套精致古风名，也不因关系变化就改写尚未获授权的原名。新增人物有原作文化依据，不直接复制原角色姓名后稍改一个字。

### G21 动漫衍生

明确作品所用译名、原名、音译、意译和角色口头简称之间的关系。漫画、动画及其他版本用词冲突时，采用已确认版本，不在不同章节来回切换。

组织、能力体系、物种与道具沿用对应原作逻辑。跨作品融合时保留来源命名空间，作者未确认前不能把外形相似的角色或术语合并成同一实体。

### G22 豪门总裁

姓名、家族称呼、公司、品牌、集团、职位和私人关系分别命名。商业身份应有实际业务和组织语境，不能单靠名字的尊贵感替代设定。

董事长、总裁、经理、股东、继承人等按本书实际身份使用，不视作可随意互换的称号。“某家、某氏、某集团”也不自动是同一实体；家庭称呼与正式工作称呼应有差别。

### G23 青春甜宠

人名、学校、班级、社团、校园地标和网名贴近作品年代与生活环境。主要人物可以有辨识度，整班同学不必都像经过同一古风姓名生成器。

昵称应来自已发生的互动、习惯或约定，不能一登场就人人拥有成套情侣称谓。少量呼应可作关系设计，不把姓名相似当作恋爱成立的证明。

### G24 星光璀璨

区分本名、艺名、组合名、经纪公司、工作室、节目、影视项目和粉丝称呼。正式宣传名、媒体简称与私人叫法要能对应。

奖项、节目职位与行业身份涉及真实体系时核对；架空奖项与机构保持本书一致性。不能擅自让所有艺名古风化，也不让粉丝名、组合名、项目名都围绕主角使用同一套意象。

### G25 职场婚恋

围绕行业、公司规模、职业分工和生活关系命名。部门、项目、产品和岗位名称应与其职能匹配，允许使用正常的现代管理与技术词汇。

区分同事称呼、客户称呼、上下级称呼和家庭称呼。不要用“殿、盟、王、夫人”等题材化称谓替代没有相应背景的职场职位，也不为显得专业虚构无意义缩写。

### G26 现言脑洞

现代社会名称为底层，按已确认设定加载重生、穿书、异能、特殊关系结构或其他机制规则。人物的本名、前世名、身份名和昵称需要区分。

不能因为有奇幻机制就让所有现实机构一并玄幻化；也不能因为有情感主线，就把每件物品命名成爱情象征。特殊机制的称呼应服务于当前剧情，而不是暴露未揭示的身份。

### G27 古风世情

先确定真实朝代或架空文化，再处理姓名、姓氏关系、宅院、街坊、铺面、家族称谓和礼仪称呼。可以保留市井与家庭的朴素层次。

字、号、排行和各种身份称呼按具体设定使用，不为每个角色强行配齐。称谓应反映叙述者和说话人的关系，不能所有人都以贵族化称号互称。

### G28 宫斗宅斗

按本书制度管理皇室、宫廷、封号、品级、家族、院落与仆役称谓。姓名、封号、位分和任职不是同一种字段，升降与婚姻变化需要记录生效时间。

不得将不同朝代或不同架空制度中的称谓随意混成一张后宫等级表。宫殿名、院名可以有辨识度，但不应直接预告居住者结局或把所有建筑都命名成争宠符号。

### G29 古言脑洞

以故事实际古代背景为基础，叠加已确认的穿越、穿书、重生、特殊能力等机制。土著称呼、外来者内心用语和系统显示名称可以不同。

不得无设定依据地把宫廷改成现代管理体系，或把普通经营组织自动命名成修真宗门。脑洞带来的新机构与新词，应在故事中出现相应形成过程或已有设定依据。

### G30 民国言情

按具体年份、地域、行业和社会身份处理人物、商号、报馆、学校、社团、军政机构与娱乐场所名称。不能仅凭模糊的“旧上海感”套用所有场景。

新旧称谓、外文名与中文名可以共存，但需要人物经历和交往环境支持。军职、职务、家族敬称与社交称呼分开；不把不同地区、不同年份的称谓无差别混用。

### G31 玄幻言情

按作品实际东方或西方幻想文化命名世界实体，情感关系只影响亲昵称呼、约定名和确有关系背景的物品别称，不覆盖整个命名系统。

女主不必统一使用花、雪、月等意象，男主不必统一冠以帝、尊、君等称号。契约、伴侣、师徒或其他身份仅在本书已经建立时启用，不能为配对名字擅自新增绑定关系。

### G32 年代

先明确年代区间、地域、城乡、家庭代际和职业环境，再命名人物、单位、商店、票证及生活用品。涉及真实制度和旧称时核对使用时期。

不同代际可以有不同命名倾向，但不能把所有人物都塞进少量“年代感字库”；普通名、书面名、乳名和后来的改名可以并存。禁止让未来品牌、单位称呼或流行网名无依据提前出现。

### G33 种田

先判断是古代、现代、末世、仙侠还是异世界种田，继承对应世界规则。村落、田庄、店铺、产品、作坊、生产组织与交易场所按实际经营活动命名。

普通生产对象不必全部设置专名；品牌化、规模化或特殊品种出现后再决定是否需要命名。不能把“种田”默认等于古代女频，也不能自动加入空间、灵泉、宅斗或修仙。

### G34 快穿

每个世界建立独立命名空间，记录本体、当前身份、使用姓名、化名、系统称呼及世界编号之间的对应关系。是否存在系统或跨世界机构，以本书设定为准。

不同世界不能批量复用同一套主角姓名、公司名和配角模板；有意保留姓名或跨世界回声时必须记录理由。世界编号主要供需要它的叙述层使用，不能无依据成为土著社会的日常称呼。

### G35 双男主

先按世界背景选择命名规则，再处理两位主角各自的家庭、文化、职业和关系称呼。“双男主”本身不自动指定古风、仙侠、现代或任何制度。

两位主角应各自可辨识，不强制成对意象、同字数或明显互补姓名。不能只根据关系中的强弱位置分配姓名风格、职业称号或社会地位；也不自动推定感情关系已经成立。

### G36 双女主

同样以实际时代与文化为命名底层，两位主要角色分别遵循其身世、职业、性格与家庭背景。关系标签不能替代人物设计。

不强制一人温柔花名、一人冷硬中性名，不通过名字预设谁保护谁、谁依附谁。亲昵称谓、组合名或共同称号须有关系进展或公开约定依据。

### G37 其他

先识别作品实际语境和对象类型，再选相近模块或提出待确认的新增模块；不得把无法识别的题材默认归入玄幻。

真实资料、出版类内容、纪实对象与非虚构名称，优先忠实保留；不能因纳入命名系统就改写事实名称。新题材模块采用独立版本，不反向改变已有作品。

## 七、跨题材标签补充

以下是组合模块，不是一份官方标签全集，也不是必须同时加载的世界设定清单。

### T01 规则怪谈、无限流、副本与生存游戏

场景名可以来自原有地点、参与者叫法或已存在的游戏界面。普通学校、旅馆、小区等不必全部改成直接透露危险规则的名字。

区分场景名称、规则文本、参与者代号与系统编号。不得让副本名、怪物名或道具名泄露尚未揭示的通关方式、真实身份和杀人规则；不自动新增裁决者、审判所或管理机关。

### T02 系统、面板、职业与任务机制

先确认系统在世界内是否被角色感知、是否有显示界面、是否有自称。后台给模型使用的字段名称，不自动成为正文中的系统术语。

面板中的功能名可以准确直白，不必全部诗化；系统正式名称、主角昵称、技能与奖励名称应区分。不得仅凭系统设定再新增管理它的高层机构。

### T03 重生、穿越、穿书与时间循环

管理前世名、现世名、原身姓名、笔名、化名及时间线中的旧称。不能把灵魂身份与社会身份自动合并，也不能让不知情角色使用只有主角知道的名字。

历史分支与循环轮次中的命名变更应记录作用范围。现代人的内心称呼可以与当地名称不同，但不自动进入全知叙述或其他人物台词。

### T04 历史穿梭、诸天与跨作品融合

每个世界、时代和原作版本独立标记来源。相同字面名称不自动视为同一实体，不同译名也不自动视为不同实体。

涉及已经确认的跨世界同一角色时，通过实体关联处理；未经确认的相似人物、神器或组织，不能靠同名直接建立血缘、转世或幕后关系。

### T05 末日求生、天灾、囤物资与废土

区分灾前正式地名、灾后幸存者俗称、营地编号与势力名称。小型临时营地可以用地点或简单代号，不必拥有完整国家化命名。

物资、疾病、灾害等级与设备应可辨识；未知现象可用临时描述，不强行起科学名或超自然名。其真实原因未揭示前，不用名称提前定性。

### T06 克苏鲁、诡异、赛博朋克与其他异质文化标签

仅在作者选定对应创作方向时加载。异质感不等于长音译词、乱码、汉字与字母乱拼，或所有事物都使用污染、深渊等同一组意象。

明确各称呼来自研究者、居民、企业、宗教群体还是未知存在。匿名编号、外语名和民间短称可以并存，但须符合各自文化与知情范围，不把技术风格自动等同于宇宙恐怖。

### T07 神豪、商业、经营、黑科技、医术与专业职业

现实企业、金融产品、技术设备、疾病、药物与专业职称涉及真实事实时核对。虚构项目与真实术语分开标记，不因起名需要就编造一个看似存在的专业概念。

经营产品可以朴素准确；黑科技也可以有正式技术名、型号和市场名，不必统一玄幻化。专业用语的功能明确不构成命名违规。

### T08 反派、女强、萌宝、奶爸、学霸与人物属性

这些属性不自动决定姓名字库。不要用名字直接给人物贴上恶毒、软弱、聪明或尊贵标签，也不强制“人设反差必须体现在姓名上”。

绰号和公众称呼可以体现他人评价，但叙述中应区分外界评价与人物本身。人物成长后不必为了属性升级反复更换本名。

### T09 甜宠、虐恋、先婚后爱、追妻、救赎与关系结构

关系发展可以带来称呼变化，但要与双方意愿、知情范围和具体场合相符。单女主、多女主、无女主、无CP等标签，不自动改变机构、地理和职业的命名规则。

伴侣间称呼不必强制配套，分手、复合或身份变化也不必一律改名。关系尚未建立时，不能因标签存在提前使用具有绑定意义的称谓。

### T10 搞笑、沙雕、反套路与谐音风格

作者明确采用相关风格时，可以使用故意夸张、谐音或反差名称，但要维持可辨识度和适用场景。不能拿搞笑标签为不一致、错名和误用反例免责。

梗名应限制在适合的角色或圈层，不让全世界每件东西都成为段子。真实严肃场景与关键情绪场景需要保留称呼的可信度。

### T11 武侠与江湖补充

武侠未作为本次36项之一单列，但本规则保留适配。以门派、帮会、镖局、山庄、市镇、江湖名号、兵器和武艺为对象，按本书时代与地域处理。

江湖绰号要有传闻、经历或公众评价依据，不给所有人强配四字称号。没有修仙设定时，不自动引入天庭、神阶、法宝和宇宙级功法。

### T12 短故事与篇幅形式

短故事、短篇与出版形式不自动构成独立的世界命名风格，应继续按具体题材处理。

篇幅短时优先减少无必要的新专名、长尊号和多套别称，但不能压缩到关键人物、地点和身份关系无法区分。短篇不是允许错用时代和机构名称的理由。

## 八、旧名称、别名与入口兼容

以下只用于客户端输入的兼容判断，不宣称这些名称已经被番茄官方合并、更名或下线；未经核验，不将它们自动视为同义分类。

| 输入名称或标签 | 规则选择方式 |
|---|---|
| 悬疑恋爱 | 采用实际世界背景＋悬疑规则＋关系称呼规则；不强行等同于女频悬疑。 |
| 奇幻仙侠 | 根据本书实际文化选择东方仙侠、西方奇幻或明确的混合规则；不直接二选一猜测。 |
| 现言甜宠 | 都市或现代社会命名＋关系称呼规则；校园和职场部分按实际场景补充。 |
| 纯爱 | 只据已确认的人物与关系处理；不能自动推定具体世界观、人物性别组合或叙事模式。 |
| 医术 | 作为专业领域叠加；按现代医学、历史医药或幻想医道分别处理，不互相替代。 |
| 综影视、综漫及具体作品衍生标签 | 加载对应原作版本与跨世界规则；保留来源，不把其他作品名称直接拼接成新实体。 |
| 无法识别的新分类或标签 | 使用通用规则与已确认世界设定，标记待建立映射；不冒充已完整适配。 |

## 九、反模板与连续性检查

### 9.1 必须拦截的新候选问题

出现下列问题时，修正或撤回新候选，不写入正式设定：违反作者明确禁用项；把反例当成候选；擅自增加设定以解释名字；与已确认事实矛盾；无依据改变实体身份、隶属关系或等级；泄露当前视角未知的身份；将未经核验的现实名称包装成已证实事实。

“问罪碑、验命石、审判钟”在新候选中属于明确禁用项。规则正文、审阅记录与既有稿件中的出现，不能因此触发盲目删除。

### 9.2 需要人工或上下文判断的问题

同音、形近、简称冲突、名称过长、生僻字多、称谓过于宏大、命名过于整齐、同一意象反复出现，以及“某某司、某某使”的批量生成，都进入语境审阅，而不是仅按字面一律判错。

不能把这些审阅项包装成可靠的“AI作者识别”结论。它们是可读性、风格和一致性检查，不证明文本来源。

### 9.3 检查项目

| 维度 | 核查问题 |
|---|---|
| 题材年代 | 是否符合当前时代、地域、文化与实际制度？ |
| 对象类别 | 读者能否在首次必要介绍后区分它是人物、地方、组织、职位还是物品？ |
| 职能层级 | 是否为“管理某事”自动起成某某司，或为“执行某事”自动起成某某使？职责与层级是否有依据？ |
| 阵营一致 | 同一组织的主体、分支、职位和建筑称谓是否自洽？例外是否已有明确依据？ |
| 读音字形 | 关键人物是否出现容易混淆的同音、形近或缩写？合理的家族共字是否被误判？ |
| 自然称呼 | 名字放进介绍、日常对话和紧张场景中是否都能自然使用？ |
| 模板密度 | 是否人人华丽、处处终极、全部同字数，或批量使用同一抽象词根？ |
| 信息边界 | 是否在名称、别名或称呼中提前泄露隐藏身份、规则和结局？ |
| 示例污染 | 是否把正向示例当作必选项，或把反例及其近义改写作为候选？ |
| 连续性 | 是否与已确认本名、旧称、身份、时间线或原作版本冲突？ |
| 核验范围 | 是否实际查过重名或事实来源？无法核验的内容是否仍保留不确定性？ |
| 修改权限 | 是否涉及已接受内容？是否已获得当前版本、当前范围的明确授权？ |

## 十、命名台账与客户端处理要求

### 10.1 每个正式实体应有稳定标识

实体标识不随改名变化。至少维护：对象类型、正式名称、常用简称、必要别名及类型、所属世界与时间线、所属地域与阵营、有效时期、知情范围、确认状态、规则版本，以及设定依据或首次有效出处。

复杂任务可以增加读音、关系性称呼、原作版本和避讳信息；并非每个路人或一次性普通物品都必须拥有完整档案。

名称相同不自动合并实体，名称不同也不自动拆成两个实体。转世、化名、同一物品的古称等需要作者已确认关系或明确文本证据，不能仅凭相似性推断。

### 10.2 输出模式

用户只要求正文时，直接使用通过检查、符合授权状态的名称，不把命名说明、评分和审阅过程插入正文。

用户要求起名时，按其指定数量提供；未指定时可默认给少量候选，每个候选只说明对象类型、简短依据和必要风险。不得要求用户从一大堆近义字排列中自行完成筛选。

用户要求审阅时，输出问题名称、所在上下文、触发规则、是否属于合理例外、建议处理方式与影响范围。未核验时不得声称“全网无重名”“符合所有历史资料”或“保证没有AI味”。

### 10.3 新名确认与改名流程

新名称先进入候选或草稿状态，在对应内容被作者接受后再进入正式台账。审校通过不等于作者确认，模型自评分高也不等于有权写入正史。

已接受名称需要调整时，先给出旧名、新名、改名原因、涉及实体、影响位置和不应修改的位置；作者确认当前版本与范围后再执行。已有明确且覆盖本次修改的授权，可以直接按授权执行，不重复索取同一确认；越出范围必须重新确认。

获准改名后，同步角色卡、人物关系、世界规则、各层大纲、细纲、当前有效正文、连续性台账及相关索引中的有效引用。同步应依据实体身份和语境，不做全书无差别字符串替换。

历史版本、审阅记录、原作引用、旧身份阶段的称呼、剧情中的假名及明确保留的旧称，不能随新名一并抹除。必要时登记为旧称或历史别名，让系统知道它们属于同一实体。

作者在确认后继续修改了相关稿件时，旧审批不能被用于覆盖新稿。更新失败时应保留可恢复版本、标明未同步范围，不能谎称全部一致。

### 10.4 权限落实

正式稿保护、版本校验、差异审阅、候选与正史分离，应由客户端的读取和写入流程落实，不能仅靠本规则中的文字约束。规则加载或关键上下文缺失时，不得静默跳过硬约束继续写入正式内容。

## 十一、最低验收用例

下列是检查规则是否正确执行的测试情境，不是故事设定。

| 测试情境 | 应有结果 |
|---|---|
| 无官署背景的仙侠宗门，模型批量把分支命名为某某司 | 指出制度套用问题，重新检查组织性质与命名方式；不擅自补建官僚体系。 |
| 已确认的历史官署或职称含司、使 | 按具体时代和制度核对，不因单字命中而判禁用。 |
| 已有阴间体系中出现阴司 | 作为条件例外处理，仍检查本书一致性。 |
| 现代公司出现数据中心或正常部门名 | 不因玄幻反例而拦截；检查是否符合现实或已确认架空语境。 |
| 新候选出现问罪碑、验命石、审判钟 | 拦截该候选；不得只换近义字继续套同一生硬模式。 |
| 用户已接受的旧正文包含上述反例 | 保留原文，提出审阅项；未经授权不改名。 |
| 作者只要求给一件物品起名 | 不因此添加测命、审判、天庭等新体系。 |
| 小说标为双男主或双女主 | 继承实际世界命名规则，不自动生成配套情侣名。 |
| 快穿进入新世界 | 采用该世界的命名空间，保留跨世界身份映射，不默认所有世界同名。 |
| 悬疑场景中只有化名公开 | 正文使用当前视角知道的称呼，不从后台台账泄露真实姓名。 |
| 获准只修改角色当前本名 | 更新授权范围内的有效引用，保留历史版本与剧情需要的旧身份称呼。 |
| 为了反模板而打乱已确认的军用编号或游戏等级 | 不通过；规则不能以去AI味为由破坏合理标准体系。 |

## 十二、最终执行原则

先理解世界，再判断对象；先沿用已确认语境，再创造必要的新名。

能朴素时不强装高深，需要庄重时不故意口语化；能准确说明功能时不强行隐晦，涉及秘密时不提前泄露。

同一文化要自洽，不同文化可以不同；历史感来自作品已经建立的生活、传承与变化，不来自批量古风词、混乱别名或整齐到失真的等级表。

对新候选先纠错，对已接受内容先守住授权边界。名字属于作品世界与人物生活，不是规则示例、分类标签或模型术语的复制品。
